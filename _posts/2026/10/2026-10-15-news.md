### Predictable AI spend in BigQuery: Introducing cost management for generative AI functions

- **Link**: [https://cloud.google.com/blog/products/data-analytics/using-bigquerys-generative-ai-cost-management-features/](https://cloud.google.com/blog/products/data-analytics/using-bigquerys-generative-ai-cost-management-features/)

<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">The </span><a href="https://docs.cloud.google.com/bigquery/docs/generative-ai-overview"><span style="text-decoration: underline; vertical-align: baseline;">generative AI functions in BigQuery</span></a><span style="vertical-align: baseline;"> (</span><code style="vertical-align: baseline;">AI.GENERATE</code><span style="vertical-align: baseline;">, </span><code style="vertical-align: baseline;">AI.IF</code><span style="vertical-align: baseline;">, </span><code style="vertical-align: baseline;">AI.CLASSIFY</code><span style="vertical-align: baseline;">, </span><code style="vertical-align: baseline;">AI.SCORE</code><span style="vertical-align: baseline;">, and more) bring large language models (LLMs) directly into your SQL, so a single query can classify millions of support tickets or score each product review for sentiment. However, because these functions are billed by the token, scaling them across massive datasets highlights the importance of managing your budget proactively. </span></p>
<p><span style="vertical-align: baseline;">We recently announced the general availability (GA) of </span><strong style="vertical-align: baseline;">token-based </strong><a href="https://docs.cloud.google.com/bigquery/docs/control-genai-costs"><strong style="text-decoration: underline; vertical-align: baseline;">cost management</strong></a><strong style="vertical-align: baseline;"> for BigQuery generative AI functions</strong><span style="vertical-align: baseline;">: daily quotas that let administrators set self-serve guardrails on AI token consumption, so teams can innovate while staying within your budget. In this blog, we provide an overview of cost management for BigQuery generative AI functions, walk through a few practical examples, and share resources to help you get started. Let’s jump in.  </span></p>
<h3><span style="vertical-align: baseline;">Quotas for managing costs</span></h3>
<p><span style="vertical-align: baseline;">Four daily quotas, managed through the Google Cloud Identity and Access Management (IAM) quota system, provide controls at the </span><strong style="vertical-align: baseline;">project</strong><span style="vertical-align: baseline;"> level and the </span><strong style="vertical-align: baseline;">per-user</strong><span style="vertical-align: baseline;"> level. Per-user limits apply to each user within a project, not across your organization.<br /><br /></span></p>

<li style="vertical-align: baseline;">

<h3><span style="vertical-align: baseline;">Token quotas vs. billing spend caps</span></h3>
<p><span style="vertical-align: baseline;">Token quotas aren't the only cost guardrail in Google Cloud.</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/bigquery/docs/control-genai-costs"><strong style="text-decoration: underline; vertical-align: baseline;">Token quotas (this feature)</strong></a><span style="vertical-align: baseline;"> are </span><span style="font-style: italic; vertical-align: baseline;">preventive</span><span style="vertical-align: baseline;"> and </span><span style="font-style: italic; vertical-align: baseline;">AI-specific</span><span style="vertical-align: baseline;">. BigQuery tracks token usage during query execution and stops work close to the limit, with separate limits per project and per user.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Cloud Billing </strong><a href="https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps#eligible-services"><strong style="text-decoration: underline; vertical-align: baseline;">spend caps</strong></a><span style="vertical-align: baseline;"> operate on </span><span style="font-style: italic; vertical-align: baseline;">dollars</span><span style="vertical-align: baseline;"> at the project and service level and can automatically block usage when a threshold is reached. They're a broad, financial backstop rather than a precise usage control, and because enforcement is not instant, some overages are incurred.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Use token quotas as your first line of defense for AI spend, and a spend cap as a project-wide safety net.</span></p>
<h3><span style="vertical-align: baseline;">How enforcement works</span></h3>
<p><span style="vertical-align: baseline;">Quotas are enforced by stopping work rather than letting a query run past your limit. A query is rejected up front with a </span><code style="vertical-align: baseline;">QuotaExceeded</code><span style="vertical-align: baseline;"> error only if a quota it needs is already exhausted. Otherwise, it starts, and if a quota runs out mid-query, BigQuery stops sending new LLM calls:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Functions that support </strong><code><strong style="vertical-align: baseline;">max_error_ratio</strong></code><span style="vertical-align: baseline;"> (such as </span><code style="vertical-align: baseline;">AI.IF</code><span style="vertical-align: baseline;">) return partial results if unprocessed rows stay within the ratio, and otherwise fail.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">General-purpose functions</strong><span style="vertical-align: baseline;"> (such as </span><code style="vertical-align: baseline;">AI.GENERATE</code><span style="vertical-align: baseline;">) still succeed. Skipped rows have no generated value, and their </span><code style="vertical-align: baseline;">status</code><span style="vertical-align: baseline;"> field contains the quota-exceeded error.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">For details, see </span><a href="https://docs.cloud.google.com/bigquery/docs/control-genai-costs#quota_enforcement_behavior"><span style="text-decoration: underline; vertical-align: baseline;">quota enforcement behavior</span></a><span style="vertical-align: baseline;"> in the documentation.</span></p>
<h3><span style="vertical-align: baseline;">Sizing your input data: </span><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code></h3>
<p><span style="vertical-align: baseline;">To choose quota values, it helps to know how much text your workloads send to a model. The </span><a href="https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-count-tokens"><code style="text-decoration: underline; vertical-align: baseline;">AI.COUNT_TOKENS</code></a><span style="vertical-align: baseline;"> function helps with this.</span></p>
<p><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code><span style="vertical-align: baseline;"> returns the number of tokens a model's tokenizer produces for a text string, without making a billable generation call. Run it over a column to measure your input data:</span></p></div>
<div class="block-code"><dl>
    <dt>code_block</dt>
    <dd>&lt;ListValue: [StructValue([(&#x27;code&#x27;, &quot;-- Count the input text tokens for each product review\r\nSELECT\r\n  SUM(\r\n    AI.COUNT_TOKENS(\r\n      CONCAT(&#x27;Classify the sentiment of this review as positive, negative, or neutral: &#x27;, review_text),\r\n\r\n      endpoint =&gt; &#x27;gemini-3.1-flash-lite&#x27;).result) AS total_input_tokens\r\nFROM\r\n  `my_project.my_dataset.product_reviews`;&quot;), (&#x27;language&#x27;, &#x27;&#x27;), (&#x27;caption&#x27;, &lt;wagtail.rich_text.RichText object at 0x7f5eb4e965d0&gt;)])]&gt;</dd>
</dl></div>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">The count is a lower bound on input tokens. It doesn't include output or thinking tokens, the instructions each AI function adds around your input, or non-text inputs such as images. Use it to:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Gauge the input side of a workload</strong><span style="vertical-align: baseline;"> before you launch it.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Right-size your quotas</strong><span style="vertical-align: baseline;"> together with a small sample run that measures actual input and output usage.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Translate tokens into dollars</strong><span style="vertical-align: baseline;"> using the published </span><a href="https://cloud.google.com/vertex-ai/generative-ai/pricing"><span style="text-decoration: underline; vertical-align: baseline;">Gemini platform pricing</span></a><span style="vertical-align: baseline;"> for your model.</span></p>
</li>
</ul>
<h3><span style="vertical-align: baseline;">From tokens to budget: a worked example</span></h3>
<p><span style="vertical-align: baseline;">Suppose you want to keep a project's daily AI spend around </span><strong style="vertical-align: baseline;">$100</strong><span style="vertical-align: baseline;"> with the </span><a href="https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-1-flash-lite"><span style="text-decoration: underline; vertical-align: baseline;">Gemini 3.1 Flash-Lite</span></a><span style="vertical-align: baseline;"> model. As of today's published pricing (BigQuery processes in batch which provides a 50% discount):</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Input tokens:</strong><span style="vertical-align: baseline;"> $0.125 per 1 million tokens</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Output tokens (response + reasoning):</strong><span style="vertical-align: baseline;"> $0.75 per 1 million tokens</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">If a small sample run shows an average </span><strong style="vertical-align: baseline;">100:1 input-to-output token ratio</strong><span style="vertical-align: baseline;">, you can solve for a daily budget:</span></p></div>

      <p>Post-quantum cryptography (PQC) is one of the most urgent security shifts of the decade — and one of the easiest to tune out. For security leaders and policymakers, the research is dense, scattered across papers and engineering blogs, and can be challenging to turn into action.</p><p>To help, we're launching <a href="https://notebook.google.com/notebook/68849586-67c5-4165-8f72-64a61991f1dd">Prepare for Post-Quantum Cryptography</a>, a public Gemini Notebook that brings Google's PQC research, engineering blogs, and migration guidance together in one place. Ask it questions, listen to an audio overview, or test yourself with flashcards, and quickly get up to speed on the quantum threat.</p><p><b>Why PQC matters now</b></p><p>Quantum computing is rapidly moving from theory to reality. Our <a href="https://blog.google/technology/research/google-willow-quantum-chip/">Willow chip</a> and <a href="https://blog.google/innovation-and-ai/technology/research/quantum-echoes-willow-verifiable-quantum-advantage/">Quantum Echoes algorithm</a> mark substantial progress, and Google research estimates that breaking <a href="https://arxiv.org/abs/2603.28846">ECDLP-256</a> and <a href="https://arxiv.org/abs/2505.15917">RSA-2048</a> encryption — the public-key cryptography schemes protecting much of our online data — would require around 500,000 and 1 million imperfect quantum computer components (noisy qubits), respectively.</p>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">This research has consequences now. It indicates that today’s online security is more vulnerable to future quantum computers than previously thought.</span></p>
<p><span style="vertical-align: baseline;">In </span><a href="https://www.ietf.org/archive/id/draft-reddy-uta-pqc-app-03.html#name-timeline-for-transition" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Store Now, Decrypt Later</span></a><span style="vertical-align: baseline;"> attacks, adversaries may steal encrypted data now and wait to decrypt it once a sufficiently powerful quantum computer exists. Data that we’ve long considered sensitive — health records, financial data, intellectual property, and government secrets — is already at risk</span><span style="vertical-align: baseline;">.</span><span style="vertical-align: baseline;"> </span></p>
<p><span style="vertical-align: baseline;">With continued advances in architecture, quantum algorithms, and quantum error correction shrinking future quantum hardware requirements, waiting to upgrade our digital locks is not a viable option. To help organizations stay ahead of the curve, Google has published a </span><a href="https://blog.google/innovation-and-ai/technology/safety-security/cryptography-migration-timeline/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">migration timeline</span></a><span style="vertical-align: baseline;"> noting our plans to transition to PQC by 2029, and we urge others to consider the same.</span></p>
<p><span style="vertical-align: baseline;">As the technology advances, policymakers should consider urging critical infrastructure owners and operators to recognize condensed timelines, and build PQC readiness into existing risk mitigation plans. We also recommend governments engage with global counterparts to promote a harmonized approach to standards development, and include technical and security experts in the building of policy and regulatory requirements focused on quantum safety. </span></p>

<p><span style="vertical-align: baseline;">Key details:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">The quotas are global.</strong><span style="vertical-align: baseline;"> Usage is summed across all regions, so costs can't pile up unnoticed in a region you weren't watching.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Output quotas include "thinking" tokens.</strong><span style="vertical-align: baseline;"> Reasoning tokens count toward your output quota, just as they count toward your Gemini platform bill.</span></p>
</li>
</ul>

<h3><span style="vertical-align: baseline;">Token quotas vs. billing spend caps</span></h3>
<p><span style="vertical-align: baseline;">Token quotas aren't the only cost guardrail in Google Cloud.</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/bigquery/docs/control-genai-costs"><strong style="text-decoration: underline; vertical-align: baseline;">Token quotas (this feature)</strong></a><span style="vertical-align: baseline;"> are </span><span style="font-style: italic; vertical-align: baseline;">preventive</span><span style="vertical-align: baseline;"> and </span><span style="font-style: italic; vertical-align: baseline;">AI-specific</span><span style="vertical-align: baseline;">. BigQuery tracks token usage during query execution and stops work close to the limit, with separate limits per project and per user.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Cloud Billing </strong><a href="https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps#eligible-services"><strong style="text-decoration: underline; vertical-align: baseline;">spend caps</strong></a><span style="vertical-align: baseline;"> operate on </span><span style="font-style: italic; vertical-align: baseline;">dollars</span><span style="vertical-align: baseline;"> at the project and service level and can automatically block usage when a threshold is reached. They're a broad, financial backstop rather than a precise usage control, and because enforcement is not instant, some overages are incurred.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Use token quotas as your first line of defense for AI spend, and a spend cap as a project-wide safety net.</span></p>
<h3><span style="vertical-align: baseline;">How enforcement works</span></h3>
<p><span style="vertical-align: baseline;">Quotas are enforced by stopping work rather than letting a query run past your limit. A query is rejected up front with a </span><code style="vertical-align: baseline;">QuotaExceeded</code><span style="vertical-align: baseline;"> error only if a quota it needs is already exhausted. Otherwise, it starts, and if a quota runs out mid-query, BigQuery stops sending new LLM calls:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Functions that support </strong><code><strong style="vertical-align: baseline;">max_error_ratio</strong></code><span style="vertical-align: baseline;"> (such as </span><code style="vertical-align: baseline;">AI.IF</code><span style="vertical-align: baseline;">) return partial results if unprocessed rows stay within the ratio, and otherwise fail.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">General-purpose functions</strong><span style="vertical-align: baseline;"> (such as </span><code style="vertical-align: baseline;">AI.GENERATE</code><span style="vertical-align: baseline;">) still succeed. Skipped rows have no generated value, and their </span><code style="vertical-align: baseline;">status</code><span style="vertical-align: baseline;"> field contains the quota-exceeded error.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">For details, see </span><a href="https://docs.cloud.google.com/bigquery/docs/control-genai-costs#quota_enforcement_behavior"><span style="text-decoration: underline; vertical-align: baseline;">quota enforcement behavior</span></a><span style="vertical-align: baseline;"> in the documentation.</span></p>
<h3><span style="vertical-align: baseline;">Sizing your input data: </span><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code></h3>
<p><span style="vertical-align: baseline;">To choose quota values, it helps to know how much text your workloads send to a model. The </span><a href="https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-count-tokens"><code style="text-decoration: underline; vertical-align: baseline;">AI.COUNT_TOKENS</code></a><span style="vertical-align: baseline;"> function helps with this.</span></p>
<p><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code><span style="vertical-align: baseline;"> returns the number of tokens a model's tokenizer produces for a text string, without making a billable generation call. Run it over a column to measure your input data:</span></p></div>
<div class="block-code"><dl>
    <dt>code_block</dt>
    <dd>&lt;ListValue: [StructValue([(&#x27;code&#x27;, &quot;-- Count the input text tokens for each product review\r\nSELECT\r\n  SUM(\r\n    AI.COUNT_TOKENS(\r\n      CONCAT(&#x27;Classify the sentiment of this review as positive, negative, or neutral: &#x27;, review_text),\r\n\r\n      endpoint =&gt; &#x27;gemini-3.1-flash-lite&#x27;).result) AS total_input_tokens\r\nFROM\r\n  `my_project.my_dataset.product_reviews`;&quot;), (&#x27;language&#x27;, &#x27;&#x27;), (&#x27;caption&#x27;, &lt;wagtail.rich_text.RichText object at 0x7f445b622b10&gt;)])]&gt;</dd>
</dl></div>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">The count is a lower bound on input tokens. It doesn't include output or thinking tokens, the instructions each AI function adds around your input, or non-text inputs such as images. Use it to:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Gauge the input side of a workload</strong><span style="vertical-align: baseline;"> before you launch it.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Right-size your quotas</strong><span style="vertical-align: baseline;"> together with a small sample run that measures actual input and output usage.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Translate tokens into dollars</strong><span style="vertical-align: baseline;"> using the published </span><a href="https://cloud.google.com/vertex-ai/generative-ai/pricing"><span style="text-decoration: underline; vertical-align: baseline;">Gemini platform pricing</span></a><span style="vertical-align: baseline;"> for your model.</span></p>
</li>
</ul>
<h3><span style="vertical-align: baseline;">From tokens to budget: a worked example</span></h3>
<p><span style="vertical-align: baseline;">Suppose you want to keep a project's daily AI spend around </span><strong style="vertical-align: baseline;">$100</strong><span style="vertical-align: baseline;"> with the </span><a href="https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-1-flash-lite"><span style="text-decoration: underline; vertical-align: baseline;">Gemini 3.1 Flash-Lite</span></a><span style="vertical-align: baseline;"> model. As of today's published pricing (BigQuery processes in batch which provides a 50% discount):</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Input tokens:</strong><span style="vertical-align: baseline;"> $0.125 per 1 million tokens</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Output tokens (response + reasoning):</strong><span style="vertical-align: baseline;"> $0.75 per 1 million tokens</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">If a small sample run shows an average </span><strong style="vertical-align: baseline;">100:1 input-to-output token ratio</strong><span style="vertical-align: baseline;">, you can solve for a daily budget:</span></p></div>
<div class="block-code"><dl>
    <dt>code_block</dt>
    <dd>&lt;ListValue: [StructValue([(&#x27;code&#x27;, &#x27;Cost:   0.125 × I + 0.75 × O = 100     (I, O in millions of tokens)\r\nRatio:  I = 100 × O&#x27;), (&#x27;language&#x27;, &#x27;&#x27;), (&#x27;caption&#x27;, &lt;wagtail.rich_text.RichText object at 0x7f445ae5cf10&gt;)])]&gt;</dd>
</dl></div>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">Solving gives about </span><strong style="vertical-align: baseline;">754 million input tokens</strong><span style="vertical-align: baseline;"> and </span><strong style="vertical-align: baseline;">7.54 million output tokens</strong><span style="vertical-align: baseline;"> per day. Set </span><strong style="vertical-align: baseline;">AI input tokens per day</strong><span style="vertical-align: baseline;"> and </span><strong style="vertical-align: baseline;">AI output tokens per day</strong><span style="vertical-align: baseline;"> to these values to hold the project near $100/day. If a project uses models with different prices, budget per model or blend the rates.</span></p>
<h3><span style="vertical-align: baseline;">Best practices for managing AI cost</span></h3>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Start with per-user quotas.</strong><span style="vertical-align: baseline;"> They stop one user or runaway experiment from draining the project's budget.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Measure before you scale.</strong><span style="vertical-align: baseline;"> Use </span><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code><span style="vertical-align: baseline;"> to size your input, then check a small sample run in the usage chart before setting limits.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Mind the output side.</strong><span style="vertical-align: baseline;"> Output tokens cost more. Where a function accepts </span><code style="vertical-align: baseline;">max_output_tokens</code><span style="vertical-align: baseline;">, set it to bound generation length.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Monitor and iterate.</strong><span style="vertical-align: baseline;"> Adjust limits as real usage and budgets change.</span></p>
</li>
</ul>
