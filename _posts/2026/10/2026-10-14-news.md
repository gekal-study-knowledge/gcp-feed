<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">The reality for most organizations is that data lives everywhere. As engineering teams expand and adopt specialized platforms for their workloads, enterprise data naturally disperses across multiple clouds and operational systems. When analytical and AI initiatives require context from across the entire organization,these teams traditionally face a difficult trade-off: build complex extraction pipelines to copy data into a central repository or accept fragmented reporting.</span></p>
<p><span style="vertical-align: baseline;">Traditional architectures address this fragmentation with scheduled extraction pipelines that copy remote datasets into a central staging warehouse. This approach creates synchronization lag, adds recurring storage costs, and triggers variable network egress fees. When schemas change upstream, pipelines break, and teams spend hours reconciling metrics across out-of-sync dashboards.</span></p>
<p><span style="vertical-align: baseline;">BigQuery and Google Cloud’s borderless Lakehouse offer a streamlined way to solve this challenge with a foundation based on the open Apache Iceberg REST catalog specification. Rather than moving data to the compute engine, you can bring Google Cloud compute and generative AI directly to your data, querying it in place across Databricks, Snowflake, and AWS Glue.</span></p>
<p><span style="vertical-align: baseline;">In this post, we walk through how to configure Databricks Unity Catalog for federation into BigQuery (AWS Glue and Snowflake set up in appendix),  run a single query joining data across all three external catalogs, and use conversational analytics in BigQuery to explore the consolidated data with natural language.</span></p></div>

<div class="block-paragraph_advanced"><h3><strong style="vertical-align: baseline;">The borderless lakehouse architecture</strong></h3>
<p><span style="vertical-align: baseline;">This solution uses </span><a href="https://docs.cloud.google.com/lakehouse/docs/about-lakehouse-catalogs"><span style="text-decoration: underline; vertical-align: baseline;">Lakehouse runtime catalog</span></a><span style="vertical-align: baseline;"> to synchronize metadata from other cloud providers, allowing you to query data with BigQuery or external open source engines through the Apache Iceberg REST catalog endpoint, all without migrating the data. Because Databricks Unity Catalog, Snowflake Horizon Catalog, and AWS Glue Data Catalog support the open Apache Iceberg REST catalog specification, you can apply a consistent connection pattern across all three platforms.</span></p>
<p><span style="vertical-align: baseline;">When you run a federated query, Lakehouse runtime catalog separates metadata synchronization from storage access:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Metadata synchronization:</strong><span style="vertical-align: baseline;"> Lakehouse runtime catalog  periodically syncs schemas, snapshot pointers, and table definitions from the remote catalog based on a refresh schedule you define.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Direct storage access:</strong><span style="vertical-align: baseline;"> During query runtime, a compatible engine reads Parquet data files directly from remote object storage, such as Amazon S3, using temporary credentials issued by the remote platform.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">All query processing runs within Google cloud compute such as </span><a href="https://docs.cloud.google.com/bigquery/docs"><span style="text-decoration: underline; vertical-align: baseline;">BigQuery</span></a><span style="vertical-align: baseline;"> or </span><a href="https://docs.cloud.google.com/managed-spark/docs"><span style="text-decoration: underline; vertical-align: baseline;">Managed Service  for Apache Spark</span></a><span style="vertical-align: baseline;">. Remote Databricks clusters, Snowflake virtual warehouses, and AWS compute instances are not invoked during execution.</span></p>
<p><span style="vertical-align: baseline;">Authentication follows an explicit three-step deployment pattern: create the federated catalog in Google Cloud, inspect its configuration to retrieve its automatically generated service account, and grant access permissions within the remote platform.</span></p>
<p><span style="vertical-align: baseline;">You can use AI to generate sample data. The schema details for tables are provided below. </span></p>

<div class="block-paragraph_advanced"><h3><strong style="vertical-align: baseline;">Plan for caching and data residency</strong></h3>
<p><span style="vertical-align: baseline;">Before deploying federated catalogs in production, consider these operational behaviors:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Background refresh timing:</strong><span style="vertical-align: baseline;"> The </span><code style="vertical-align: baseline;">--refresh-interval</code><span style="vertical-align: baseline;"> flag controls metadata synchronization. The minimum interval is 300 seconds. For larger catalogs containing hundreds of tables, metadata retrieval can take longer. If a sync cycle overruns, BigQuery skips the next scheduled run to avoid task queuing.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Automatic query caching:</strong><span style="vertical-align: baseline;"> BigQuery caches retrieved cross-cloud data blocks in the region where your federated catalog resides (e.g. </span><code style="vertical-align: baseline;">us-central1</code><span style="vertical-align: baseline;">). This helps reduce network transfer on repeated queries. Because cached blocks reside within Google Cloud storage in that region, confirm that this aligns with your organization's data residency policies.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Encryption controls:</strong><span style="vertical-align: baseline;"> Cross-cloud cache blocks use Google-managed encryption keys. If your organization enforces the </span><code style="vertical-align: baseline;">constraints/gcp.restrictNonCmekServices</code><span style="vertical-align: baseline;"> policy constraint, BigQuery bypasses the cache and reads directly from remote storage for every query.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Monitoring access metrics:</strong><span style="vertical-align: baseline;"> You can evaluate cache utilization in your query execution plans. Check the </span><code style="vertical-align: baseline;">objectStorageStats</code><span style="vertical-align: baseline;"> section in BigQuery job statistics to compare </span><code style="vertical-align: baseline;">cacheBytesRead</code><span style="vertical-align: baseline;"> against </span><code style="vertical-align: baseline;">objectStorageBytesRead</code><span style="vertical-align: baseline;">.</span></p>
</li>
</ul>

### プレッシャーにさらされているランサムウェア: 変化する脅威ランドスケープにおける戦術、技術、手順

- **Link**: [https://cloud.google.com/blog/ja/topics/threat-intelligence/ransomware-ttps-shifting-threat-landscape/](https://cloud.google.com/blog/ja/topics/threat-intelligence/ransomware-ttps-shifting-threat-landscape/)

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="font-style: italic; vertical-align: baseline;">執筆者: Bavi Sadayappan、Zach Riddle、Ioana Teaca、Kimberly Goody、Genevieve Stark</span></p>
<hr /></div>
<div class="block-paragraph_advanced"><h4><strong style="vertical-align: baseline;">はじめに</strong></h4>
<p><span style="vertical-align: baseline;">2018 年以降、金銭目的の脅威アクターの多くが侵入後にランサムウェアを展開することによって収益化を図る戦略へと移行し始めたことにより、ランサムウェアはほぼすべての業種と地域の組織を対象とした、最もまん延している脅威の一つとなっています。近年、ランサムウェア攻撃は進化しており、堅牢なエコシステムが出来上がり、その活動を支える地下コミュニティのコモディティ化と専門化により、攻撃への参入障壁が下がっています。Ransomware as a Service（RaaS）ビジネスモデルの急増はその典型的な例です。ランサムウェアはその活動の規模と重大な業務の停止に陥るリスクから、依然として主要な脅威ではあるものの、複数の指標からランサムウェア攻撃全体の収益性低下が確認されています。この収益性の低下の傾向は、サイバーセキュリティ対策の強化、組織の復旧能力の向上、ランサムウェアの支払い金額と支払い率の低下など、複数の要因による結果と考えられます。さらに近年では、ランサムウェアのエコシステムは数多くの活動を阻害する要因による影響を受けています。たとえば、法執行機関の介入などの外部からの圧力、アクター間の内部対立などがあり、その両方によって、LockBit、ALPHV、Basta、RansomHub など、これまで活発に活動していた RaaS グループの消滅や大幅に弱体化につながっています。しかし、このような混乱下においても、しっかりした基盤を持つ RaaS ブランドの Qilin と Akira はその空白を埋めるように台頭し、2025 年にデータリークサイト（DLS）に投稿された被組織者数で上位となっています（図 1）。</span></p>
<p><span style="vertical-align: baseline;">このレポートでは、Mandiant Consulting が対応した 2025 年のランサムウェア インシデントから直接確認されたランサムウェアの状況と一般的な戦術、技術、手順（TTP）を紹介します。この分析では、データ窃取による恐喝のみに焦点を当てた攻撃は除外しています。主な分析結果は以下のとおりです。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">3 分の 1 のインシデントの初期アクセス ベクトルとして、脆弱性の悪用が確認または疑われています。ほとんどの場合、一般的な VPN とファイアウォールの脆弱性が標的となっています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">分析したランサムウェア侵入の 77% でデータ窃取の疑いがあり、2024 年のインシデントの 57% から大幅に増加しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年に対応したランサムウェア侵入の約 43% で、脅威アクターが仮想化インフラストラクチャを標的としていることが確認されており、2024 年の 29% から増加しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">REDBIKE が最もよくデプロイされたランサムウェア ファミリーで、分析したランサムウェア インシデントの 30% を占めていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">BEACON や MIMIKATZ などの特定の侵入ツールの使用の減少や、リモート管理ツールの利用の低迷など、過去数年で見られた傾向の一部は引き続き確認されています。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Google Threat Intelligence Group（GTIG）による TTP の分析は、主に Mandiant による対応から入手したデータに依拠しており、グローバルなランサムウェア侵入活動のサンプルに過ぎません。そうしたインシデントはネットワーク侵入活動に続く侵害後のランサムウェア デプロイによるものであり、多くの場合、データ窃取による恐喝も行われています。影響を受けた組織はアジア太平洋地域、ヨーロッパ、北米、ラテンアメリカにわたっており、ほぼすべての業種が含まれています。</span></p>
<p><span style="vertical-align: baseline;">2026 年も引き続きランサムウェアは最も影響の大きいサイバー脅威の一つであると予想されますが、利益の減少により、継続的な標的の変更、データ窃取による恐喝の増加、より攻撃的な恐喝戦術の使用に加え、被害組織の環境へのアクセスを場当たり的に二次的な収益化メカニズムに利用するなど、他の収益化手法と戦術を使用する脅威アクターも出てくる可能性があります。</span></p>
<p><span style="vertical-align: baseline;">ランサムウェアによる脅威への対処に役立つ推奨事項は、ホワイト ペーパーの</span><a href="https://cloud.google.com/blog/topics/threat-intelligence/ransomware-protection-and-containment-strategies"><span style="text-decoration: underline; vertical-align: baseline;">ランサムウェアの防止および封じ込め戦略: エンドポイント保護、セキュリティ強化、封じ込めのための実践ガイダンス</span></a><span style="vertical-align: baseline;">に記載されています。</span></p></div>

<div class="block-paragraph_advanced"><h4><strong style="vertical-align: baseline;">2025 年のランサムウェアの状況</strong></h4>
<p><span style="vertical-align: baseline;">2025 年のランサムウェア環境はますます競争が激化し、1 件以上投稿がある一意の DLS の数が過去最高となりました。恐喝を行うランサムウェア アクターの増加に加え、これらの脅威アクターに的を絞った法執行機関による継続的な取り組み、組織のセキュリティ強化により、近年ランサムウェア オペレーターの利益率は縮小していると考えられます。この状況に対して、脅威アクターは標的から使用するテクノロジーまで、新たな戦略を採用していると思われます。このような進化としては、小規模な組織を標的とする攻撃の増加傾向や、ランサムウェアのデプロイを伴わないデータ窃取による恐喝へのシフトなどがあります。さらに、脅威アクターは攻撃の一部分（交渉など）に AI を組み込み、Web3 テクノロジーを活用してインフラストラクチャの復元力を強化しています。こうした点では活動の拡大が見られる一方で、近年の内部での混乱と外部からの圧力によって、一部の脅威アクターはより慎重になっており、潜在的なパートナーをより厳格に審査するようになっています。ランサムウェア アクターは引き続き戦術を調整して進化させ、一定レベルの成功の確保または過去に達成した収益性の回復に取り組むものと予想されます。</span></p>
<p><span style="vertical-align: baseline;">2025 年は DLS の投稿件数が過去最高を記録し、総投稿数は 2024 年の投稿数を 50% 近く上回りました。投稿件数は過去最高であったものの、DLS データのみでランサムウェア攻撃の全体規模を判断することには注意が必要です。脅威アクターは通常、恐喝の交渉の開始または完了を拒否した被害組織についてのみ、DLS 投稿を作成します。</span><a href="https://www.coveware.com/blog/2026/2/3/mass-data-exfiltration-campaigns-lose-their-edge-in-q4-2025#payments" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">公開レポート</span></a><span style="vertical-align: baseline;">では、身代金の支払い率が低下していることが明らかになっており、これが少なくとも部分的には被害組織を晒すこうしたサイトへの投稿が着実に増加している要因となっている可能性があります。また、データ窃取のみの攻撃に関連する DLS 投稿と、ランサムウェアのデプロイを伴う攻撃に関連する投稿を区別することも困難です。たとえば、CL0P DLS とつながりを持つ脅威アクターは、引き続きランサムウェアをデプロイすることはあるものの、現在では主にデータ窃取による恐喝のみの攻撃に移行しています。CL0P は 2025 年に 3 番目に投稿が多かった DLS でしたが、この投稿に関連するインシデントの大部分にランサムウェアは関与していませんでした。また、BABUK 2.0 とつながりを持つ脅威アクターなどが投稿内容の捏造や誇張を行っているケースに加え、少なくとも被害組織数を若干水増しした内容を再投稿するケースも多数確認されています。最後になりますが、すべての投稿が同じ重要性を持つわけではありません。たとえば、2024 年 12 月から 2025 年 1 月にかけて、FUNKSEC が最も多く DLS 投稿を行いましたが、関連するインシデントの多くは、データ窃取による恐喝を目的としたウェブサイトの侵害という、影響の小さなイベントと思われます。</span></p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">ランサムウェアはこれまで非常に収益性が高かったものの、最近の混乱や組織のセキュリティ強化がこの収益性に影を落としている可能性があります。公開レポートによると、身代金の支払い率と平均の要求額はどちらも減少しています。2026 年 2 月、身代金の支払い率は過去数年間にわたって全体的に低下しており、2025 年第 4 四半期には過去最低を記録したと Coveware が</span><a href="https://www.coveware.com/blog/2026/2/3/mass-data-exfiltration-campaigns-lose-their-edge-in-q4-2025" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">報告</span></a><span style="vertical-align: baseline;">しています。同様に、2025 年 6 月には Sophos が平均の身代金要求額は昨年 3 分の 1 に減少し、2024 年の 200 万ドルから 2025 年には 134 万ドルになっていると</span><a href="https://assets.sophos.com/X24WTUEQ/at/9brgj5n44hqvgsp5f5bqcps/sophos-state-of-ransomware-2025.pdf" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">報告</span></a><span style="vertical-align: baseline;">しています。公開レポートによると、ランサムウェアの影響を受けた組織は簡単に復旧できるようになっており、これも身代金支払い額の減少に影響している可能性があります。たとえば、2025 年 2 月に Unit 42 は企業のランサムウェア インシデントからの復旧能力が高まっていると</span><a href="https://www.paloaltonetworks.com/engage/unit42-2025-global-incident-response-report" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">報告</span></a><span style="vertical-align: baseline;">しています。2024 年にはランサムウェア被害組織のほぼ半数がバックアップから復元できています。この割合は 2023 年は約 28%、2022 年はわずか 11% でした。</span></p>
<p><span style="vertical-align: baseline;">組織のセキュリティの向上と、被害組織のランサムウェア攻撃からの復旧能力の向上によって、一部の攻撃者は支払いを受け取るためのより確実な方法として、データ窃取を捉えるようになっている可能性があります。Mandiant が調査した侵入攻撃では、従来のランサムウェアのデプロイの減少と反比例して、データ窃取による恐喝の増加が確認されました。さらに、一部の RaaS プログラムでは、ランサムウェアに加えてデータ窃取による恐喝のみのオプションも提供しており、顧客ベースからの需要を反映した結果である可能性があります。また、特に大規模な組織でセキュリティ態勢が強化されたことで、脅威アクターが標的を変更せざるを得ず、セキュリティ プログラムの成熟度が低い小規模な組織を標的とした攻撃に重点を置き始めている可能性もあります。DLS に投稿された被害組織の規模（従業員数の推定値に基づく）を分析すると、脅威アクターが大企業から中小企業へと標的をシフトしていることがわかります（図 3）。脅威アクターはこの傾向についてはっきりと言及しています。たとえば、2024 年 4 月と 5 月に流出したチャットで、Basta アクターは「通常のネットワーク」と比較して、小規模な企業のネットワークを標的にする方が効果的であると理論づけていました。</span></p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">2025 年には、さまざまな法執行機関と政府による取り組み、脅威アクター関連のデータ漏洩と対立など、ランサムウェアのエコシステムに悪影響を及ぼす数々の事件が発生しました。このような事象の一部は脅威アクター間での対立の結果によるものと思われます（図 4）。このような事件の多くは逮捕、押収、制裁などによる脅威アクターの直接的な活動停止につながりました。同時に一部の事件では、脅威アクターは TTP の変更を余儀なくされ、セキュリティ研究者にとっては一部のランサムウェア攻撃の内部の仕組みと背後にいる関係者について貴重な知見が得られました。しかし、2025 年に長年活動を続けてきたブランドである Qilin と Akira の規模拡大は、ランサムウェア アクターがレジリエンスを持っており、競合する RaaS 運営者の摘発と出口詐欺後の空白を埋められる能力があることを示しています。全体的に不安定なランサムウェア脅威の環境と法執行機関からの圧力とが相まって、ランサムウェア チームはオペレーションのセキュリティを強化するようになり、その結果、潜在的なアフィリエイトの審査がより厳格になっていることを示す兆候が表れています。また、プライベートまたは準プライベートのサービスが注目を集めるようになっています。たとえば、2025 年はこの 4 年間で初めて、最も活発な RaaS オペレーションの上位 2 つのうちの 1 つが公開されなかった年でした。Akira にはアフィリエイトがいると思われるものの、オペレーションに関して一般向けの広告は出されていません。</span></p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">2025 年、ランサムウェア アクターは新たなテクノロジーまたは確立されたテクノロジーを導入して活動の効率性と有効性を高めることで、引き続きオペレーションを進化させました。一部の脅威アクターはテイクダウンまたは検知の取り組みに対してインフラストラクチャのレジリエンスを高める方法として、Web3 テクノロジーを活動に取り入れています。Cry0 RaaS は Internet Computer Protocol（ICP）ブロックチェーンを利用して、分散型キャニスター スマート コントラクト経由で交渉サイトをホストすることにより、TOR を使わなくてもクリアネットにアクセスできると主張しています。一方、DEADLOCK ランサムウェアは C2 インフラストラクチャの保存とローテーションに Polygon スマート コントラクトを利用しています。また、脅威アクターが AI 機能を RaaS サービスに組み込んでいることも確認されています。GLOBAL RaaS には被害組織の分析を行い、コミュニケーションを支援する AI を活用したチャットが搭載されていると言われています。CHAOS には「組み込みの AI chatbot」が組み込まれているとされていますが、その具体的な使用用途は不明です。BERT は AI ベースのデータ分析を使用して、被害組織の弱みを特定していると言われています。最後に、Windows と Linux の両方のシステムで実行できるランサムウェア ファミリーの数は、2024 年と比較して 2 倍に増加しています。これは脅威アクターが活動をサポートする複数の異なるバリエーションを作成するのではなく、クロスプラットフォームのランサムウェアに移行していることを示している可能性があります。</span></p>
<h4><strong style="vertical-align: baseline;">確認されている一般的な戦術、技術、手順</strong></h4>
<p><span style="vertical-align: baseline;">以降のセクションでは、侵入後のランサムウェアのデプロイ インシデントで確認された TTP の傾向について、GTIG の攻撃ライフサイクル モデル（図 5）の対応するステージごとに説明します。このセクションで概説する TTP は、2025 年中の Mandiant が主導したランサムウェア調査において確認されたものです。</span></p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">初期アクセス</span></p>
<p><span style="vertical-align: baseline;">2025 年のランサムウェア インシデントで最も多く特定された初期アクセス ベクトルは、脆弱性の悪用または悪用の可能性で、インシデントの 3 分の 1 を占めていました。続いて、ウェブ侵害、認証情報の盗難、ブルート フォース攻撃となっています（図 6）。ビッシングは注目を集めた大規模な複数のデータ窃取による恐喝キャンペーンでよく利用された戦術でしたが、ランサムウェア インシデントでは確認されませんでした。一部のベクトルは検証が困難であることを踏まえ、今年は全体像を示すために初期アクセス ベクトルとして疑われるものについても分析に含めています。たとえば、認証情報の盗難を確認するのは困難で、認証情報が数週間前に発生した別のインシデントで収集された可能性や個人のデバイスから収集された可能性もあります。一方、ブルート フォース攻撃では、ベクトルの特定に使用できるログエントリが多数生成される傾向があります。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年全体を通じて、ランサムウェア オペレーターは初期アクセスに幅広いシステムの脆弱性を利用していることが確認されました（表 1）。確認または疑われた脆弱性の悪用の大部分は、2025 年より前に公開された脆弱性に関わるものでしたが、少なくとも一部のランサムウェア アクターのオペレーションでは、</span><a href="https://cloud.google.com/blog/topics/threat-intelligence/2025-zero-day-review"><span style="text-decoration: underline; vertical-align: baseline;">ゼロデイ攻撃</span></a><span style="vertical-align: baseline;">の利用を示す複数の兆候が確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脆弱性を悪用したまたは悪用した疑いがあるほとんどのケースで、脅威アクターは Fortinet（CVE-2024-55591、CVE-2024-21762、CVE-2019-6693）、SonicWall（CVE-2024-40766）、Palo Alto（CVE-2024-3400）、Citrix（CVE-2023-4966）などの一般的な VPN とファイアウォールの脆弱性を標的としていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">悪意のあるアクターが Veritas Backup Exec、Zoho ManageEngine、Microsoft SharePoint、SAP Netweaver などの公開されているさまざまなサービスの脆弱性の悪用にも成功していることが確認されています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">年間を通して、複数のランサムウェアとデータ窃取による恐喝のオペレーションが、初期アクセスとしてゼロデイ脆弱性を利用した証拠が確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年 7 月中旬、UNC6357 アクターは Microsoft SharePoint の脆弱性（CVE-2025-53770 と CVE-2025-53771）を悪用して被害組織の環境にアクセスし、LOCKBIT.WARLOCK をデプロイしようとしました。この攻撃は脆弱性の開示後に確認されましたが、ログデータや公開された</span><a href="https://www.microsoft.com/en-us/security/blog/2025/07/22/disrupting-active-exploitation-of-on-premises-sharepoint-vulnerabilities/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">レポート</span></a><span style="vertical-align: baseline;">などの証拠から、同じアクターがこの脆弱性をゼロデイとして悪用しようとしていた可能性があります。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年 8 月、GTIG は高い確率で UNC2165 が CVE-2025-8088 のゼロデイ攻撃で MYTHICAGENT をデプロイしたと判断しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">確認されたインシデントではランサムウェアのデプロイは行われていませんが、CL0P DLS とつながりを持つ脅威アクターが、Oracle EBS 環境に対するゼロデイ攻撃として CVE-2025-61882 を</span><a href="https://cloud.google.com/blog/topics/threat-intelligence/oracle-ebusiness-suite-zero-day-exploitation"><span style="text-decoration: underline; vertical-align: baseline;">悪用</span></a><span style="vertical-align: baseline;">した可能性があります。CL0P DLS は CLOP ランサムウェアを利用した多面的な恐喝行為に関与しているとされていますが、基本的にはデータ窃取による恐喝であり、ランサムウェアのデプロイではありません。</span></p>
</li>
</ul>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威クラスタがマルバタイジングと検索エンジン最適化（SEO）の手法を利用して、初期アクセスを目的としたマルウェア ペイロードを配布していることが確認されました。これはランサムウェア オペレーター自身と、その後のランサムウェアの侵入につながる初期アクセス パートナーの両方が行っています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC6016 によるマルウェアの配布では、マルバタイジングを利用して PuTTY などの正規のソフトウェア ツールを装ったマルウェア ペイロードを配布し、初期アクセスを確保しています。確認された UNC6016 によるアクセスの少なくとも一部は、最終的に NITROGEN または RHYSIDA ランサムウェアのデプロイに至っています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC2465 はマルバタイジングと SEO 手法を日常的に利用して、RVTOOLs インストーラを装った SMOKEDHAM ペイロードを配布していました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">今年は頻度が減ったものの、多くの脅威アクターが引き続き盗んだ認証情報を初期アクセスに利用していました。初期アクセス ベクトルが特定された侵入の 21% で、脅威アクターは正当な認証情報を悪用して被害組織の環境にアクセスしていました。通常、被害組織の VPN の認証またはリモート デスクトップ プロトコル（RDP）ログインを通じてアクセスされています。常に盗まれた認証情報のソースを特定できるわけではありませんが、アクターはアンダーグラウンド フォーラムでの認証情報の購入やインフォスティーラー ログで公開されている認証情報の使用など、さまざまな手法で認証情報を入手できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部のアクターは被害組織の VPN に対してブルート フォース攻撃を実施していることが引き続き確認されています。Daixin と名乗るランサムウェアが関与したインシデントでは、脅威アクターは約 1 年間にわたってさまざまな VPN ユーザー アカウントに対して定期的にブルート フォース攻撃を仕掛け、最終的に初期アクセスに成功しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の侵入で、ランサムウェア オペレーターが仲介ネットワーク経由で被害組織にアクセスしていることが確認されました。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の異なるランサムウェア活動において、被害組織の子会社のネットワークにアクセスしたうえで、被害組織のネットワークにアクセスしていることが確認されました。ある事例では、脅威アクターは子会社へのアクセスを利用して、ブルート フォース攻撃で被害組織の VPN にアクセスしています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">別のインシデントでは、脅威アクターがサードパーティ ベンダーが所有する VPN 接続を利用して、被害組織の環境内のオペレーション テクノロジー（OT）システムにアクセスしました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">CLOP ランサムウェアのデプロイにつながった侵入では、UNC5833 はヘルプデスク ユーザーになりすました初期アクセス パートナーからアクセスを確保しています。このパートナーは Microsoft Teams のチャット セッションで従業員をソーシャル エンジニアリングして Quick Assist をインストールさせました。2025 年に確認されたインシデントでは、ランサムウェア オペレーターによるソーシャル エンジニアリングの使用は限定的でしたが、金銭目的の侵入を行うアクターの間では引き続き一般的な手法となっています。</span></p>
</li>
</ul></div>

<p><span style="vertical-align: baseline;">足場の確立とプレゼンスの維持</span></p>
<p><span style="vertical-align: baseline;">被害組織の環境に侵入した脅威アクターはさまざまな手法を使用して、足場を確立し、プレゼンスを維持しています。そのような手法には、有効な認証情報、トンネラー、バックドア、正規のリモート アクセス ツールの利用などがあります。脅威アクターは攻撃ライフサイクルのこの両方のフェーズをサポートするツールとして、引き続きリモート管理ツールを使用していますが、その使用割合は 2024 年よりもわずかに低くなっています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ランサムウェア アクターは被害組織の環境に足場を築くために、引き続き漏洩した認証情報を利用しています。</span></p>

<p><span style="font-style: italic; vertical-align: baseline;">表 2: 足場の確立とプレゼンスの維持に使用された正規のリモート アクセス ツール</span></p>
<p><span style="vertical-align: baseline;">権限の昇格</span></p>
<p><span style="vertical-align: baseline;">ランサムウェア アクターにとって、高度な権限を持つアカウントのアクセス確保は重要なステップです。これにより、AV ソフトウェアの無効化、バックアップの削除、ネットワーク全体へのランサムウェアのデプロイなど、攻撃の次の段階に進めるようになります。脅威アクターは引き続き、さまざまな権限昇格ツールと手法を利用しています。MIMIKATZ の利用、Windows オペレーティング システムに保存された認証情報のダンプ、Active Directory（AD）の悪用などがあります。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年のランサムウェア侵入のうち、脅威アクターが MIMIKATZ を利用したケースは約 18% に上ります。最近の利用はわずかながらも減少傾向にあり、2024 年にはランサムウェア侵入全体の 20% で利用されていました。注目すべき点は公開されている他の権限昇格ツールと認証情報窃取ツールも減少していることです。たとえば、2025 年のランサムウェア侵入では LAZAGNE は確認されませんでしたが、2024 年は 2%、2023 年は 4%、2022 年は 6% を占めていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">過去の数年と同様に、2025 年も脅威アクターはさまざまな手法を使用して Windows 認証システムを標的とし、特権アカウントへのアクセスを試みています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは Windows システムに保存されている認証情報を取得するため、Local Security Authority Subsystem Service（LSASS）のプロセスメモリのダンプ、Active Directory ドメイン データベース（NTDS.dit）ファイルのコピー、Security Account Manager（SAM）、SYSTEM、SECURITY のレジストリ ハイブのエクスポートを頻繁に試みていることが確認されています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">確認されたその他の手法としては、Kerberoasting 攻撃、WDigest 認証情報のキャッシュを有効にするレジストリの変更、Windows Data Protection API（DPAPI）経由での認証情報の復元などがあります。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは不正使用のアカウントとアクターがプロビジョニングしたアカウントを、ローカル管理者グループとドメイン管理者グループに追加するか、SeRemoteInteractiveLogonRight、SeDebugPrivilege、SeLoadDriverPrivilege、SeBackupPrivilege などの追加の権限をアカウントに付与することで、日常的に権限を昇格させていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部の侵入では、脅威アクターは AD ロールを悪用して、DCSync レプリケーションや AD 証明書サービス（AD CS）の不正使用など、さまざまな手段で権限を昇格させていました。MEDUSALOCKER.V2 インシデントでは、脅威アクターは「Move-ADDirectoryServerOperationMasterRole」コマンドレットを実行して、Flexible Single Master Operation（FSMO）のロールを被害組織の AD ドメイン コントローラから不正なものと疑われるドメイン コントローラに転送しています。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威アクターがバックアップ ツール、ブラウザ、パスワード マネージャー、平文で保存されている認証情報など、さまざまな内部ソースから認証情報を収集しようとしていることが確認されました。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">確認された侵入の約 10% で、脅威アクターは認証情報の収集のために Veeam Backup &amp; Replication を標的としています。これは 2024 年にも確認されています。複数の脅威アクターが公開されている Veeam-Get-Creds.ps1 スクリプトまたはカスタムの PowerShell スクリプトを使用して、Veeam の構成データベースに保存されている認証情報を取得しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">いくつかのインシデントでは、脅威アクターは保存された認証情報の取得のため、Chromium ベースのブラウザを標的としています。たとえば、UNC2165 RANSOMHUB インシデントでは、脅威アクターはインライン PowerShell を実行して、Google Chrome と Microsoft Edge のローカルの状態ファイルから DPAPI で保護されたマスター暗号鍵を取得して復号し、ブラウザ内に保存された認証情報にアクセスできるようにしました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは KeePass、Bitwarden、Windows 資格情報マネージャーなどの一般的なパスワード管理ツールにアクセスするか、アクセスを試みていました。AGENDA ランサムウェアが関与した UNC2465 による侵入では、脅威アクターは自己ホスト型の Bitwarden サーバーにアクセスし、Vault データベースの中身をエクスポートして密かに引き出していました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">REDBIKE ランサムウェア インシデントでは、脅威アクターは SonicWall アプライアンスから平文のパスワードを収集した可能性が高く、そのパスワードは管理者アカウントとも共有されていたため、アクターはドメイン管理者権限を獲得できました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">被害組織の仮想化された環境を標的としたあるランサムウェア インシデントでは、脅威アクターは CVE-2024-37085 を悪用して ESXi ハイパーバイザへの管理者アクセス権を取得しました。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">内部偵察</span></p>
<p><span style="vertical-align: baseline;">2025 年に内部偵察に利用された戦術は、ここ数年の戦術とほぼ同じです。脅威アクターは引き続き、ネイティブ システム ユーティリティ、PowerShell コマンド、一般公開されているソフトウェアを利用しています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは引き続き PowerShell を使用して、実行中のプロセス、ネットワーク共有、ユーザー グループのメンバーに関する情報を入手するために Active Directory（AD）オブジェクトをクエリしています。この活動は Get-ADComputer や Get-ADUser などのネイティブのコマンドレットの使用から、スクリプト ブロックを使用した他のシステムデータのクエリまで多岐にわたります。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数のケースで、脅威アクターは Get-ADComputer と Get-ADUser を使用して、AD オブジェクトのリストを別のファイルにエクスポートしています。たとえば、MEDUSALOCKER.V2 が関与しているインシデントでは、脅威アクターは特定のユーザー オブジェクト プロパティをクエリして、アカウント ID、連絡先情報、組織のメタデータをエクスポートしました（図 8）。同じインシデントで、脅威アクターは別のコマンドを実行してドメインに参加しているパソコンをクエリし、オペレーティング システム（OS）、IPv4 アドレス、最終ログイン日などのプロパティを入手しました（図 9）。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部のケースでは、脅威アクターは一度に多数のコマンドを実行する PowerShell スクリプト ブロックを実行していました。たとえば、INTERLOCK インシデントでは、脅威アクターは現在のユーザーのユーザー名、セキュリティ識別子（SID）、グループ メンバーの特定などのユーザー プロファイリングの実行、ドメイン接続の確認、ドメイン管理者グループの列挙という処理を 1 行にまとめたスクリプトを実行しています。注目すべき点として、このスクリプトにはジッターまたは処理遅延が含まれており、コマンド実行中にランダムな一時停止が作成されていました。これはコマンドの短時間での実行に対する検知を回避する試みと考えられます。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは攻撃ライフサイクルのこのフェーズでも引き続き、ipconfig、netstat、ping、nltest などの Windows の内部ユーティリティに大きく依存していました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">多くの侵入で一般公開されている偵察ユーティリティが使用されています。このような公開ツールは、Advanced IP Scanner、Softperfect Network Scanner（NETSCAN）、Angry IP Scanner などのネットワークのプロービングに特化したものから、PowerSploit や IMPACKET などのレッドチーム ツールまで多岐にわたります。特に、Advanced IP Scanner、NETSCAN、Angry IP Scanner などのネットワーク偵察ユーティリティは、侵入の約 50% で使用されており、2023 年と 2024 年に確認された使用状況と類似しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターが機密情報に関連する可能性のあるファイルとフォルダにアクセスしているケースが多々確認されています。バックアップ スクリプトとパスワード マネージャーを検索していると思われるケースもあれば、データ窃取による恐喝を有利に進めるために、引き出す機密ファイルを探していると思われるケースもあります。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">REDBIKE の侵入では脅威アクターは「パスポート」、「i9」、「サイバー保険」などのキーワードを検索していました。パスポートや就労資格証明書などの個人を特定できる情報（PII）を検索するだけでなく、脅威アクターは被害組織のサイバー保険ポリシーも入手することで、交渉戦略や要求する身代金額の上限の決定に役立てようとしていた可能性があります。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威アクターが被害組織の環境内の仮想化インフラストラクチャに関する情報を得るために、標的を絞った内部偵察を実施しています。このようなシステムへのランサムウェアのデプロイをスムーズに進めるための情報収集と考えられます。REDBIKE インシデントでは、脅威アクターは Get-VM コマンドレットを実行してハイパーバイザを列挙し、VMware vSphere の内部ウェブポータルにアクセスしました。</span></p>
</li>
</ul></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">ラテラル ムーブメント</span></p>
<p><span style="vertical-align: baseline;">2025 年全体を通して、アクターは RDP、サーバー メッセージ ブロック（SMB）、Secure Shell（SSH）などの一般的な組み込みプロトコルを、不正取得した認証情報または攻撃者が作成したアカウントとともに広範囲に使用して、ラテラル ムーブメントを実行しました。また、さまざまなツールやユーティリティを利用して、被害組織の環境内でトラフィックをトンネリングしてプロキシしているアクターも確認されています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">侵入の約 85% で、脅威アクターは不正利用のアカウントまたは攻撃者が作成したアカウントで RDP を利用して、ラテラル ムーブメントを行いました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">さまざまなインシデントで、脅威アクターは SMB を利用してラテラル ムーブメントを実行し、ネットワーク共有へのアクセス、ペイロードのステージング、リモート コマンドの実行を行っていることが確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">SAFEPAY ランサムウェアのインシデントでは、脅威アクターは SMB を利用してさまざまなネットワーク共有にアクセスし、そのアクセスを利用して複数のホストに NETSCAN のコピーをステージングしました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">また、複数のアクターが IMPACKET.SMBEXEC を利用してリモート コマンドを実行していることも確認されています。たとえば、MEDUSALOCKER.V2 ランサムウェアのデプロイにつながったある侵入では、脅威アクターは IMPACKET.SMBEXEC を利用して、リモートホスト上に新しいローカル管理者アカウントを作成するコマンドを実行しました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">数多くのインシデントで、さまざまな脅威アクターが特に ESXi システムに横移動するときに、PuTTY や KiTTY などの一般的な公開ユーティリティを利用してホストへの SSH 接続を確立していることが確認されました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">リモート実行とラテラル ムーブメントには一般的な Windows ユーティリティが引き続き頻繁に使用されており、PsExec、Windows リモート管理（WinRM）に加え、頻度は低いものの Windows Management Instrumentation コマンドライン（WMIC）も使用されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">いくつかの侵入では、脅威アクターは PowerShell を使用して、「Enter-PSSession」コマンドレットで WinRM 経由でのインタラクティブなリモート セッションを確立しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC5774 の INTERLOCK ランサムウェア インシデントでは、脅威アクターは WinRM を使用してドメイン コントローラへの接続を確立し、net.exe を使用したユーザー アカウントのパスワードのリセットなどのリモート コマンドを実行しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC2465 のインシデントでは、脅威アクターは WMIC を使用してリモートホスト上で SMOKEDHAM ペイロードを実行し、ラテラル ムーブメントを展開しています。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">多数のインシデントで、脅威アクターはファイアウォール ルールを操作して、RDP や SMB などのさまざまな種類のトラフィックが被害組織の環境内で許可されるようにしていました。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">あるインシデントでは、FIN6 脅威クラスタと疑われる UNC6021 がファイアウォール ルールを変更してリモート デスクトップ アクセスを有効にする netsh コマンドを実行するタスクを作成し、スケジュール設定しています（図 10）。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC6276 の侵入では、脅威アクターはホストに SYSTEMBC.LINUX をデプロイする前に、ESXi ホストのファイアウォールを無効にしています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">あるインシデントでは、脅威アクターはホストに OpenSSH をインストールし、PowerShell コマンドを実行して、ポート 22 でのインバウンド トラフィックを許可する新たなファイアウォール ルールを構成しました（図 11）。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">INC ランサムウェアのデプロイにつながった侵入では、脅威アクターは攻撃者が作成したアカウントを利用して、ネットワーク内の複数の追加のサブネットへのアクセスを許可する新しいファイアウォール ポリシーを作成しました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは SYSTEMBC、VIPERTUNEL、PYSOXY、CLOUDFLARED、OpenSSH など、さまざまな悪意のあるユーティリティと正規のユーティリティを利用して、被害組織のネットワーク内でトラフィックをトンネリングしてプロキシしています。ある LOCKBIT.WARLOCK の侵入では、脅威アクターは CLOUDFLARED を利用して 2 台のホスト間の RDP 接続をトンネリングしました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">件数は多くありませんが、脅威アクターが METASPLOIT や AMNESIAC などの一般公開されている侵入後活動ツールを利用しているインシデントも確認されています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは頻繁に仮想システムのさまざまな管理コンソールへのアクセスを悪用して、仮想ホストにラテラル ムーブメントを展開しています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の事例で、脅威アクターはこのアクセスを利用して、SSH 接続を確立してラテラル ムーブメントを行う前に ESXi ホストで SSH を有効にしていると思われます。たとえば、FOULFOG.LINUX インシデントでは、脅威アクターは被害組織の VMware vSphere の一元管理ポータルからのアクセスを利用して、vm-host で SSH を有効にしました。そのうえで、user root1 を作成し、新しく作成したユーザーを使用して SSH 接続し、ファイアウォールを無効にしました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">あるインシデントでは、脅威アクターは被害組織の Nutanix Prism Central 管理ツールへのアクセスと不正使用のアカウントを利用して、複数の追加システムにラテラル ムーブメントを行いました。同じインシデントで、脅威アクターは VMware ウェブユーザー インターフェースも使用して多数の ESXi ホストにアクセスしました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部の侵入で、脅威アクターがブルート フォース攻撃を実施して、追加のシステムのアカウントにアクセスしようとした証拠が確認されています。</span></p>
</li>
</ul></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">目的達成</span></p>
<p><span style="vertical-align: baseline;">以下のセクションでは、攻撃ライフサイクルの目的達成フェーズで確認されたことについて説明します。具体的にはランサムウェアのデプロイ、データ引き出し、分析回避と復旧回避の手法について取り上げます。ランサムウェア攻撃を行う脅威アクターは、交渉時に優位に立てるよう、データ窃取を伴う多面的な恐喝活動を日常的に行っています。また、脅威アクターはセキュリティ ソフトウェアの改ざん、バックアップの削除、ログの消去など、常にさまざまな戦術を使用して、オペレーションが成功し、被害組織の復旧能力が低下するようにしています。2025 年の注目すべき傾向としては、REDBIKE ランサムウェアのまん延、データ窃取による恐喝を伴うインシデントの割合の増加、仮想システムを標的とするために使用される手法の成熟化の兆候が挙げられます。</span></p>
<p><span style="vertical-align: baseline;">ランサムウェア ファミリー</span></p>
<p><span style="vertical-align: baseline;">REDBIKE は 2025 年の Mandiant のインシデント対応調査で最も確認されたランサムウェアであり、AGENDA、INC ランサムウェアがそれに続きます（図 12）。2024 年には、REDBIKE は LOCKBIT.BLACK および RANSOMHUB と並んで 1 位でしたが、LOCKBIT が 2024 年に法的措置による大きな混乱を経験し、2025 年には RansomHub が突然活動を停止しました。2025 年全体を通じて、NINTHBEE や SILVERPINE などの新たに特定されたランサムウェアが関与するインシデントも少数ながら確認されました。これは少なくとも一部の脅威アクターが新しいランサムウェア ファミリーを開発し、維持していることを示しています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">REDBIKE は 2025 年のランサムウェア インシデントのほぼ 30% で確認され、2023 年に単一のランサムウェア ファミリーとして過去最高を記録した LOCKBIT や ALPHV の 17% を上回りました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは異なる恐喝ブランドの下で実施される、一見無関係なオペレーションにおいて既存のランサムウェア ファミリーを再利用していることが引き続き確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2024 年に RaaS に対して法的措置が取られて以降、LOCKBIT ランサムウェア インシデントは大幅に減少しましたが、2025 年には少数の LOCKBIT.WARLOCK インシデントが確認されました。WarLock DLS は 2025 年 7 月に登場し、それ以降の被害件数は 75 件以上に上ります。LOCKBIT.WARLOCK は元の LOCKBIT コードベースを大幅に活用していますが、異なる暗号化アルゴリズムを使用して、以前はインライン化されていたオペレーションを専用の関数にリファクタリングしています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年には、CONTI ランサムウェアが関与する侵入がいくつか確認されました。CONTI RaaS は活動に関するチャットログと CONTI のソースコードが漏洩した後、2022 年 5 月にシャットダウンされていました。たとえば、Gunra ランサムウェア グループに関連した 2025 年のインシデントでは、CONTI がデプロイされていることが確認されました。ランサムウェア ペイロードの分析により、難読化にわずかな違いが見られるものの CONTI のソースコードを元にしていることが判明しました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">INC ランサムウェアをオペレーションに利用している 3 つの異なる恐喝ブランドとして、INC Ransom、Sinobi、Lynx が確認されました。INC ランサムウェアのソースコードは 2024 年 5 月にアンダーグラウンド フォーラムで宣伝されていますが、Lynx と INC Ransom の DLS ドメインは同じ脅威アクターによって取得されています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年のインシデントで ODDSIDE ランサムウェアが確認されました。ODDSIDE は PowerShell ベースのランサムウェアで、DARKMATTER と名乗っています。PowerShell ベースのランサムウェアはまったく前例がないわけではありませんが、かなり珍しいものです。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">あるインシデントでは、脅威アクターが CLOP ランサムウェアをデプロイしていることが確認されました。マルウェア リポジトリにアップロードされた CLOP ランサムウェアのサンプルを特定したことは何度かあるものの、CLOP ランサムウェアのインシデントに対応するのは、このインシデントが 2020 年以降初となります。近年、CL0P データリークサイトとつながりを持つ脅威アクターは、暗号化の実行ではなく主にデータ窃取による恐喝のみのオペレーションを行っていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部のインシデントでは、ランサムウェアのペイロードを入手できませんでした。たとえば、TridentLocker ブランドのランサムウェア インシデントが少数確認されていますが、これらのインシデントではランサムウェア ペイロードがメモリ内で実行されたことを示唆する証拠があります。脅威アクターはセキュリティ検知を回避し、簡単に解析と復旧ができないようにするため、インメモリ実行を使用してランサムウェアをデプロイした可能性があります。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは恐喝活動で正規の暗号化ツールを悪用することがあります。2025 年には、脅威アクターが BitLocker を使用して 200 台以上のリモートホストを暗号化するインシデントが確認されました。</span></p>
</li>
</ul></div>

<p><span style="font-style: italic; vertical-align: baseline;">表 3: Mandiant の 2025 年インシデント対応調査で確認されたランサムウェア ファミリー</span></p>
<p><span style="vertical-align: baseline;">データの引き出し</span></p>
<p><span style="vertical-align: baseline;">2025 年には、ランサムウェアの侵入の約 77% でデータ窃取が確認されたかその疑いがあり、2024 年の約 57% から大幅に増加しました。このようなインシデントで、データの特定、ステージング、引き出しの戦略として最も頻繁に確認されたのは、Rclone や MEGASync などの正規のデータ同期ツールの使用、組み込みツールやポータブル版の WinRar や 7Zip を使用したファイル圧縮、Filezilla や Winscp などの FTP クライアントの使用でした。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">データが盗まれた侵入では、脅威アクターが法務、人事、会計、事業開発データなど、さまざまな種類の機密データを標的にしていることが日常的に確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターが機密データの引き出しと収集の標的としている可能性のあるシステムを手動で偵察している証拠が確認されました。たとえば、メールへのアクセス、ブラウザ経由での SharePoint やその他の Microsoft 365 環境へのアクセスが確認されています。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年、脅威アクターはデータの引き出しに引き続き一般公開されているツールやユーティリティに利用しています。Rclone、MEGASync、Megatools、restic に加え、Cyberduck も使用している可能性があります。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">データ窃取が確認されたかその疑いがある侵入の約 28% で、Rclone を使用して、攻撃者が制御するインフラストラクチャにデータが引き出されています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">INC ランサムウェアのインシデントでは、脅威アクターは wget コマンドと curl コマンドを使用して、Rclone と INC.LINUX ランサムウェア ペイロードをそれぞれネットワーク接続ストレージ（NAS）サーバーにダウンロードしました。その後、脅威アクターは Rclone を実行してサーバーからデータを引き出したうえで、INC.LINUX ペイロードを手動で実行しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">データ窃取が確認されたかその疑いがある侵入の 26% で、脅威アクターは正規の FTP / SFTP クライアントをインストールまたは利用しました。一般的に利用されているソフトウェアには、FileZilla、WinSCP、PuTTY セキュアコピーなどがあります。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">データ引き出しに使用されたことは確認されていませんが、脅威アクターが Total Commander、Xcopy、Gpg4win などのさまざまなユーティリティをインストールまたは実行していることが確認されました。これは偵察、ステージング、盗んだデータのエクスポートのために使用された可能性があります。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは Azure、AWS、Backblaze、Cloudzy、Filemail、Google ドライブ、MEGA、OneDrive などの数々の正規クラウド サービスとインフラストラクチャを利用して、盗んだデータを引き出しています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">AGENDA ランサムウェアのデプロイにつながった UNC5471 の侵入では、脅威アクターはバッチ スクリプトと WinRAR を利用して、ディレクトリ内のファイルのアーカイブを自動化しました。そのうえで Megatools と SLEETSEND を使用して、MEGA と Cloudzy のクラウド ストレージ サービスにデータを引き出しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威アクターが盗んだデータを攻撃者が制御する OneDrive アカウントに転送していることが確認されました。UNC5496 の侵入の一つでは、脅威アクターはコマンドを実行して、Rclone で一般的なファイル拡張子タイプのリストに一致するすべてのファイルを、脅威アクターが制御する OneDrive アカウントに転送しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数のインシデントで、脅威アクターが AzCopy を利用して、盗んだファイルを攻撃者が制御する Azure ストレージに転送していることが確認されました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC6098 の侵入の一つでは、脅威アクターは SQL Server インポートおよびエクスポート ウィザードを利用して SQL データベースをエクスポートしました。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">ランサムウェアのデプロイ</span></p>
<p><span style="vertical-align: baseline;">2025 年を通して、侵入で利用されたランサムウェアのデプロイ手法は多岐にわたっています。脅威アクターはバッチ スクリプト、スケジュール設定されたタスク、グループ ポリシー オブジェクト（GPO）、レジストリキー、PowerShell スクリプトの使用など、手動と自動の両方のデプロイ手法を採用していました。注目すべき点として、インシデントの約 20% で脅威アクターは仮想化インフラストラクチャを標的としており、オペレーターが ESXi ホストに対するランサムウェアのデプロイの一部を自動化していることが複数のインシデントで確認されています。これは仮想システムを標的とする手法が成熟しつつあることを示唆しています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは通常自動化されたメカニズムを利用して、ランサムウェアをデプロイしていました。多くのケースで、ネイティブの Windows メカニズムを利用して、ランサムウェアの実行がスムーズに進むようにしています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威クラスタがバッチ スクリプトを利用して、被害組織の環境でランサムウェア ペイロードを容易に実行できるようにしています。LOCKBIT.WARLOCK の侵入では、脅威アクターはランサムウェア ペイロードを実行するファイルとともに、ドメイン コントローラに NetExec をステージングしました。そのうえで、NetExec を使用してバッチファイルを SMB 経由で多数のホストにコピーし、それを起動してランサムウェア ペイロードを実行しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">別の LOCKBIT.WARLOCK の侵入では、脅威アクターは SMB 経由で複数のホストにランサムウェア ペイロードをステージングしたうえで、スケジュールされたタスクから実行しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">NINTHBEE ランサムウェアのインシデントでは、脅威アクターは GPO を変更して、Windows Defender を無効にする悪意のあるスケジュールされたタスクを加え、そのうえでランサムウェア ペイロードを実行しました。同じ侵入で、脅威アクターは PsExec から複数のリモートホストで NINTHBEE ペイロードを実行しようともしています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">DOLLARLOCKER が関与していると思われるインシデントでは、脅威アクターは Windows サービスを作成して、ランサムウェア ペイロードを実行するコマンドを実行しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の脅威クラスタが Windows レジストリを利用して、ランサムウェアのデプロイを達成しています。UNC5471 の侵入時、脅威アクターは Run レジストリキーを作成し、複数のサーバーで AGENDA ランサムウェアを永続的に実行しました。INTERLOCK ランサムウェアの侵入では、脅威アクターは暗号化後に LegalNoticeCaption と LegalNoticeText のレジストリ値を変更し、起動時にシステムがランサム攻撃を受けていることを示すバナーを表示しました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは SMB をランサムウェア ペイロードのステージングに使用するだけでなく、被害組織のネットワーク全体でより広範囲にランサムウェアをデプロイするためにも利用していることが確認されています。あるインシデントでは、アクターは「Invoke-ShareFinder」PowerShell コマンドレットを使用してネットワーク共有を特定し、このリストを標的のリストとして REDBIKE に提供したと考えられます。その結果、SMB 経由で 500 台以上のエンドポイントにおいて暗号化が試みられました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">確認された侵入のうち少数のケースでは、脅威アクターは PowerShell を利用して、被害組織の環境全体に BitLocker 暗号化を自動的にデプロイしています。ある侵入では、脅威アクターは PowerShell スクリプトを使用して、複数のホストで BitLocker のインストール、構成、パスワードの割り当てを行いました。そのうえで、これらのホスト上の複数のドライブで暗号化を有効にし、システムの再起動をスケジュールして、ホストを強制的にロック状態にしました。また、レジストリを変更して、BitLocker の起動前の復旧画面にランサムノートも表示しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年に対応したランサムウェア侵入の約 43% で、脅威アクターが仮想化インフラストラクチャを標的としていることが確認されており、2024 年の 29% から増加しています。仮想システムへのランサムウェアのデプロイは通常手動で行われますが、2025 年には、脅威アクターがランサムウェアのデプロイ ステージの一部を自動化しようとしていたインシデントが少なくとも複数確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">UNC5495 の侵入時、脅威アクターは ESXi ホストの認証情報を受け入れるバッチ スクリプトを利用して、BABUK.MARIO のデプロイを自動化しました。バッチ スクリプトは KiTTY のステージング済みコピーを使用して、ランサムウェア ペイロードをホストにコピーしました。その後、SSH 経由で接続してコマンドを実行し、各ホストでペイロードを実行しました。別の侵入では、脅威アクターは PowerShell スクリプトを利用して被害組織の vCenter Server を認証し、新しい root パスワードを設定して、ESXi ホストで SSH を有効にしました。その後、同じスクリプトを使用して、RIFTEAR ランサムウェア ペイロードのホストへのコピー、バックアップの削除、仮想マシン（VM）のシャットダウン、ランサムウェア ペイロード実行前のセキュリティ ポリシーの無効化を行いました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ESXi ホストにランサムウェアをデプロイする前に、脅威アクターはホストの ExecInstalledOnly 設定を無効にして、カスタム バイナリの実行を許可していました（図 13）。ある侵入では、脅威アクターは vCenter Server にもアクセスし、ロックダウン モードの例外ユーザー設定を変更しました。この設定はホストがロックダウン モードのときに権限を維持できるユーザーを制御するものです。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の侵入事例で、脅威アクターは復号の前に仮想マシンを停止し、ファイルのロックを解除する手順を踏んでいました。これはほぼ確実にランサムウェア ペイロードの影響を最大化するためと思われます。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数の事例で、脅威アクターはランサムウェア ペイロードを実行する前に他のプログラムで使用中のファイルのロックを解除するために、正規のアンインストーラ ユーティリティである IOBIT を使用するか、その使用を試みていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">複数のアクターが暗号化の前に仮想マシンをシャットダウンし、バックアップとスナップショットを削除していることも確認されました。少なくとも 1 件の侵入では、アクターは PowerShell スクリプトを利用して、仮想マシンの電源をオフにするプロセスを自動化しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ある侵入では、脅威アクターは被害組織の Commvault サーバーにアクセスし、暗号化前に vCenter バックアップ ボリュームを削除することにより、復旧を妨害していました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">TridentLocker ブランドのランサムウェア インシデントでは、中程度の確度で、脅威アクターが WAVECALL の永続化に使用されたものと同じ CrushFTP のプレビュー ハイジャック手法を利用して、WAVECALL C2 サーバーからランサムウェア ペイロードをダウンロードして実行したものと思われます。</span></p>
</li>
</ul></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">検知、解析、復旧妨害の戦術</span></p>
<p><span style="vertical-align: baseline;">ランサムウェア アクターは常に検知回避、解析妨害、復旧妨害の戦術をオペレーションに取り入れ、侵入時の検知を回避するだけでなく、暗号化後に被害組織が簡単に復旧できないようにしています。このような戦術は脅威アクターが手動で実行することが多いですが、多くのランサムウェア ファミリーには、分析を妨害し、暗号化前にバックアップを削除する機能が組み込まれています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターは常にランサムウェア侵入時にセキュリティ管理を無効化して改ざんし、検知または悪意のあるペイロードの実行のブロックがされないようにしていました。最も一般的な方法として、脅威アクターが Windows レジストリを変更するなどして Windows Defender を無効化するケースが確認されています。一部のケースでは、Set-MpPreference PowerShell コマンドレットを使用して Defender の構成を変更し、マルウェアとランサムウェアのペイロードを除外として追加していました。また、脅威アクターは GPO、スケジュール設定されたタスク、PowerShell スクリプトを利用して、さまざまなセキュリティ管理を改ざんしていることも確認されています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">REDBIKE のインシデントでは、脅威アクターは PowerShell を使用して、Windows Defender のレジストリキーに関連付けられたさまざまな値（DisableRealtimeMonitoring、DisableScanOnRealtimeEnable、DisableOnAccessProtection など）を変更するコマンドを実行し、Windows Defender の多数の機能を無効にしました（図 14）。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">WHITERABBIT が関与した侵入では、脅威アクターは「Add-MpPreference」コマンドレットを使用した、Base64 でエンコードされた PowerShell コマンドを実行して、Defender の除外リストを変更し、ランサムウェア バイナリ、さまざまなファイル拡張子（「.cmd」、「.bat」、「.exe」など）、ユーザー データフォルダを追加しました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">NINTHBEE が関与したインシデントでは、脅威アクターはスケジュール設定されたタスクを登録して、Microsoft Defender によるダウンロードされたファイルとメールの添付ファイルに対するリアルタイム スキャンを無効にするコマンドを毎日実行していました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ランサムウェア アクターは活動の痕跡を消すために、アーティファクトを削除し、イベントログを消去することがよくあります。このようなレコードには、コマンドの実行、ファイアウォールのトラフィック、盗まれた認証情報に関する情報が含まれています。wevtutil ユーティリティを使用して、複数のインスタンスでログを簡単に削除できるようにしています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">FOULFOG.LINUX インシデントでは、脅威アクターはランサムウェア バイナリの名前を「filerw」という疑わしくない名前に変更し、システムのコマンド履歴を削除して、削除したファイルと置き換える空のファイルを作成しました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">一部のケースでは、脅威アクターはオペレーションで無害な名前を使用して、正規のソフトウェアやシステム リソースになりすまそうとしています。たとえば、RIFTTEAR インシデントでは、脅威アクターは「\Microsoft\Update」という名前のスケジュールされたタスクを登録し、エンドポイントの検知と対応（EDR）プロセスを強制終了させることを目的としていると思われる不正なコマンドを実行しました。CONTI が関与した別のケースでは、ランサムウェア バイナリのファイル名が「enc_lin」から「rsync」に変更されており、ネイティブの同期コマンドライン ユーティリティのように見せかけようとしていました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ランサムウェア アクターはたびたびバックアップを無効化または削除して、復元オプションを阻止または制限していました。一部のケースでは、脅威アクターは PowerShell スクリプトを使用してバックアップ サーバーの停止、またはボリューム シャドーコピー（VSS）の削除を行っています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">注目すべき点として、RANSOMHUB のインシデントでは、脅威アクターは Cisco Integrated Management Controller（CIMC）へのアクセスを利用して、9 つのノードからなる Cohesity クラスタ全体で仮想メディア経由 Debian Linux ISO イメージをマッピングしました。起動優先順位を変更し、ハードウェアの電源を入れ直すことで、ノードが外部の Linux 環境で起動し、Cohesity のオペレーティング システム（OS）が上書きされ、バックアップ データにアクセスできないようにしました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">いくつかの侵入では、脅威アクターはセキュリティ ソフトウェア ソリューションに関連するプロセスとサービスを終了させるツールを使用しました。具体的には、署名付きカーネルモード ドライバを悪用するもので、例としては、オープンソースの TERMINATOR や WATCHDOGKILLER、脆弱なカーネルモード ドライバをデコードしてインストールするユーティリティである WARCLAW などの非公開ツールがあります。</span></p>
</li>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">ツールの普及</span></p>
<p><span style="vertical-align: baseline;">2025 年を通して、ランサムウェア アクターはランサムウェア侵入のさまざまなステージで、一般公開されているツールと正規のソフトウェアに大きく依存していることが引き続き確認されました。正規のソフトウェアは依然として多用されていますが、RMM ツールと侵入後活動 C2 フレームワークの使用はわずかに減少しました。特に、WinRAR と Rclone の使用はインシデントのほぼ 4 分の 1 で確認されました。このツールはそれぞれデータのステージングと引き出しで通常使用されるものであるため、データ窃取を伴うインシデントの増加に伴う結果と考えられます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターが 2025 年のランサムウェア インシデントで侵入後活動 C2 フレームワークを使用した割合は約 15% で、2024 年の約 20% から減少しました。侵入後活動フレームワークの使用が減少している理由は、主に Cobalt Strike BEACON の使用が減少傾向にあるためです。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年のランサムウェア インシデントで Cobalt Strike BEACON がデプロイされたのはわずか 2% で、数年にわたって減少傾向が続いています。2021 年にはランサムウェア インシデントの約 60% で BEACON が使用されていましたが、2022 年には約 38%、2023 年には 20%、2024 年には 11% にまで減少しました。この減少は AdaptixC2 などの新しいフレームワークを模索する一部のアクターが存在することが一つの要因として考えられます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">侵入の約 8% で AdaptixC2（ADAPTAGENT）侵入後活動フレームワークが使用されていました。</span><a href="https://unit42.paloaltonetworks.com/adaptixc2-post-exploitation-framework/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">AdaptixC2</span></a><span style="vertical-align: baseline;"> はペネトレーション テスター向けに開発されたオープンソースの侵入後活動フレームワークです。ただ、長年にわたって CobaltStrike が使用されてきたのと同様に、脅威アクターはオペレーションをスムーズに実行するため、このようなタイプのペネトレーション テストツールを悪用することがよくあります。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">頻度は低いものの、MYTHICAGENT、METASPLOIT、HAVOC、EXPLORATIONC2 に関連するペネトレーション フレームワークも確認されました。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">昨年確認された傾向と同様に、脅威アクターによるリモート管理ツールの利用はわずかに低下していると思われます。2025 年のインシデントの約 24% で少なくとも 1 つの RMM が関与しており、2024 年の 28%、2023 年の 40% から減少しています。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年のランサムウェア インシデントで確認されたリモート管理ツールは 10 種類で、2024 年の 9 種類と同程度ですが、2023 年の 13 種類からは全体的に減少しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">同じ侵入において複数の異なる RMM を利用する脅威アクターの事例も減少しました。2025 年に複数の RMM が確認されたインシデントは約 5% にとどまり、2024 年の 8%、2023 年の 16% から減少しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">過去数年と同様に、2025 年もランサムウェア インシデントで最もデプロイされた RMM は AnyDesk でした。ただ、全体的な使用率は 2023 年の約 31%、2024 年の 16% から 2025 年には 10% まで減少しています。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">脅威アクターによるトンネラーの使用は、2024 年とほぼ同程度ですが、個々のトンネラーの使用にはわずかな変化がありました。たとえば、CLOUDFLARED は 2025 年のインシデントの 8% で確認されましたが、2024 年は約 4% でした。</span></p>
</li>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">SYSTEMBC の使用はわずかに減少しており、2023 年にはトンネラーを使用したインシデントの約 14% でしたが、2024 年には 7% 強、2025 年には 6% 強にまで減少しています。SYSTEMBC インフラストラクチャは 2024 年 5 月に Operation Endgame によって</span><a href="https://www.europol.europa.eu/media-press/newsroom/news/largest-ever-operation-against-botnets-hits-dropper-malware-ecosystem" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">破壊</span></a><span style="vertical-align: baseline;">されています。マルウェアは依然としてフォーラムで販売されていますが、法執行機関の介入により一部の脅威アクターはそのマルウェアをオペレーションで使用し続けることをやめた可能性があります。</span></p>
</li>
</ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年全体を通じて、脅威アクターは引き続き Advanced IP Scanner や SoftPerfect Network Scanner などの公開ネットワーク スキャン ツールを利用しており、その使用割合は侵入の約 50% で、2024 年と同程度となっています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">2025 年には、脅威アクターがデータ窃取をスムーズに進めるためによく使用する WinRAR や Rclone などの公開ツールの使用が増加しました。これは 2024 年から 2025 年にかけてデータ窃取が疑われるまたは確認されたインシデントが全体的に増加していることと比例しています。WinRAR と Rclone はインシデントの約 23% で確認されました。2024 年に Rclone が関与した侵入は約 16%、WinRAR が関与した侵入はわずか 8% でした。</span></p>
</li>
</ul>
<h4><strong style="vertical-align: baseline;">修復とセキュリティ強化</strong></h4>
<p><span style="vertical-align: baseline;">ランサムウェアによる脅威への対処に役立つ推奨事項は、ホワイト ペーパーの</span><a href="https://cloud.google.com/blog/topics/threat-intelligence/ransomware-protection-and-containment-strategies"><span style="text-decoration: underline; vertical-align: baseline;">ランサムウェアの防止および封じ込め戦略: エンドポイント保護、セキュリティ強化、封じ込めのための実践ガイダンス</span></a><span style="vertical-align: baseline;">に記載されています。</span></p>
<h4><strong style="vertical-align: baseline;">見通しと影響</strong></h4>
<p><span style="vertical-align: baseline;">アクター間の対立や法的措置によって混乱が続いているものの、ランサムウェア アクターは引き続き強い動機を維持しており、恐喝のエコシステムはこれまでどおりの回復力があることを示しています。しかし、いくつかの指標からこのようなオペレーションの全体的な収益性は低下しており、少なくとも一部の脅威アクターは大企業を標的することをやめ、小規模な組織に対して多数の攻撃を行うことに重点をシフトさせていることがわかります。これは被害組織のセキュリティ態勢の向上、身代金要求の拒否の増加、復旧機能の強化により、デプロイが成功しにくくなったことが原因であると考えられます。今後数年間で、報告要件や身代金の支払い禁止などの規制が厳しくなり、身代金の支払いを思いとどまる企業が増える可能性があります。今後もランサムウェアは世界的に最も影響の大きい脅威の一つであると予想されますが、利益の減少により、他の収益化手法と戦術にシフトする脅威アクターも出てくる可能性があります。このような動きは、データ窃取による恐喝オペレーションの増加、より攻撃的な恐喝戦術の使用に加え、侵害したインフラストラクチャを使用してフィッシング メッセージを送信するなど、被害組織の環境へのアクセスの二次的な収益化メカニズムでの場当たり的な使用といった形で現れてくる可能性があります。</span></p>
