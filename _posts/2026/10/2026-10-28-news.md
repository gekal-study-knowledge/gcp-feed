<h2 class="release-note-product-title">AlloyDB for PostgreSQL</h2>
<h3>Announcement</h3>
<p>The following AlloyDB AI and vector search features and improvements are
generally available
(<a href="https://cloud.google.com/products#product-launch-stages">GA</a>):</p>
<ul>
<li><p>The <code>alloydb_scann</code> extension supports four-level tree (4LT) ScaNN vector
indexes on PostgreSQL 17 and later, providing support for tables with up to
10 billion vector rows. For more information, see
<a href="https://docs.cloud.google.com/alloydb/docs/ai/create-scann-index#create-scann-index-manual">Four-level ScaNN tree indexes</a>.</p></li>
<li><p>4LT ScaNN vector indexes support automatic index maintenance. For more
information, see <a href="https://docs.cloud.google.com/alloydb/docs/ai/create-scann-index">Create a ScaNN index</a>
and
<a href="https://docs.cloud.google.com/alloydb/docs/ai/maintain-vector-indexes#maintain-index-automatically">Maintain vector indexes automatically</a>.</p></li>
<li><p>You can enable streaming functionality for ScaNN vector indexes by setting
the <code>scann.satisfy_limit</code> parameter to <code>relaxed_order</code>. When enabled, the
vector scan continues searching through additional leaf partitions until it
finds enough results to satisfy the <code>LIMIT</code> clause of your query, improving
recall on filtered searches. Additionally, you can enable this feature for
parallel process scans by setting the <code>scann.enable_parallel_satisfy_limit</code>
database flag to <code>on</code>. For more information, see
<a href="https://docs.cloud.google.com/alloydb/docs/reference/ai/scann-index-reference#scann-satisfy-limit">ScaNN index reference</a>
and
<a href="https://docs.cloud.google.com/alloydb/docs/ai/best-practices-tuning-scann#improve-recall-for-filtered-searches">Best practices for tuning ScaNN indexes</a>.</p></li>
<li><p>Vector assist simplifies the deployment and management of your AlloyDB
vector workloads by helping you set up production-ready vector search
capabilities, including embedding generation, query optimization, and index
creation for vector types such as Hierarchical Navigable Small World (HNSW).
For more information, see
<a href="https://docs.cloud.google.com/alloydb/docs/ai/vector-assist-overview">Vector assist overview</a>.</p></li>
<li><p>For AlloyDB for PostgreSQL instances running PostgreSQL 17 and later, the
maximum supported value for <code>num_leaves</code> when building ScaNN vector indexes
is increased from 30,000,000 to 104,857,600. For more information, see
<a href="https://docs.cloud.google.com/alloydb/docs/ai/create-scann-index">Create a ScaNN index</a> and
<a href="https://docs.cloud.google.com/alloydb/docs/reference/ai/scann-index-reference">ScaNN index reference</a>.</p></li>
<li><p>You can use the
<a href="https://docs.cloud.google.com/alloydb/docs/reference/extensions#external_search_fdw"><code>external_search_fdw</code></a>
extension to connect to external search clusters and query their data
directly from your database using the following search sources:</p>
<ul>
<li><p><a href="https://docs.cloud.google.com/alloydb/docs/elastic-search">Elasticsearch</a></p></li>
<li><p><a href="https://docs.cloud.google.com/alloydb/docs/solr-search">Solr</a></p></li>
<li><p><a href="https://docs.cloud.google.com/alloydb/docs/opensearch">OpenSearch</a></p></li>
</ul></li>
<li><p>AlloyDB supports the <code>rum</code> extension for high-performance full-text search
operations on PostgreSQL 17 and earlier. The <code>rum</code> extension extends
standard GIN indexes by storing positional information directly in the
index, letting you perform faster phrase searches and relevance ranking
without accessing the table data. For more information, see
<a href="https://docs.cloud.google.com/alloydb/docs/ai/create-rum-index">Create and manage a RUM index</a>.</p></li>
</ul>
<h3>Fixed</h3>
<p>AlloyDB provides more accurate memory usage estimation and prevents
out-of-memory (OOM) errors when you build a ScaNN
<a href="https://docs.cloud.google.com/alloydb/docs/ai/create-scann-index#create-scann-index-manual">four-level tree index</a>.
This feature is in
<a href="https://cloud.google.com/products#product-launch-stages">Preview</a>. This update
improves the stability of index builds by enforcing memory limits and
improving memory estimation under constrained conditions.</p>
<h3>Security</h3>
<p>In response to <a href="https://docs.cloud.google.com/support/bulletins#gcp-2026-071">GCP-2026-071</a>, Google is
updating AlloyDB managed components. The fix to the certificate store is shipped
in a new maintenance version that AlloyDB applies during
<a href="https://docs.cloud.google.com/alloydb/docs/maintenance#timing">scheduled maintenance</a>, so you don't need to
manually update AlloyDB managed instances. You can also apply the fix by
<a href="https://docs.cloud.google.com/alloydb/docs/self-service-maintenance">performing self-service maintenance</a>.</p>
<p>Depending on how you connect to AlloyDB, take the following actions:</p>
<ul>
<li><p>If you use the AlloyDB Auth Proxy, then upgrade it to
<a href="https://docs.cloud.google.com/alloydb/docs/auth-proxy/connect#install">v1.17.2 or later</a>. If you run the
standalone proxy binary, then also update the host's certificate authority
(CA) certificates.</p></li>
<li><p>If you use the
<a href="https://docs.cloud.google.com/alloydb/docs/connect-language-connectors">AlloyDB Language Connectors</a>, then
update the language runtime and operating system CA certificates (for example,
Go 1.26.10 or 1.27.3 or later).</p></li>
</ul>

<div class="block-paragraph"><p>Enterprise AI needs to go beyond simple chat interfaces. To provide real value, AI agents must access your data warehouses to generate actionable insights, all while maintaining strict security and data governance.</p><p>This guide explores how to build a secure bridge between Google Cloud’s Gemini Enterprise and Snowflake. By using the Model Context Protocol (MCP) and the Google Agent Development Kit (ADK), you can empower your agent to act as an assistant that understands natural language, generates precise SQL via Snowflake Cortex and executes queries with user-level permissions.</p><h3><b>Choosing the right integration pattern</b></h3><p><b>Direct Connection vs. custom orchestration</b></p><p>The Google ADK architecture demonstrated in this post represents the advanced / custom orchestration pattern. It is designed for developers building complex, multi-agent systems on Google Cloud, such as workflows that combine Snowflake insights with external enterprise tools, custom reasoning loops, or cross-platform state management in Gemini Agent Engine.</p><p>For standard enterprise basic use cases where you want to connect Gemini Enterprise directly to Snowflake use the joint solutions mentioned in <a href="https://www.snowflake.com/en/developers/guides/quickstart-iceberg-cortex-gemini/" target="_blank">this link</a>.</p><h3><b>The architectural approach</b></h3><p>This architecture allows a business user to ask questions like, <i>"What were our top 5 selling items in Texas last quarter?"</i></p><p>Rather than exposing raw SQL execution to the client, the agent delegates both query generation and execution to a governed Snowflake Cortex Agent exposed through the Snowflake MCP server:</p><ol><li><b>Governed translation</b>: The ADK agent passes the user's natural language question to the Snowflake MCP server, which invokes the Cortex Agent (CORTEX_AGENT_RUN) backed by Cortex Analyst semantic view.</li><li><b>Direct execution within the governed boundary</b>: The Cortex Agent translates the question into SQL and executes it directly inside Snowflake using the authenticated user's OAuth session and role privileges, returning the structured results to the ADK agent.</li></ol><p>This approach provides deterministic text-to-SQL translation mapped to your corporate semantic definitions, keeps query execution inside Snowflake's governed boundary, and reduces the risk of schema hallucinations or unvalidated SQL execution.</p><h3><b>System architecture flow</b></h3><p>The diagram below illustrates the trust boundaries and the numbered flow of execution between the Gemini Enterprise app and Snowflake ecosystems.</p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">Many organizations with workloads on VMware are looking for ways to expedite their data center exits, migrate and modernize their mission-critical workloads, or simply leverage the cloud as a secondary disaster recovery site. But they want to do so without altering existing operational playbooks. </span></p>
<p><span style="vertical-align: baseline;">Today, we are announcing the general availability of the </span><a href="https://cloud.google.com/solutions/vmware"><span style="text-decoration: underline; vertical-align: baseline;">VMware solution</span></a> <span style="vertical-align: baseline;">on Google Cloud, part of the </span><a href="http://cloud.google.com/solutions/modernize"><span style="text-decoration: underline; vertical-align: baseline;">Google Cloud Modernize</span></a><span style="vertical-align: baseline;"> portfolio, giving you full administrative authority for VMware Cloud Foundation (VCF) on dedicated Google Cloud bare metal.</span></p>
<p><span style="vertical-align: baseline;">This new deployment model complements our existing Google-managed service, offering you greater flexibility and architectural choice for running VMware workloads in Google Cloud. With this new self managed offering, organizations with dedicated operational practices maintain direct control over their virtualization stack, specific maintenance windows, and custom integration with third-party monitoring and management tools.</span></p>
<p><span style="vertical-align: baseline;"><span style="vertical-align: baseline;">The launch of VMware Cloud Foundation 9.x by Broadcom is a key driver behind this self-managed deployment option. Featuring a unified VCF control plane for end-to-end stack deployment and lifecycle management, this solution enables Google Cloud customers to directly leverage Broadcom's latest innovations and fully maximize their licensing investments in VMware Cloud Foundation.</span></span></p>
<p style="padding-left: 40px;"><span style="font-style: italic; vertical-align: baseline;">“Customers want the agility of Google Cloud without rearchitecting their VMware environments or abandoning the operational practices they have invested in. <div class="block-paragraph_advanced"><h3><strong style="vertical-align: baseline;">High-performance architecture on bare metal</strong></h3>
<p><span style="vertical-align: baseline;">The self-managed VMware solution is deployed on dedicated GCE Z3 bare metal instances (z3-highmem-192-highlssd-metal). Powered by 2.2 GHz - 4th Generation Intel Xeon Processors (Sapphire Rapids) processors, each node delivers:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">96 physical cores (192 hyper-threads) </span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">1.5 TB RAM</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">72 TB all-flash NVMe storage</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">200 Gbps networking</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Operating natively within Google Cloud alongside GCE and Google Kubernetes Engine (GKE), this architecture provides high bandwidth and low-latency networking for transactional databases and direct access to native Google Cloud services, including BigQuery, the Gemini platform, Cloud Run, and more. </span></p>
<p><span style="vertical-align: baseline;">The solution's storage architecture is built on VMware vSAN hyperconverged infrastructure using high-performance, all-flash NVMe storage from Z3 nodes. Beyond standard storage, these drives can also be utilized for NVMe memory tiering. In addition to vSAN, the solution also supports NetApp volumes.</span></p>
<p style="padding-left: 40px;"><span style="font-style: italic; vertical-align: baseline;">"VMware solution on Google Cloud gives enterprises greater control, choice, and architectural freedom as they move to the cloud. We are excited to expand our partnership with Google Cloud by offering NetApp Volumes as an external datastore. Together, we’re helping customers confidently migrate their VMware workloads and data to Google Cloud while retaining the flexibility, performance and data management capabilities they rely on</span><span style="vertical-align: baseline;">.” <strong>- Pravjit Tiwana, SVP/GM, Cloud Storage, NetApp</strong></span></p>

### Gemini エージェントがスタートアップにもたらすメリット

- **Link**: [https://cloud.google.com/blog/ja/topics/startups/what-the-gemini-agent-means-for-startups/](https://cloud.google.com/blog/ja/topics/startups/what-the-gemini-agent-means-for-startups/)

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 10 月 16 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/topics/startups/what-the-gemini-agent-means-for-startups?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">小規模なチーム、限られたランウェイ、そして常に迅速なプロダクト提供を求められるプレッシャー。これは、Google for Startups が日々ともに働く起業家たちが直面している現実です。会社をゼロから立ち上げる際、運用上のオーバーヘッドやインフラストラクチャ構築に費やす時間は、コアプロダクトの開発に割くべき時間を削ることになります。</span></p>
<p><span style="vertical-align: baseline;">先週開催された Gemini at Work 2026 で、Google は </span><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/welcome-to-gemini-at-work-2026"><span style="text-decoration: underline; vertical-align: baseline;">Gemini エージェントを発表</span></a><span style="vertical-align: baseline;">しました。これは、パーソナル アシスタントとしても、チームの専任メンバーとしても機能する汎用エージェントです。そして今週、新しいフロンティア モデルである </span><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/gemini-4-argon-available-on-google-cloud?e=48754805"><span style="text-decoration: underline; vertical-align: baseline;">Gemini 4 Argon</span></a><span style="vertical-align: baseline;"> の一般提供を開始しました。このモデルは、長時間のマルチステップ タスク全体を通してコンテキストを維持するようにトレーニングされています。</span></p>
<p><span style="vertical-align: baseline;">ここでは、Gemini エージェントの仕組み、創業者に役立つ 5 つのポイント、そしてスタートアップが実力以上の成果を上げるためにこれをどう活用しているかをご紹介します。</span></p>
<h4><strong style="vertical-align: baseline;">Gemini エージェントとは</strong></h4>
<p><span style="vertical-align: baseline;">文書作成、コーディング、データ分析ごとに、別々の chatbot にプロンプトを入力する必要はもうありません。Gemini エージェントなら、1 つのエージェントが大まかな目標を理解し、完成した成果物まで仕上げて提供します。これは、次の 3 つの原則によって定義されます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">統合型:</strong><span style="vertical-align: baseline;"> 1 つのエージェントで、ナレッジワーク、データ分析、クリエイティブ アセットの生成、コードの記述と実行を処理できるようになりました。複雑なジョブの場合、専用の一時的なサブエージェントを動的にスピンアップし、それらの作業を並列または順次連携させます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">どこからでもアクセス可能:</strong><span style="vertical-align: baseline;"> ウェブ、コマンドライン、デスクトップ、モバイルなど、日常的に使うあらゆる環境で動作します。さらに、Gmail、ドキュメント、スプレッドシート、スライド、ドライブ、Chat、カレンダーにもネイティブに対応しています。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">永続性:</strong><span style="vertical-align: baseline;"> クラウド上で動作し、4 つの領域（セッション、セマンティック、手続き、エピソード）にわたって連続的なメモリーを保持します。新規採用者のように自ら業務に慣れ、チーム、ツール、ビジネス コンテキストを学習するため、プロンプトごとに自社について説明し直す必要はありません。また、ノートパソコンを閉じた後も、数日間にわたるタスクを進め続けることができます。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">5 つの役割を同時にこなす創業者にとって、Gemini は、カレンダー、プロジェクト、ドキュメントの状況をすでに把握している「デジタル参謀」のように機能します。マーケット トレンドの調査、スプレッドシートでの財務モデル作成、そしてその両方を網羅した提案資料の作成まで、各ステップでプロジェクト概要や目標を繰り返し説明することなく、Gemini にまとめて依頼できます。また、先回りして自発的に機能します。投資家から最新のプロダクト アップデートを資料として求めるメールが届くと、Gemini がそのリクエストを検知して処理を提案します。ワンクリックで作業が完了し、すぐに共有やレビューが可能な状態で手元に戻ってきます。</span></p>
<h4><strong style="vertical-align: baseline;">スタートアップ向けの 5 つの重要ポイント</strong></h4>
<p><strong style="vertical-align: baseline;">1. コワーカー エージェントとスキルでアウトプットを拡大</strong></p>
<p><span style="vertical-align: baseline;">個人のアシスタント機能にとどまらず、チーム全体と連携する持続的な</span><strong style="vertical-align: baseline;">コワーカー エージェント</strong><span style="vertical-align: baseline;">を作成することもできます。各エージェントには、それぞれ専用の Workspace アカウント、メールアドレス、ドライブ ストレージ、ディレクトリ情報が付与されます。リリース コーディネーター、QA トリアージ担当者、財務アナリストといった特定の役割を設定すれば、チームメンバーは Chat スペースにエージェントを追加したり、Google ドキュメントのコメントで </span><code style="vertical-align: baseline;">@名前リンクを追加</code><span style="vertical-align: baseline;">したりして作業を委任できます。</span></p>
<p><span style="vertical-align: baseline;">また、エージェントに再利用可能な</span><strong style="vertical-align: baseline;">スキル</strong><span style="vertical-align: baseline;">を持たせるだけでなく、Gemini が業務プロセスを学習しながら自らスキルを作成することも可能です。たとえば、BigQuery や Knowledge Catalog と連携した運用レポートスキルを使えば、チームの誰もが平易な言葉で質問するだけで、リアルタイムのレポートを作成して保存できます。一度保存すれば、追加のトークンコストをかけることなく、必要なときにいつでもレポートを実行できます。さらに Gemini では、法務や金融サービスをはじめとする、特定の領域に特化した事前構築済みの機能も提供しています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">スタートアップにとっての意味:</strong><span style="vertical-align: baseline;"> コワーカー エージェントによってチームの対応力を即座に引き上げることができます。また、スキルを活用することで、投資家向けレポートや運用レポートなどの定期的なプロセスを標準化し、実行のたびにトークンを消費することもなくなります。</span></p>
</li>
</ul>
<p><strong style="vertical-align: baseline;">2. オープンモデルとサードパーティ モデルを自由に選択</strong></p>
<p><span style="vertical-align: baseline;">Gemini はエージェントであり、その基盤となるモデルは自由に選択できます。スタートアップのアーキテクチャが成熟するにつれて、すべてのタスクを単一のフロンティア モデルに処理させると、粗利益が急速に圧迫されます。Gemini エージェントを使用すると、Gemini モデル、Anthropic の Claude などのサードパーティ モデル、</span><a href="https://cloud.google.com/blog/topics/startups/why-your-startup-needs-open-models-alongside-frontier-apis"><span style="text-decoration: underline; vertical-align: baseline;">Gemma</span></a><span style="vertical-align: baseline;"> などの軽量なオープンモデルの間で、ワークロードを動的にルーティングできます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">スタートアップにとっての意味:</strong><span style="vertical-align: baseline;"> ロックインされることなく、柔軟性を確保できます。大量の決定的ジョブにはコンパクト モデルを、複雑な推論にはフロンティア モデルを使用することで、タスクあたりのコストを最適化できます。また、プロダクトの進化に合わせて、ワークフローを再構築することなくモデルを入れ替えることができます。</span></p>
</li>
</ul>
<p><strong style="vertical-align: baseline;">3. サービスやツールに接続</strong></p>
<p><span style="vertical-align: baseline;">エージェントの有用性は、アクセスできるシステムによって決まります。Gemini エージェントは、Google Workspace に加え、パートナー ソリューションを含むエンジニアリング、データ、ビジネスの各種スタックに直接接続できます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">開発とコラボレーション:</strong><span style="vertical-align: baseline;"> Git、Slack、Jira など。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">データとローカル ファイル:</strong><span style="vertical-align: baseline;"> BigQuery、Postgres、Snowflake、Databricks などに加え、デスクトップ上のファイルにも対応。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">MCP を介したカスタムツール:</strong><span style="vertical-align: baseline;"> ネットワーク内外の Model Context Protocol（MCP）サーバー。エンジニアが社内ツールを構築して共有できます。</span></p>
</li>
</ul>
<p><strong style="vertical-align: baseline;">スタートアップにとっての意味:</strong><span style="vertical-align: baseline;"> カスタム コネクタの保守にエンジニアのリソースを割く代わりに、エージェントを既存のコードベース、データベース、MCP ツールに直接接続して、データの所在を問わずリアルタイムに操作できるようになります。</span></p>
<p><strong style="vertical-align: baseline;">4. 組み込みのセキュリティとガバナンス</strong></p>
<p><span style="vertical-align: baseline;">B2B スタートアップにとって、大企業によるセキュリティ監査は、商談が失速しやすい大きな関門です。バックグラウンドでは、各エージェントに暗号化された</span><strong style="vertical-align: baseline;">エージェント ID</strong><span style="vertical-align: baseline;"> が割り当てられ、明確な監査証跡が確保されます。また、エージェントは分離されたサンドボックス内で実行され、組み込みのプロンプト インジェクション防御機能によって保護されます。外部トラフィックは </span><strong style="vertical-align: baseline;">Agent Gateway</strong><span style="vertical-align: baseline;"> を経由してルーティングされるため、ガバナンス ポリシーを確実に適用できます。さらに、コワーカー エージェントもそれぞれ Workspace アカウントを持つため、管理の手間はこれまでのユーザー管理とまったく変わりません。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">スタートアップにとっての意味:</strong><span style="vertical-align: baseline;"> 大企業の最高情報セキュリティ責任者から、AI ワークフローにおけるデータ プライバシー、プロンプト インジェクション、アクセス制御への対策を問われても、すでにエンタープライズ グレードのアーキテクチャが整っているため、調達プロセスのハードルをスムーズにクリアできます。</span></p>
</li>
</ul>
<p><strong style="vertical-align: baseline;">5. リアルタイムのコスト管理でランウェイを保護</strong></p>
<p><span style="vertical-align: baseline;">サブエージェントを数時間から数日間にわたって実行する自律型エージェントは、ループ処理をチェックしないままでいると、すぐに請求額が膨れ上がってしまいます。こうした事態を防ぐため、Cloud Billing コンソールでリアルタイムの費用上限を直接設定できるようになりました。上限に達するとプロジェクトのエージェントが自動的に一時停止するため、バグによる予期せぬ高額請求を確実に回避できます。その基盤として、Gemini は推論に最適化された TPU 8i を含む </span><a href="https://cloud.google.com/ai-infrastructure?e=48754805"><span style="text-decoration: underline; vertical-align: baseline;">Google による特化型 AI インフラストラクチャ</span></a><span style="vertical-align: baseline;">上で動作し、前世代比で 80% 優れたコスト パフォーマンスを実現します。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">スタートアップにとっての意味:</strong><span style="vertical-align: baseline;"> 創業者や開発者は、長時間動く並列エージェント ループの試行錯誤に安心して取り組めます。標準で備わった財務セーフティ ネットが手元資金を守り、投資家からの信頼確保にもつながります。</span></p>
</li>
</ul>
<h4><strong style="vertical-align: baseline;">すでに実践している創業者</strong></h4>
<p><span style="vertical-align: baseline;">スタートアップや AI ネイティブなイノベーターは、すでに Gemini を活用しています。没入型ストーリーテリング プラットフォームを提供する</span><a href="https://cloud.google.com/transform/whenere-dreamlands-gemini-jane-austen-fortnite-future-of-fan-fiction"><span style="text-decoration: underline; vertical-align: baseline;"> </span><strong style="text-decoration: underline; vertical-align: baseline;">Whenere</strong><span style="text-decoration: underline; vertical-align: baseline;"> は Dreamlands を活用</span></a><span style="vertical-align: baseline;">して、名作小説『高慢と偏見』の世界を Fortnite 上に再現しました。Dreamlands は Gemini 基盤のエージェント型 3D ワールド構築プラットフォームであり、Gemini は新しいオブジェクトごとにテクスチャを約 7 秒、10 セント未満のコストで生成しました。あるアーティストは、1 日で約 250 個のカスタム アセットを作成し、歴史的に忠実な邸宅を 1 週間足らずで完成させました。アプリケーション構築プラットフォームの </span><strong style="vertical-align: baseline;">Lovable</strong><span style="vertical-align: baseline;"> をはじめ、</span><strong style="vertical-align: baseline;">OpenEvidence</strong><span style="vertical-align: baseline;">、</span><strong style="vertical-align: baseline;">Recursion</strong><span style="vertical-align: baseline;">、</span><strong style="vertical-align: baseline;">Replit</strong><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/welcome-to-gemini-at-work-2026?e=48754805"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">など</span></a><span style="vertical-align: baseline;">のスタートアップやイノベーターも、この動きに加わっています。</span></p>
<p><strong style="vertical-align: baseline;">Google for Startups で構築</strong></p>
<p><span style="vertical-align: baseline;">エージェント時代の到来により、社内業務を担うコワーカー エージェントのデプロイから、プロダクトへのエージェント型ワークフローの直接組み込みまで、少数精鋭のチームであっても実力以上の大きな成果を生み出せるようになります。</span></p>
