### Scale agents securely with IAM Helper Agent Skills and MCP Tools

- **Link**: [https://cloud.google.com/blog/products/identity-security/scale-agents-securely-with-iam-helper-agent-skills-and-mcp-tools/](https://cloud.google.com/blog/products/identity-security/scale-agents-securely-with-iam-helper-agent-skills-and-mcp-tools/)

- **Fetched**: 2026-10-27 01:30:29

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">As organizations adopt autonomous agents to build applications, securing identities and access has become more challenging. Developers relying on agents to provision cloud resources, write Terraform, and deploy microservices at machine-speed only find their CI/CD pipelines blo</span><span style="vertical-align: baseline;">cked even faster as security friction scales. </span><span style="vertical-align: baseline;"> </span></p>
<p><span style="vertical-align: baseline;">To help you get ahead of agentic-era Identity and Access Management, today we’re introducing IAM Helper. This suite of intelligent, agent-facing building blocks can automate complex, end-to-end IAM workflows. </span></p>
<p><span style="vertical-align: baseline;">As an agent-native orchestration and interface layer for Google Cloud IAM, it augments Google Cloud’s core IAM engines — including Policy Intelligence and Privileged Access Manager (PAM) — making IAM skills callable directly by autonomous code assistants, deployment pipelines, and custom agents. Using this functionality reduces the administrative overhead of maintaining least-privilege security and agent governance, while maximizing utility, and accelerating deployment.</span></p>
<h3><strong style="vertical-align: baseline;">IAM Helper Agent Skills: Fast, secure deployment with automated governance</strong></h3>
<p><span style="vertical-align: baseline;">Manual troubleshooting of permission blockers creates friction for engineering and administrators, while shortcuts can lead to broad agent over-permissioning that puts least privilege at risk. </span></p>
<p><span style="vertical-align: baseline;">IAM Helper empowers agents to handle access management dynamically. It shifts the burden of policy evaluation away from human administrators and LLMs, offloading complex orchestration directly to the Google Cloud backend, to maximize token efficiency and prevent costly operational bottlenecks.</span></p>
<p><span style="vertical-align: baseline;">Rather than operating as isolated utilities, IAM Helper Agent Skills guide agents through the cloud access lifecycle. These end-to-end workflows, helper scripts, and guardrails packaged using the open </span><a href="https://agentskills.io/home" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Agent Skills standard</span></a><span style="vertical-align: baseline;"> can orchestrate multiple underlying functions and APIs to resolve complex IAM tasks. They work across common agents (Gemini CLI, Gemini Cloud Assist, ADK, Claude Code, and Cursor). </span></p>
<h3><strong style="vertical-align: baseline;">Built-in guardrails and real-world impact</strong></h3>
<p><span style="vertical-align: baseline;">Every IAM Helper agent skill separates read-only discovery from policy changes: Diagnostics and simulations run automatically, while any change to access policies pauses for human-in-the-loop (HITL) confirmation based on customizable risk tiers. To see the value of IAM Helper in practice, consider how it transforms two everyday scenarios:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Scaled user-assisted remediation</strong><span style="vertical-align: baseline;">: Suppose a developer's coding agent hits a 403 error while deploying a new application. Rather than filing a support ticket and idling, the agent uses iam-helper-for-troubleshooting to identify the missing Pub/Sub permission in seconds, then uses iam-helper-for-privileged-access-management to request a one-hour JIT grant, eliminating hours of debugging friction.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Autonomous pipeline self-healing</strong><span style="vertical-align: baseline;">: An infrastructure agent encounters a permission block during a routine deployment pipeline. Rather than failing the build, the pipeline uses IAM Helper Agent skills to generate a revised, least-privilege policy, verifies against 90 days of logs via iam-helper-for-policy-simulator that active services won't break, and routes the change to an admin for quick approval.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">IAM Helper Agent Skills are designed for maximum token and cost efficiency, allowing agents to execute multi-step administrative operations autonomously.</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Authoring compliant, least-privilege policies</strong><span style="vertical-align: baseline;">: As DevOps engineers translate access requirements into JSON, YAML, or Terraform HCL, iam-helper-for-policy-management generates and validates IAM v1 allow bindings and IAM v2 deny rules. It automatically catches and blocks risky configs before they are applied, including public access (allUsers) and broad basic roles (roles/owner, roles/editor).</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Unblocking 403 errors in seconds</strong><span style="vertical-align: baseline;">: When an on-call engineer or deployment agent hits a cryptic 403 PERMISSION_DENIED error, iam-helper-for-troubleshooting identifies the exact missing permission or blocking rule in seconds. It adapts to the user’s role: Developers can check if they can unblock themselves locally or generate a structured ticket for their administrator (Requester flow), while security administrators can trace inherited allow and v2 deny rules across organization, folder, and project hierarchies to resolve the issue (Resolver flow).</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Simulating blast radius before rolling out changes</strong><span style="vertical-align: baseline;">: Before a platform engineer updates a policy or applies IAM Recommender role reductions, they need confidence that active workloads won't break. iam-helper-for-policy-simulator walks the agent through a structured plan, simulate, analyze, and apply flow, testing proposed changes against 90 days of historical access logs to confirm existing traffic won't be disrupted before any update takes effect.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Elevating access just-in-time instead of granting standing privileges</strong><span style="vertical-align: baseline;">: When responders or maintenance agents need temporary production access, iam-helper-for-privileged-access-management manages the lifecycle of on-demand credentials through Privileged Access Manager (PAM). It supports requester, administrator, and approver workflows so elevated access is audited, time-bound, and automatically revoked once the task is done.</span></p>
</li>
</ol>
<p><span style="vertical-align: baseline;">While IAM Helper Agent Skills supply the high-level workflow logic, they are all based on a common set of foundational MCP Tools. </span></p>
<h3><strong style="vertical-align: baseline;">Powered by Google Cloud IAM MCP tools</strong></h3>

<p><span style="vertical-align: baseline;">Rather than requiring teams to write custom API wrappers, MCP tools give agents a standard way to query the cloud backend and get exact answers without parsing verbose policy documents in the prompt, maximizing token efficiency. <p><span style="vertical-align: baseline;">Because operations like hierarchy traversal, group expansion, and policy evaluation happen on dedicated IAM endpoints (spanning IAM v1 allow roles, IAM v2 deny, Policy Troubleshooter, and Policy Analyzer), skills run quickly and accurately with minimal token usage. Teams can also use these atomic MCP tools directly when writing their own custom Agent Skills, making it straightforward to combine Google Cloud's IAM capabilities with internal ticketing systems, custom compliance checks, and existing deployment pipelines.</span></p>

### Unifying enterprise context and semantics: LookML in Knowledge Catalog is now GA

- **Link**: [https://cloud.google.com/blog/products/business-intelligence/lookml-metadata-indexing-in-knowledge-catalog-is-now-ga/](https://cloud.google.com/blog/products/business-intelligence/lookml-metadata-indexing-in-knowledge-catalog-is-now-ga/)
- **Published**: 2026-10-27 01:00:00
- **Fetched**: 2026-10-27 01:30:29

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph"><p>As enterprises go from experimental AI agent prototypes to using them in production, data teams are realizing that <i>access</i> to data is not the same as <i>understanding</i> that data. To help bridge that gap, today, we are announcing the general availability (GA) of LookML semantic language indexing in Knowledge Catalog for <a href="https://cloud.google.com/looker">Looker Core on Google Cloud</a>.</p><p>To answer a complex business question accurately, an AI agent needs context — table schemas, data lineage, governance policies, business definitions, etc.. However, context is not a monolith; knowing where data lives is very different from knowing how to calculate metrics with it. In the enterprise, teams often conflate broad organizational context (usually in the form of metadata from structured and unstructured documents) with deterministic business semantics (the exact SQL formulas, join paths, and filtering rules that define metrics like net revenue or churn), assuming that a single data catalog or a business intelligence (BI) tool handling both enterprise-wide asset discovery and precise metric calculation.</p><p>In reality, no one tool can carry the entire load for agentic AI, as enterprise agents require both organizational context and deterministic business semantics. In Google Cloud environments, those are provided by Knowledge Catalog and LookML:</p><ul><li><b>Broad enterprise context with Knowledge Catalog:</b> Agents need a unified context graph that aggregates metadata across structured tables and unstructured documents. Through Knowledge Catalog, agents discover assets, inspect data quality, trace end-to-end lineage, respect column-level privacy tags, and surface corporate policy documents. The context graph tells an agent what data exists, how it is governed, and how it is connected.</li><li><b>Deterministic mathematical semantics with LookML:</b> What a catalog does not author on its own is how the numbers are computed. Describing a table is not the same as defining how tables join or how metrics are calculated. Looker's modeling language, LookML, encodes production-tested semantic logic — multi-grain join protections, conditional filters, and exact KPI formulas — so agents don't guess SQL math at runtime.</li></ul><p>With this native integration, the LookML business logic that powers your trusted BI reporting is automatically indexed into Knowledge Catalog — giving Gemini Enterprise and custom AI agents both enterprise-wide discovery and deterministic BI semantics.</p><h3><b>Why a context graph needs deterministic semantics</b></h3><p>When an LLM agent connects directly to raw database tables — even when armed with basic table descriptions or a business glossary — it still has to infer mathematical relationships on the fly. Without explicit semantic rules, agents routinely fall into two traps:</p><ol><li><b>Metric definition drift:</b> Standard text-to-SQL agents can invent conflicting formulas for foundational KPIs like net revenue or customer acquisition cost, failing to apply domain-specific accounting rules (such as recognizing revenue only when <i>order_status = 'Complete'</i> or prorating annual contracts across active service days).</li><li><b>Naive join fan-outs:</b> Complex schemas often contain one-to-many (1:N) and zero-to-many (0:N) relationships across invoices, line items, and refunds. Without pre-modeled join relationships and symmetric aggregation rules, agent-generated SQL can multiply rows and inflate financial totals.</li></ol><p>Knowledge Catalog and Looker solve this together, enabling you to model once in LookML and access those semantics everywhere across Google Cloud's AI ecosystem. Knowledge Catalog enforces semantic math when that logic is defined in a semantic modeling tool; LookML provides a mature, production-proven language for defining those exact mathematical relationships.</p><h3><b>What's new: LookML in Knowledge Catalog</b></h3><p>Previously, catalog integrations only captured shallow, file-level pointers and basic dashboard inventories. With this release, LookML's deterministic semantics become a first-class layer in the Knowledge Catalog context graph. An agent that finds a metric in the graph now also finds its exact definition, its join path, and its lineage back to source tables — in the same place, under the same governance. Synchronization is always on by default with no action required from end users, and with live sync, any update pushed to production LookML is reflected in Knowledge Catalog in near-real-time so agents operate on the freshest business logic.</p><p>Because this metadata is indexed directly into Knowledge Catalog by default, it is <a href="https://docs.cloud.google.com/gemini/enterprise/docs/connectors/connect-knowledge-catalog#configure-knowledge-catalog">immediately available to Gemini Enterprise</a>, without custom agent code or separate catalog data stores. When connected to Knowledge Catalog, Gemini Enterprise uses built-in read-only skills and hybrid search to look up technical schemas, business glossaries, and indexed LookML logic in a single step, passing that rich context directly to your federated BigQuery connector to generate accurate SQL. (For developers building custom agents, the same context bundles are also accessible via the LookupContext API.)</p><p>Knowledge Catalog now captures and links the following entity levels across Looker Core on Google Cloud:</p><ul><li><b>LookML models (looker-model):</b> Captures descriptive metadata, database connection routing, include hierarchies, data validation tests (assert), and parent-child EntryLinks mapping models to their associated Explores, Views, and LookML dashboards.</li><li><b>LookML Explores (looker-explore):</b> Indexes full relational join logic (type, sql_on, relationship cardinality such as many_to_one fan-out protection, foreign_key, required_joins, and sql_where) as Schema-Join relationships. It also captures mandatory filter guardrails (always_filter, access_filter), inherited dimensions and measures, and predefined <b>starter queries</b> that help agents and analysts overcome the cold-start problem.</li><li><b>LookML Views and fields (looker-view):</b> Extracts column-level compiled LookML SQL expressions (for example, ${total_revenue} / NULLIF(${count}, 0)), primary keys, dimension group timeframes, field synonyms, and derived table transformation logic (including SQL and native derived tables, partition keys, and cluster keys).</li><li><b>Dashboards, Looks, and tiles (looker-dashboard, looker-dashboard-element, looker-look):</b> Catalogs both UI-created and LookML-defined dashboards and visualization tiles, complete with dashboard filters, chart types, ownership, and usage statistics. Users in Knowledge Catalog are able to see table- and column-level lineage from underlying BigQuery tables all the way to individual dashboard tiles, allowing data engineers to evaluate schema changes proactively, before disruptions occur.</li></ul></div>

### Easy to integrate, compliant by design: Bringing the Swiss Franc to Google Cloud Universal Ledger

- **Link**: [https://cloud.google.com/blog/topics/financial-services/easy-to-integrate-compliant-by-design-bringing-the-swiss-franc-to-google-cloud-universal-ledger/](https://cloud.google.com/blog/topics/financial-services/easy-to-integrate-compliant-by-design-bringing-the-swiss-franc-to-google-cloud-universal-ledger/)
- **Published**: 2026-10-27 05:00:00
- **Fetched**: 2026-10-27 06:22:00

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph"><p>Every day, countless financial transactions are interrupted by slow, expensive, and inflexible conventional payment systems. As a result, public commercial stablecoins like Tether, USDC, and PayPal USD have become increasingly popular by making it easy to move money efficiently with instant, 24/7 blockchain settlement.</p><p>Yet major regulated banks have largely kept such transactions at arm’s length; for these financial institutions, reserve-backed public stablecoins present numerous risks, including strict capital and liquidity requirements and unmanageable regulatory and operational uncertainty.</p><p>Indeed, banks don't want to adopt existing stablecoins. Instead, they need the speed and efficiency of tokenized currency built on the trusted economic foundations they’ve nurtured over years or even decades in business. That’s why many are now turning to <a href="https://cloud.google.com/application/web3/universal-ledger">Google Cloud Universal Ledger</a> (GCUL). Rather than channeling public stablecoins, GCUL provides the secure infrastructure banks need to issue and settle tokenized deposits. That brings real-time, 24/7 programmable payments into commercial bank money while satisfying regulators and without disrupting core banking operations.</p><p>For many banks, this is a compelling vision, but adopting new payment technology and integrating it with core banking systems can seem to bank CTOs like a daunting undertaking. <div class="block-paragraph"><p>As a result, many banks are trying to figure out how to offer their customers the benefits of stablecoins — high speed, low cost, 24/7 availability, and programmability — without introducing problems often associated with existing reserve-backed stablecoins, such as regulatory issues, poor throughput performance, negative influence on bank reserves, and potentially no yield participation.</p><h3><b>Solution proposal</b></h3><p>Realizing this vision means modernized payments architectures must seamlessly and instantly enable individuals and institutions to transfer bank-held assets to accounts at any target bank. Orchestrating this shared ecosystem requires central entities to establish the governing rulebook, enforce issuance limits, and manage network-wide settlement parameters. During its pilot, Crypto Finance assumed this role, which within GCUL is known as the “currency operator.”</p><p>In this position, Crypto Finance can configure the network for either instant or deferred settlement. This choice is analogous to traditional banking: instant settlement acts like real-time gross settlement, where transactions settle individually and immediately and require high liquid reserves. In contrast, deferred settlement operates like netting, where payments are accumulated and offset and only periodically settle the net difference. For the pilot, Crypto Finance chose to adopt deferred settlement, in which GCUL manifests capital efficiency. In this way, clients enjoy instant transfers while banks conserve liquidity through periodic settlement.</p><h3><b>Concept validation</b></h3><p>To demonstrate instant, bi-directional account-to-account transfers on GCUL, Crypto Finance orchestrated a pilot with two digital token issuers, a Swiss digital asset bank, and a Swiss B2B transaction bank. Crypto Finance established the rulebook for interactions between the participant banks, such as interbank settlement, integration with traditional SIC payment rails, and AML/compliance protocols. Although some backend steps still needed manual intervention, Crypto Finance’s pilot proved that fully automated, cross-institution integration is feasible and established a generalized architecture that can scale to virtually any asset class.</p></div>

GCUL addresses these needs through redundancy between geographically distributed nodes operating on an enterprise-grade consensus model, ensuring reliability.
