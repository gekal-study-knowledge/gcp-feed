<summary>詳細を表示</summary>
<div class="block-paragraph"><p>Whether you are iterating on a quick bug fix or planning a complex migration, different tasks call for different models.</p><p>In keeping with Google Cloud's commitment to an open ecosystem and to give developers the right model for every job, <b>Claude Opus 5.5 and Claude Sonnet 5.5 are now available in Google Antigravity for Google Cloud customers.</b> Claude Opus 5.5 is built for complex work while Claude Sonnet 5.5 is a faster, lower-cost complement.</p><p>Once enabled by an administrator, developers can select Claude Opus 5.5 and Sonnet 5.5 directly from the model picker. Administrators can also select Google’s Gemini models, including Gemini 3.8 Flash and Gemini 4 Argon. The models apply across Antigravity 2.0, Antigravity CLI and our recently released <a href="https://antigravity.google/docs/ide/extensions/" target="_blank">Antigravity IDE extensions</a> for VS Code, JetBrains IntelliJ, and Visual Studio. This lets you choose the right model for the job, under a unified enterprise billing and security boundary.</p><p>In this post, we’ll share two engineering patterns for building in Antigravity using these models. To view the entire list of models supported in Antigravity across subscriptions, see our documentation <a href="https://antigravity.google/docs/models/" target="_blank">here</a>.</p><h3>Multi-model engineering patterns in Antigravity</h3><p>Having multiple model families available inside the same agent harness unlocks practical multi-model workflows that improve code quality while controlling latency and cost.</p><h3><b>Pattern 1: Cross-model verification ("LLM-as-a-Judge") in loop and graph workflows</b></h3><p>When building agentic loops or multi-step graph workflows, using the same model to both write code and review its own output can reinforce model-specific blind spots. Pairing two distinct model families, one as the implementer and another as the validator (judge), provides independent verification before moving to the next stage of a workflow.</p><p>In Antigravity, you can run this pattern either interactively or via automated subagents:</p><ol><li><b>Plan and implement with Model A:</b> Start in planning mode using <code>Claude Opus 5.5</code> or <code>Gemini 4 Argon</code> to design and implement a multi-file change.</li><li><b>Validate with Model B:</b> Before committing or advancing the loop, switch models, or invoke a one-shot <code>/model</code> check in the CLI, to have a different model family critique the implementation against your test suite and requirements.</li></ol><h3><b>Pattern 2: Pairing reasoning models with Flash subagents</b></h3><p>Complex engineering tasks often combine a few high-reasoning decisions with dozens of high-volume, mechanical lookups (searching files, grepping logs, checking lint output, or classifying test failures). Running every lookup on a frontier model can increase both latency and spend.</p><p>Antigravity's Subagent customization system (<code>.agents/agents/*.md</code>) lets you assign specific model tiers (<code>inherit</code>, <code>flash</code>, or <code>pro</code>) to specialized subagents. When your primary session is running a more powerful model.</p><p>Subagents configured with <code>model: inherit</code> use your active session model for deep reasoning subtasks.</p><p>Subagents configured with <code>model: flash</code> offload high-speed search, classification, and triage work to Gemini Flash models.</p><p>For example, you can define a fast log-triage subagent in <code>.agents/agents/test-triager.md</code>:</p></div>

Wiz used a mix of models to identify and help remediate these vulnerabilities. </span></p>
<p><span style="vertical-align: baseline;">Notably, Gemini 4 Argon made an invaluable contribution to finding the vulnerability, exploit development, attack detection, and validation of the patch.</span></p>
<p><span style="vertical-align: baseline;">While Google Cloud itself is not vulnerable, users of PHP running on Google Cloud may be vulnerable</span><span style="vertical-align: baseline;">. </span><span style="vertical-align: baseline;">At Google Cloud, we understand the severity of these vulnerabilities, and are sharing guidance to help our customers take immediate action to secure their applications.</span></p>
<h3><strong style="vertical-align: baseline;">Vulnerability background</strong></h3>
<p><span style="vertical-align: baseline;">PHP is a widely-used, server-side scripting language that powers many websites, content management systems, and web applications. On Oct. 21, 2026, CVE.org assigned the vulnerabilities as CVE-2026-109618 and CVE-2026-109619. </span></p>
<p><span style="vertical-align: baseline;">The official Common Vulnerability Scoring System (CVSS) base severity score for each of the PHP flaws has been determined as Critical, a severity of 9.2. Generally, this ranking means that threat actors can crash and hijack the affected system, and can easily steal, alter, and wipe its data — although mitigating circumstances can make it harder to exploit the flaw.</span></p></div>
<div class="block-paragraph_advanced"><ul>
<li style="vertical-align: baseline;">
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">CVE-2026-109618</strong><span style="vertical-align: baseline;">: Out-of-memory handling can interrupt PHP while internal request data is only partially initialized. Request cleanup may then treat the invalid data as valid.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">CVE-2026-109619</strong><span style="vertical-align: baseline;">: Request-owned internal state can survive after its backing memory has been freed. A later request handled by the same worker may use that stale state before normal initialization resets it.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Vulnerable versions</strong><span style="vertical-align: baseline;">: All versions of PHP from 5.4 through 8.5.11</span></p>

<li style="vertical-align: baseline;">

<p><span style="vertical-align: baseline;">また、サイバー ガードレールなしの Argon を、信頼できる一部の防御者に提供しています。これにより、サイバーセキュリティ機能の全範囲をテストできます。信頼できる防御者は、</span><a href="https://deepmind.google/fairwind-program/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Fairwind プログラム</span></a><span style="vertical-align: baseline;">を通じて審査されます。このプログラムは、政府機関、重要インフラ、サイバーセキュリティ パートナーに、高度なモデルへの独占的かつ無制限のアクセスを提供する、対象者限定の取り組みです。</span></p>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 10 月 14 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/topics/developers-practitioners/one-agent-development-kit-five-languages?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">エージェントといえば Python というイメージがありますが、実際は必ずしもそうではありません。現在の先進的なエコシステムでは、エージェントは</span><a href="https://cloud.google.com/run"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Cloud Run</span></a><span style="vertical-align: baseline;"> 上で Go マイクロサービスとして大規模に同時実行されることもあれば、</span><a href="https://github.com/google/adk-js/blob/main/core/src/models/chrome_prompt_llm.ts" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">ブラウザタブ内で動作</span></a><span style="vertical-align: baseline;">して Chrome のオンデバイス モデルを呼び出すこともあります。しかし、エージェント フレームワークの多くは Python のみのスタックを想定しています。そのため、エージェント ワークロードのためだけに Python サービスをスピンアップしたり、エージェント オーケストレーション ロジックを独自の言語でゼロから構築したりすることが必要になります。</span></p>
<p><span style="vertical-align: baseline;">Google の</span><a href="https://adk.dev/" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Agent Development Kit（ADK）</span></a><span style="vertical-align: baseline;">は、</span><a href="https://github.com/google/adk-python" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Python</span></a><span style="vertical-align: baseline;">、</span><a href="https://github.com/google/adk-go" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Go</span></a><span style="vertical-align: baseline;">、</span><a href="https://github.com/google/adk-js" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">TypeScript</span></a><span style="vertical-align: baseline;">、</span><a href="https://github.com/google/adk-java" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Java</span></a><span style="vertical-align: baseline;">、</span><a href="https://github.com/google/adk-kotlin" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Kotlin</span></a><span style="vertical-align: baseline;"> をサポートしているため、このようなトレードオフは発生しません。ADK の各バージョンはそれぞれの言語のランタイムと型システムに合わせてゼロから構築されており、かつ、オープン プロトコルによる相互運用性を備えた統合アーキテクチャを共有しています。</span></p>
<h4><strong style="vertical-align: baseline;">共通の基盤</strong></h4>
<p><span style="vertical-align: baseline;">5 つの言語すべてが同じオープン プロトコルをサポートしているため、使用する言語によってアーキテクチャが固定されることはありません。すべての言語の ADK に</span><a href="https://modelcontextprotocol.io/" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Model Context Protocol</span></a><span style="vertical-align: baseline;"> クライアントが含まれており、MCP サーバーとして公開されたカスタムツールを、どの言語からでもすぐに呼び出すことができます。</span></p>
<p><span style="vertical-align: baseline;">マルチエージェント システムの場合、ADK は</span><a href="https://github.com/a2aproject/A2A" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Agent2Agent（A2A）</span></a><span style="vertical-align: baseline;">プロトコルをサポートしているため、エージェントは HTTP 経由でリモート エージェントと通信できます。エージェントが異なる言語やフレームワークで記述されていても、A2A を通じて相互運用することができます。</span></p>
