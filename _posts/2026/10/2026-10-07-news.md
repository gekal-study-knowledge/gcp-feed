### Managed Apache Iceberg at scale: How Spanner powers Lakehouse runtime catalog

- **Link**: [https://cloud.google.com/blog/products/data-analytics/lakehouse-runtime-catalog-powered-by-spanner/](https://cloud.google.com/blog/products/data-analytics/lakehouse-runtime-catalog-powered-by-spanner/)

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">As customers modernize to lakehouse architectures, they are standardizing on open formats such as Apache Iceberg to create a shared data estate across compatible engines. This enables you to build AI-native lakehouses that turn data to semantic knowledge, enable proactive action, and operate at an agentic scale.</span></p>
<p><span style="vertical-align: baseline;">One of the key components of a lakehouse is the catalog, and in the Apache Iceberg environment, that usually means the Iceberg REST Catalog. An Apache Iceberg catalog is responsible for maintaining table pointers, handling atomic commits, and serving as the single source of truth for table locations. But as large enterprise organizations modernize to lakehouses, they have begun to realize that they need a highly scalable and available managed catalog as a part of their lakehouse architecture. This becomes even more important as querying scales with agents. To support a large amount of repeated small queries from agents, you will need to build on top of a managed catalog that provides atomicity, consistency, availability and concurrency at massive scale. </span></p>
<p><span style="vertical-align: baseline;">In this blog, we explore the challenges a managed catalog faces in modern cloud environments at agent scale, and show you how Google Cloud’s serverless </span><a href="https://cloud.google.com/blog/products/data-analytics/biglake-metastore-now-supports-iceberg-rest-catalog?e=a"><span style="text-decoration: underline; vertical-align: baseline;">Lakehouse runtime catalog</span></a><span style="vertical-align: baseline;"> can help address them. Powered by </span><a href="https://cloud.google.com/spanner"><span style="text-decoration: underline; vertical-align: baseline;">Spanner</span></a><span style="vertical-align: baseline;">, Google Cloud’s always-on database with virtually unlimited scale, and built to meet the open Apache Iceberg REST catalog specification, the Lakehouse runtime catalog is the highly scalable and available foundation you need for the agentic era.</span></p>
<h3><strong style="vertical-align: baseline;">Challenges a managed catalog needs to solve in the Lakehouse</strong></h3>
<p><span style="vertical-align: baseline;">When speaking with data engineers and infrastructure leads running production analytics at scale in a Lakehouse, the following core pain points consistently emerge and need to be solved by a managed catalog: </span></p>
<p><strong style="vertical-align: baseline;">Atomic commits and concurrency control:</strong><span style="vertical-align: baseline;"> Iceberg guarantees ACID transactions via optimistic concurrency control (OCC). A managed catalog must implement a bulletproof atomic compare-and-swap (CAS) operation to swap the current metadata pointer.</span></p>
<p><strong style="vertical-align: baseline;">High availability and operational maintenance:</strong><span style="vertical-align: baseline;"> Because queries fail immediately if the catalog is down, a managed catalog becomes a critical Tier-1 service.</span></p>
<p><strong style="vertical-align: baseline;">Scaling the database backing the catalog:</strong><span style="vertical-align: baseline;"> Catalog architects typically face a difficult trade-off when choosing a backing database for table metadata and state. Traditional scale-up relational databases provide SQL and ACID transactions, but hit vertical CPU, memory, storage and connection limits under heavy concurrent read/write loads unless manually sharded which incurs a huge operational overhead; while scale-out database systems are either eventually consistent, hard to manage, not enterprise-ready, or all of the above. </span></p>
<p><strong style="vertical-align: baseline;">Table maintenance coordination:</strong><span style="vertical-align: baseline;"> A catalog alone does not optimize data; you must build and operate ancillary pipelines for compaction, snapshot expiration, manifest rewriting, and orphan file cleanup.</span></p>
<p><strong style="vertical-align: baseline;">Governance and security:</strong><span style="vertical-align: baseline;"> A catalog acts as the security gatekeeper. The catalog must implement and maintain:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">Authentication protocols (e.g., OAuth2 token exchange, IAM federation)</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">Access control down to namespace and table levels</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">Vended storage credentials (e.g., generating short-lived tokens so query engines don't need broad, direct storage credentials)</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">Lakehouse runtime catalog</strong></h3>
<p><span style="vertical-align: baseline;">To solve these challenges, we built the Lakehouse runtime catalog (GA) with support for Iceberg Rest Catalog. The Lakehouse runtime catalog is a fully serverless, highly available, and unified metadata registry designed from the ground up to support modern open table formats like</span><strong style="vertical-align: baseline;"> </strong><span style="vertical-align: baseline;">Apache Iceberg. By natively implementing the Apache Iceberg REST Catalog specification</span><strong style="vertical-align: baseline;">,</strong><span style="vertical-align: baseline;"> the Lakehouse runtime catalog decouples metadata discovery from compute engines, helping ensure multiple Iceberg-compatible engines can access a shared data estate and enabling you to take your workloads to production sooner. We’ve helped many customers streamline the migration of their managed catalogs. For example, </span><a href="https://cloud.google.com/customers/etsy-lakehouse"><span style="text-decoration: underline; vertical-align: baseline;">Etsy</span></a><span style="vertical-align: baseline;"> migrated its catalog to Lakehouse runtime catalog, joining data in place to accelerate pipeline queries by 60%.</span></p></div>

<h3><strong style="vertical-align: baseline;">What powers the Lakehouse runtime catalog?</strong></h3>
<p><span style="vertical-align: baseline;">The Lakehouse runtime catalog is a highly available, concurrent and scalable catalog with strong consistency guarantees because it is built on top of </span><a href="https://cloud.google.com/spanner"><span style="text-decoration: underline; vertical-align: baseline;">Spanner</span></a><span style="vertical-align: baseline;">. Unlike traditional scale-up relational databases that hit vertical single-node ceilings, Spanner combines full relational SQL semantics and multi-table ACID transactions with the horizontal scale-out elasticity for both reads and writes of a NoSQL system. </span></p>
<p><span style="vertical-align: baseline;"><span style="vertical-align: baseline;">Spanner makes the Lakehouse runtime catalog highly available through Spanner’s </span><a href="https://docs.cloud.google.com/spanner/docs/instance-configurations#regional-configurations"><span style="text-decoration: underline; vertical-align: baseline;">regional configurations</span></a><span style="vertical-align: baseline;"> with up to 99.99% availability. Spanner also delivers out-of-the-box scalability for  Lakehouse runtime catalog: As a horizontally scalable database, Spanner does not require manual sharding and scales compute and storage independently and transparently. Spanner dynamically monitors data volume and query load, splitting and redistributing data ranges across nodes. Compute nodes scale dynamically based on CPU utilization and storage thresholds. Spanner automatically detects split-level overload and moves heavy splits away from overloaded nodes. Spanner also lets Lakehouse runtime catalog users eliminate the </span><a href="https://dl.acm.org/doi/abs/10.1145/2491245?__cf_chl_tk=oi5rkZKtX5q2CR93K9mrIHsAp_oqRxwaGqqpqq99v9Y-1790923307-1.0.1.1-pNUQvRr4OBosWiOcfxGuTWTD8I3JW_8V0i5xLuCsErU" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">traditional trade-offs</span></a><span style="vertical-align: baseline;"> between relational consistency and distributed scalability, delivering Lakehouse runtime catalog’s industry-leading </span><a href="https://docs.cloud.google.com/spanner/docs/true-time-external-consistency"><span style="text-decoration: underline; vertical-align: baseline;">consistency guarantees</span></a><span style="vertical-align: baseline;">. Lakehouse transactions are serializable — the order of transactions within the database is the same as the order in which clients observe the transactions to have been committed. </span><span style="vertical-align: baseline;">This foundation allows Lakehouse users to operate at agent-scale. </span> </span></p>
<p><span style="vertical-align: baseline;">Then, to further power agentic use cases, the Lakehouse runtime catalog integrates directly with Knowledge Catalog to easily discover lakehouse Iceberg tables and provide trusted context to agents. Knowledge Catalog leverages an efficient combination of </span><a href="https://docs.cloud.google.com/spanner/docs/full-text-search"><span style="text-decoration: underline; vertical-align: baseline;">full-text search</span></a><span style="vertical-align: baseline;"> and native</span><a href="https://docs.cloud.google.com/spanner/docs/vector-search-overview"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">vector search</span></a><span style="vertical-align: baseline;"> provided by Spanner; this approach enables better recall for search retrieval, pairing lexical keyword searches with semantic embeddings in a single query. Because both index types are built on the identical base dataset, they update with strict, transactional ACID consistency alongside base table DML operations. This removes operational overhead such as managing sync pipelines, and external-vector and full-text search systems. In short, the Lakehouse runtime catalog provides faster time-to-market for your agentic use cases.</span></p>

<div class="block-paragraph_advanced"><p style="text-align: center; font-size: 0.8rem;"><em><span style="vertical-align: baseline;">Co-authors:</span></em><br /><em><span style="vertical-align: baseline;"><strong>Stenal Jolly</strong>, Strategic Cloud Engineer, Google</span></em><br /><em><span style="vertical-align: baseline;"><strong>Anubhav Dhawan</strong>, Software Engineer, Google</span></em></p>
<p><span style="vertical-align: baseline;">Following the </span><a href="https://medium.com/google-cloud/mcp-toolbox-v1-0-the-open-source-framework-for-secure-agentic-data-access-3c2199546ba8" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">landmark announcement</span></a><span style="vertical-align: baseline;"> of MCP Toolbox v1.0, we're thrilled to announce that the <a href="https://github.com/googleapis/mcp-toolbox-sdk-java" rel="noopener" target="_blank">MCP Toolbox Java SDK</a> has officially reached version 1.0.</span></p>
<p><span style="vertical-align: baseline;">This release brings first-class, type-safe agent orchestration to one of the world's most widely adopted enterprise ecosystems. Java's mature architecture is purpose-built for rigorous demands, providing the high concurrency, strict transactional integrity, and robust state management required to safely scale mission-critical AI agents in production.</span></p>
<p><span style="vertical-align: baseline;">In this post, we'll tell you about what's new in Java SDK v1.0, show you a real-world example, and help you get started with your own implementation.</span></p>
<h2><span style="vertical-align: baseline;">MCP: The universal interface</span></h2>
<p><span style="vertical-align: baseline;">Today, developers face a compounding integration bottleneck: if you have <em>N</em> different AI models and <em>M</em> enterprise data sources, you must build, secure, and maintain <em>N × M</em> bespoke, custom connections. This lack of a unified integration layer forces engineering teams to rely on a fragmented web of ad-hoc pipelines. As a result, scaling an agentic architecture quickly becomes unsustainable, exposing sensitive enterprise databases to severe security vulnerabilities, fragmented access controls, and massive maintenance overhead.</span></p>
<p><span style="vertical-align: baseline;">Eliminating the fragmented web of custom integrations is the core problem solved by the Model Context Protocol (MCP). Acting as a universal interface—the "USB Type-C" for AI orchestration—MCP decouples models from data sources. Instead of writing custom or managed API integration code for every new model or database, developers write to a single, standardized protocol. This approach allows any MCP-compliant agent to securely and immediately interact with any MCP-enabled system. The MCP connection lets developers connect agents to real-world systems without building bespoke integrations for every new model.</span></p>
<h2><span style="vertical-align: baseline;">What's new in Java SDK v1.0: Built for production workloads</span></h2>
<p><span style="vertical-align: baseline;">When we announced the </span><a href="https://medium.com/google-cloud/announcing-the-mcp-toolbox-java-sdk-2ed3171bbaa0" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">public Beta</span></a><span style="vertical-align: baseline;"> for the MCP Toolbox Java SDK, our goal was to bring first-class, type-safe agent orchestration to enterprise Java environments. Since then, we've collaborated with developers and open-source contributors to harden our APIs.</span></p>
<p><span style="vertical-align: baseline;">The v1.0 release marks a stable, backwards-compatible foundation suitable for enterprise workloads. Here's what's new and hardened since our v0.2 release:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Transport layer abstraction &amp; </strong><code><strong style="vertical-align: baseline;">HttpMcpTransport</strong></code><span style="vertical-align: baseline;">: We introduced a clean transport layer abstraction alongside </span><code style="vertical-align: baseline;">HttpMcpTransport</code><span style="vertical-align: baseline;">. This feature decouples the core protocol logic from underlying HTTP clients, making it easy to swap network implementations or customize connection pooling.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Decoupled client authentication</strong><span style="vertical-align: baseline;">: To simplify enterprise security compliance, client authentication is now decoupled using </span><code style="vertical-align: baseline;">CredentialsProvider</code><span style="vertical-align: baseline;"> and </span><code style="vertical-align: baseline;">AuthMethods</code> classes<span style="vertical-align: baseline;">. Credentials are resolved asynchronously on every request, so teams can refresh tokens dynamically or plug in their own token source (Google OIDC via ADC ships in the box, anything else is a one-method interface).</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Default parameter support</strong><span style="vertical-align: baseline;">: Native support for default values in tool parameters, reducing prompt payload sizes and enhancing agent reliability.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Pruning bound parameters</strong><span style="vertical-align: baseline;">: Sensitive parameters that are bound server-side (like </span><code style="vertical-align: baseline;">tenant_id</code><span style="vertical-align: baseline;">) are now automatically stripped from exposed tool definitions so the LLM can't manipulate them.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Version selection &amp; session tracking</strong><span style="vertical-align: baseline;">: Standardized MCP version selection and robust session tracking ensure consistent protocol negotiation and conversation-state lifecycles.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">HTTP credential exposure warnings</strong><span style="vertical-align: baseline;">: Added built-in detection that warns you at runtime when credentials are about to travel over a plaintext HTTP connection.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Generic client headers map</strong><span style="vertical-align: baseline;">: Easily attach custom corporate proxy headers, transaction tracing IDs, or correlation metadata to all outgoing requests.</span></p>
</li>
</ul>

<div class="block-paragraph_advanced"><h2><span style="vertical-align: baseline;">Real-world example: The autonomous transit concierge</span></h2>
<p><span style="vertical-align: baseline;">To demonstrate the power of the Java SDK combined with AlloyDB, let's look at an enterprise use case.</span></p>
<p><span style="vertical-align: baseline;">Meet</span><strong style="vertical-align: baseline;"> Cymbal Transit</strong><span style="vertical-align: baseline;">, a fictitious intercity bus network. <p><span style="font-style: italic; vertical-align: baseline;">"I need to get from New York to Boston tomorrow morning. Can I bring my Golden Retriever? If so, book me the fastest trip."</span></p>

<h3><span style="vertical-align: baseline;">Stateful agent architecture in Spring Boot</span></h3>
<p><span style="vertical-align: baseline;">The hardest part of building conversational AI in enterprise applications is managing state: when a user asks, "What times are available?" and follows up with, "Book the 8 AM one," the agent must remember prior context across turns.</span></p>
<p><span style="vertical-align: baseline;">Using the Java MCP Toolbox SDK with Spring Boot and LangChain4j, we can cleanly maintain conversational memory in the HTTP Session and we can cleanly separate the agent into two declarative components:</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">A declarative agent interface that manages the prompt, tools, and conversational memory via an HTTP session.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">A tool execution service that routes agent requests directly to the MCP Toolbox server.</span></p>
</li>
</ol></div>

<p><span style="vertical-align: baseline;">By pairing the MCP Toolbox Java SDK with LangChain4j, we achieve clean separation of concerns and effortless state management:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Zero-boilerplate session management</strong><span style="vertical-align: baseline;">: The </span><code style="vertical-align: baseline;">@MemoryId String sessionId</code><span style="vertical-align: baseline;"> parameter binds conversation history directly to the user's HTTP session.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Declarative agent contract</strong><span style="vertical-align: baseline;">: The </span><code style="vertical-align: baseline;">TransitAgent</code><span style="vertical-align: baseline;"> interface defines the model's persona and system instructions without complex prompt templating.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Type-safe tool execution</strong><span style="vertical-align: baseline;">: The </span><code style="vertical-align: baseline;">TransitAgentTools</code><span style="vertical-align: baseline;"> Spring service wraps remote MCP database tools as native Java methods.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">This architecture ensures your agent remains modular: you can refine prompt guidance in the interface, manage user sessions automatically, and execute secure database queries through MCP Toolbox without tight coupling.</span></p>
