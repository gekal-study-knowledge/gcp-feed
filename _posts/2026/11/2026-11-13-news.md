<h2 class="release-note-product-title">Looker</h2>
<h3>Announcement</h3>
<p>Beginning November 9, 2026, the following features will be automatically enabled for Looker (original) and Looker (Google Cloud core) instances running Looker 26.22.</p>
<h3>Feature</h3>
<p>Looker (original) now supports <a href="https://docs.cloud.google.com/looker/docs/admin-panel-authentication-google#mirroring">Google Group mirroring</a>, which lets administrators automatically assign Looker roles and groups that are based on Google Groups membership. The updated <strong>Google Authentication</strong> admin page also adds <a href="https://docs.cloud.google.com/looker/docs/admin-panel-authentication-google#advanced_role_management">advanced role management</a> and <a href="https://docs.cloud.google.com/looker/docs/admin-panel-authentication-google#configuring_google_authentication_using_the_api">programmatic configuration through the Looker API</a>.</p>
<h3>Change</h3>
<p>We will begin billing for usage of Gemini-assisted features that exceeds their instance token allocation. Gemini-assisted features are a set of agentic capabilities that include Conversational Analytics and other generally available features that use Gemini.</p>
<p>Looker admins can prepare for the billing of this usage by associating their Looker instance with a Google Cloud project that has a valid billing account. You can specify a Google Cloud project on your instance's <a href="https://docs.cloud.google.com/looker/docs/admin-panel-platform-gil#designate-billing-project"><strong>Gemini in Looker</strong> admin page</a>.</p>
<h3>Feature</h3>
<p>Looker visualizations now support grouping rows or pivot columns that are outside of row or column limits into a consolidated "Other" category. When you use <a href="https://docs.cloud.google.com/looker/docs/table-options#limit_displayed_rows">Limit Displayed Rows</a> or <a href="https://docs.cloud.google.com/looker/docs/table-options#limit_displayed_pivot_columns">Limit Displayed Pivot Columns</a>, select <strong>Group remaining rows into 'Other'</strong> or <strong>Group remaining pivots into 'Other'</strong> to display the top N rows or pivot columns alongside an aggregated "Other" category. You can also customize the category label and, for some chart types, choose a custom color.</p>
<p>Row grouping is supported on table, bar, column, line, area, scatterplot, pie, and donut multiples visualizations. Pivot grouping is supported on table, bar, column, line, area, and scatterplot visualizations.</p>
<h3>Feature</h3>
<p>When you <a href="https://docs.cloud.google.com/looker/docs/downloading#filter_and_query_metadata">download Looks, Explores, or dashboard tiles</a>, you can include filter and query information in the downloaded file. PNG images can include a filter banner, and Excel workbooks can include query metadata and filter sheets. Dashboard editors can set the default Excel metadata option for tile downloads in the <a href="https://docs.cloud.google.com/looker/docs/editing-user-defined-dashboards#download-add-query-metadata-sheet">dashboard settings</a>. When you download a <a href="https://docs.cloud.google.com/looker/docs/tabbed-dashboards#download-pdf">tabbed dashboard as a PDF</a>, you can choose whether all dashboard filters appear at the top of the PDF or each tab's active filters appear under that tab's header.</p>
<h3>Feature</h3>
<p>Looker administrators can now opt in to the <a href="https://docs.cloud.google.com/looker/docs/db-config-google-bigquery#official-jdbc-driver">official Google BigQuery JDBC driver</a> (<a href="https://cloud.google.com/products#product-launch-stages">Preview</a>) on <a href="https://docs.cloud.google.com/looker/docs/db-config-google-bigquery">BigQuery connections</a>. The new driver is built and supported by Google and will replace the current Looker legacy driver in a future release.</p>
<p>To try the driver, perform the following steps:</p>
<ol>
<li>Open the <a href="https://docs.cloud.google.com/looker/docs/admin-panel-database-connections"><strong>Connections</strong></a> admin page by selecting <strong>Admin &gt; Database &gt; Connections</strong>.</li>
<li>Click the <strong>Edit</strong> button for a BigQuery connection. (See <a href="https://docs.cloud.google.com/looker/docs/admin-panel-database-connections#editing-connections">Editing connections</a> for more information.)</li>
<li>Turn off the <a href="https://docs.cloud.google.com/looker/docs/db-config-google-bigquery#stable_driver"><strong>Use latest stable driver</strong></a> toggle on the connection.</li>
<li>From the <a href="https://docs.cloud.google.com/looker/docs/connecting-to-your-db#driver-version"><strong>Driver Version</strong></a> drop-down menu, choose one of the <strong>BigQuery Official [Preview]</strong> driver options.</li>
<li>Select <strong>Test</strong> to <a href="https://docs.cloud.google.com/looker/docs/db-config-google-bigquery#testing_the_connection">check the connection</a>, and then select <strong>Update Connection</strong>.</li>
</ol>
<p>Note the following details:</p>
<ul>
<li>Existing connections continue to use the current driver unless an administrator opts in.</li>
<li>You can switch back at any time by choosing the previous <a href="https://docs.cloud.google.com/looker/docs/connecting-to-your-db#driver-version">driver version</a>.</li>
</ul>
<p>If you encounter an issue during the Preview of Looker support of the official BigQuery driver, report it to <a href="mailto:cloud-looker-dialects@google.com">cloud-looker-dialects@google.com</a>.</p>
<h3>Change</h3>
<p>When you <a href="https://docs.cloud.google.com/looker/docs/downloading#downloading_a_dashboard_as_a_pdf">download a dashboard as a PDF</a> or <a href="https://docs.cloud.google.com/looker/docs/scheduling-and-sending-dashboards#expand_tables_to_show_all_rows">set up a PDF dashboard delivery</a>, selecting <strong>Expand tables to show all rows</strong> makes the <strong>Fit Page to Dashboard</strong> option unavailable and sets <strong>Paper Size</strong> to <strong>A4</strong>, with page breaks enabled by default.</p>
<h3>Feature</h3>
<p>The Sankey chart type is now generally available. Sankey charts visualize the flow and distribution of data between categories, stages, or states. Sankey charts are especially useful for analyzing multi-step pathways, such as customer journeys, website navigation flows, or resource allocations across different systems. Learn more about using <a href="https://docs.cloud.google.com/looker/docs/sankey-options">Sankey charts</a> in Looker.</p>

<p>Two-factor authentication (2FA) is now enabled by default for all new and existing Looker (original) instances that use email and password authentication and that didn't opt out during the advance opt-out window. Administrators retain full control to manage or disable 2FA by using the <a href="https://docs.cloud.google.com/looker/docs/admin-panel-authentication-two-factor"><strong>Admin &gt; Authentication &gt; Two-Factor</strong> panel</a>.</p>
<h2 class="release-note-product-title">Managed Service for Apache Airflow</h2>
<h3>Breaking</h3>
<p><em>(Airflow 3.3.1, 3.2.2, and 2.11.1)</em> Upgraded the <code>pip</code> package from version
23.2.1 to version 26.2.2. This update is available in Managed Airflow (Gen 3)
builds <code>composer-3-airflow-3.3.1-build.8</code>,
<code>composer-3-airflow-3.2.2-build.12</code>, and <code>composer-3-airflow-2.11.1-build.25</code>
and later, and in the Managed Airflow (Gen 2) image
<code>composer-2.18.0-airflow-2.11.1</code> and later.</p>
<p>This version includes security fixes and changes how custom PyPI packages are
installed:</p>
<ul>
<li><strong>PEP 440 version specifiers</strong>: <code>pip</code> 26.2.2 enforces
<a href="https://peps.python.org/pep-0440/#version-specifiers">PEP 440</a> compliance
and supports the <code>.*</code> wildcard only with <code>==</code> and <code>!=</code>. For example, use
<code>gcsfs&gt;=0.8</code> instead of <code>gcsfs&gt;=0.8.*</code>.</li>
<li><strong>Isolated source builds</strong>: source packages (<code>.tar.gz</code>) are always built in
an isolated environment. If you install source packages from a private
repository that is your only package index, make sure that the repository
contains precompiled wheel packages (<code>.whl</code>) for <code>setuptools</code> and any other
build dependencies (listed under <code>[build-system] requires</code> in
<code>pyproject.toml</code>). Alternatively, publish your packages as <code>.whl</code> packages.
As a temporary workaround to disable build isolation, add
<code>no-build-isolation = false</code> to the <code>[global]</code> section of your <code>pip.conf</code>
file. This workaround works only if the build dependencies are already
installed in your environment.</li>
<li><strong>Legacy <code>pkg_resources</code> builds</strong>: older source packages that rely on
<code>pkg_resources</code> might fail to build. Use newer package versions with
precompiled <code>.whl</code> packages, or for your own private packages, build them
as <code>.whl</code> packages or update their build scripts so that they don't use the
legacy <code>pkg_resources</code> module.</li>
</ul>
<p>Make sure that your custom PyPI packages are compatible with these changes
before you upgrade your environment. If the installation of PyPI packages fails
during an upgrade, your environment keeps running with its current version and
packages.</p>

<p><span style="vertical-align: baseline;">データベースは、AI 対応ソフトウェアの開発スピードに追いつくのに苦戦してきました。私たちが話を聞いたエンジニアリング チームやプラットフォーム チームでは、データベース プロビジョニングの遅延によりコーディング エージェントの作業が停滞し、複雑さにより CI / CD テスト パイプラインがボトルネックとなり、サンドボックスから本番環境への移行時に社内アプリが行き詰まる状況が見られています。これまで、エージェント対応機能と妥協のないエンタープライズ セキュリティおよびスケールを兼ね備えた PostgreSQL サービスは市場に存在しませんでした。</span></p>
<p><span style="vertical-align: baseline;">この問題を解決するため、Google は、デベロッパーや AI コーディング エージェント向けに特別に設計された</span><a href="https://cloud.google.com/products/alloydb"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">AlloyDB for PostgreSQL</span></a><span style="vertical-align: baseline;"> の新サービス、</span><strong style="vertical-align: baseline;">AlloyDB Express</strong><span style="vertical-align: baseline;"> のプレビュー版の提供を開始したことをお知らせいたします。数秒で起動し、アイドル状態になると自動的に一時停止するため、AI を活用した迅速な開発と堅牢なエンタープライズ インフラストラクチャのギャップを埋めることができます。その結果、アプリケーション構築を加速させ、本番環境規模に簡単に拡張できる、安全性が高く費用対効果に優れたデータベース環境が実現します。無料枠から始めて、使用量に応じた料金のみお支払いください。</span></p>
<p><span style="vertical-align: baseline;">エージェント対応データベースである AlloyDB Express は、以下のような特長を備えています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">2 秒未満でデータベースを作成:</strong><span style="vertical-align: baseline;"> </span><code style="vertical-align: baseline;">gcloud</code><span style="vertical-align: baseline;"> CLI、REST API、MCP、Terraform、コンソールを使用して、すぐに使える PostgreSQL データベースを 2 秒未満で作成できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">ゼロへのスケーリング:</strong><span style="vertical-align: baseline;"> データベースは 15 分間非アクティブな状態が続くと自動的に一時停止するため、アイドル状態の間のコンピューティング費用は発生しません。新しいクエリが到着すると、数秒で自動的に起動します。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">AI とセキュリティを組み込んだエンタープライズ仕様:</strong><span style="vertical-align: baseline;"> ベクトル検索、テキスト検索、ハイブリッド検索などのエンタープライズ AI 機能を活用して、AI アプリケーションを迅速に構築できます。これらはすべて、組み込みのエンタープライズ セキュリティ ガードレールで保護されています。</span></p>

</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">ワンクリックで本番環境規模にアップグレード:</strong><span style="vertical-align: baseline;"> アプリを本番環境に移行する準備が整ったら、既存のデータベースをワンクリックで AlloyDB にアップグレードできます。これにより、データ、スキーマ、ユーザー、接続文字列をそのまま維持しながら、エンタープライズ向けの高可用性（HA）、リードレプリカ、障害復旧（DR）を実現できます。</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">セキュリティを犠牲にすることなく開発を加速</strong></h3>
<p><span style="vertical-align: baseline;">AlloyDB Express は、セルフサービスの迅速さと組み込みのエンタープライズ セキュリティを兼ね備えています。アプリビルダーやコーディング エージェントは、手動で設定することなく完全に分離された PostgreSQL データベースを即座にプロビジョニングできるため、すべてのテストやプロトタイプを専用のデータベースで実行できるようになります。また、プラットフォーム管理者やセキュリティ管理者は、IAM、ネットワーク、組織のポリシーを一元的に一度定義するだけで、デベロッパーやコーディング エージェントが作成したすべての AlloyDB Express データベースが、自動的に会社のセキュリティ ガードレール内に収まるようになります。</span></p>
<p><span style="vertical-align: baseline;">コードを記述したのがデベロッパーか AI エージェントかを問わず、以下のような組み込みの保護メカニズムによってセキュリティが確保されます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">安全なデフォルト接続で公開範囲を最小限に抑える:</strong><span style="vertical-align: baseline;"> IP アドレスをマスクし、明示的に許可されるまで受信トラフィックをブロックするパブリック DNS エンドポイントを使用して、データをパブリック インターネットから隠します。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">プライベート VPC ネットワーキングによる安全な内部統合:</strong><span style="vertical-align: baseline;"> Private Service Connect（PSC）またはプライベート DNS を使用して、内部ワークロードを安全に接続します。</span></p>

<p><strong style="vertical-align: baseline;">きめ細かなアクセス制御で最小権限を適用:</strong><span style="vertical-align: baseline;"> Google Cloud IAM、VPC Service Controls、ネイティブの PostgreSQL ロールを活用して、エージェントとユーザーの権限を確実に制限します。</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">AI 機能が組み込まれている AlloyDB Express</strong></h3>

<p><strong style="vertical-align: baseline;">自然言語からの SQL 生成:</strong><span style="vertical-align: baseline;"> デベロッパーや AI エージェントが平易な英語で質問すると、組み込みの AlloyDB Studio と自然言語 API を活用して、数秒でクエリを生成、実行、改良できます。</span></p>

### Google の Agentic Data Cloud にエージェントを大規模に強化する新機能が登場

- **Link**: [https://cloud.google.com/blog/ja/products/databases/whats-new-across-googles-agentic-data-cloud/](https://cloud.google.com/blog/ja/products/databases/whats-new-across-googles-agentic-data-cloud/)
- **Published**: 2026-11-13 11:10:00
- **Fetched**: 2026-11-13 19:33:13

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 11 月 5 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/products/databases/whats-new-across-googles-agentic-data-cloud?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">エージェントの時代に突入したのはそう昔のことではありませんが、今や、組織は本番環境でエージェントを運用し、大きな価値を引き出すようになっています。新たな収益源を獲得する機会となるほか、効率の向上や、リスク管理まで、エージェントを活用した業務の再構築は、企業のリーダーにとって最優先事項となっています。</span></p>
<p><span style="vertical-align: baseline;">そこで Google は、</span><a href="https://cloud.google.com/data-cloud"><span style="text-decoration: underline; vertical-align: baseline;">Agentic Data Cloud</span></a><span style="vertical-align: baseline;"> を構築しました。これは、いわゆる System of Action（行動のシステム）であり、その設計思想として、ウォールド ガーデン（閉じられた環境）を取り払ってあらゆるデータを有効活用する、高精度と信頼性を実現する、低コストでプロアクティブに運用する、といったことを重視しています。</span><strong style="vertical-align: baseline;">PayPal、Siemens、Telus、Vodafone、Walmart</strong><span style="vertical-align: baseline;"> などの大手企業は、すでに Google とともにビジネス上の成果を上げています。</span></p>
<p><span style="vertical-align: baseline;">ここでは、Google の Agentic Data Cloud の主な最新情報をお知らせします。Google は、あらゆる場面でエージェントを強化するとともに、企業ごとのコンテキストに基づいてグラウンディングしながら正確で信頼できる回答を提供するなど、エージェント主体のエクスペリエンスを技術者とビジネス ユーザーの両方にとって優れたものにしています。</span></p>
<h4><strong style="vertical-align: baseline;">ボーダーレスな Lakehouse で、エージェントがあらゆるデータを有効活用</strong></h4>
<p><span style="vertical-align: baseline;">企業データは、マルチクラウド環境やオンプレミス システム、SaaS プラットフォーム（Confluent、SAP、Salesforce、Workday など）まで、あらゆる場所に存在します。オープンな Apache Iceberg 形式を基盤とする</span><a href="https://cloud.google.com/products/lakehouse"><span style="text-decoration: underline; vertical-align: baseline;">ボーダーレスな Lakehouse</span></a><span style="vertical-align: baseline;"> により、データの保存場所を問わず、あらゆるデータを活用することが可能となっており、エージェントは一元管理された基盤を利用できます。この基盤のもとでは、データを移動したり、コネクタを組み合わせたりする必要はなく、想定外の下り（外向き）料金が発生することもありません。インフラストラクチャからモデルまで、あらゆるレイヤで調整済みのスタックを利用できます。実際、Apache Iceberg で管理されているデータは、過去 1 年間で 3 倍以上に増加しています。</span></p>
<p><span style="vertical-align: baseline;">ここでは、ボーダーレスな Lakehouse に関連する新しい機能強化をいくつかご紹介します。</span><strong style="vertical-align: baseline;">Gemini が</strong><a href="https://cloud.google.com/blog/ja/products/data-analytics/borderless-lakehouse-integrates-with-gemini"><strong style="text-decoration: underline; vertical-align: baseline;">ボーダーレスな Lakehouse と直接連携</strong></a><span style="vertical-align: baseline;">できるようになりました。これにより、ビジネス ユーザーはクラウド全体に分散したレコードに対して、自然言語でクエリすることが可能となります。また、エージェントは推論をグラウンディングできるようになり、ビジネス ワークフローの促進につながります。さらに、</span><a href="https://docs.cloud.google.com/lakehouse/docs/about-cross-cloud-data-access"><strong style="text-decoration: underline; vertical-align: baseline;">AWS および Azure 向けの Cross-Cloud Interconnect とキャッシュ保存</strong></a><span style="vertical-align: baseline;">が一般提供となり、プライベートで安全な接続を通じて、下り（外向き）料金を追加で支払うことなく、クラウド間でデータをクエリできるようになりました。外部のクラウドデータに対してクエリを実行すると、Lakehouse は取得したデータブロックを Google Cloud 内に自動的にキャッシュ保存します。さらに、Databricks Unity、Snowflake Horizon、AWS Glue とのオープンな Iceberg カタログ連携や、SAP、Workday、Salesforce とのゼロコピー統合も利用できます。</span></p>
<p><span style="vertical-align: baseline;">AI にコンテキストを提供するため、</span><strong style="vertical-align: baseline;">ボーダーレスな Lakehouse は Knowledge Catalog と直接統合</strong><span style="vertical-align: baseline;">されています。Knowledge Catalog はクラウド ストレージ内の分散データや非構造化データに自動的にインデックスを付与し、エージェントが適切なコンテキストに基づき正確性を得られるようにします。また、トークン費用も抑えられ、インテリジェントで持続可能なエージェント戦略を実現できます。</span></p>
<p><span style="font-style: italic; vertical-align: baseline;">「Delivery Hero talabat はボーダーレスな Lakehouse において、Amazon S3 テーブルから Apache Iceberg 形式の単一の元データを BigQuery に連携させることで、データ移動の費用を約 40% 削減しました。また、本番環境のストリーミング トランザクション イベントに対して両方のクラウドから数分以内にクエリできます。」</span><strong style="vertical-align: baseline;">-</strong><span style="vertical-align: baseline;"> </span><strong style="vertical-align: baseline;">Delivery Hero talabat、スタッフ データ エンジニア、Harish Ramesh 氏</strong></p>
<p><span style="vertical-align: baseline;">エージェントがただちにアクションを実行するには、過去の分析データとリアルタイムのトランザクション データの両方に同時にアクセスする必要があります。そこで、</span><a href="https://cloud.google.com/products/alloydb"><strong style="text-decoration: underline; vertical-align: baseline;">AlloyDB</strong></a><strong style="vertical-align: baseline;"> とボーダーレスな Lakehouse の新たなインテグレーション</strong><span style="vertical-align: baseline;">についてお知らせいたします。</span><a href="https://cloud.google.com/blog/ja/products/databases/direct-iceberg-access-in-alloydb?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">AlloyDB から Iceberg に直接アクセス</span></a><span style="vertical-align: baseline;">することで、ETL パイプラインやコピーを使うことなく、Cloud Storage に保存されている Iceberg テーブルに直接クエリを実行できるようになり、単一の PostgreSQL クエリで本番環境の運用データと過去のレイクハウス データを結合することが可能となります。AlloyDB のトランザクション機能と Iceberg テーブルへの直接アクセスを組み合わせることで、トランザクション データと分析データを効率的に組み合わせて、エージェントからの厳しい要求に応えられるようになります。また、</span><a href="https://docs.cloud.google.com/lakehouse/docs/about-lakehouse-catalogs"><span style="text-decoration: underline; vertical-align: baseline;">Lakehouse ランタイム カタログ</span></a><span style="vertical-align: baseline;">と完全に統合されているため、AlloyDB に Iceberg テーブルを他のテーブルと同じように登録できます。これらのテーブルはすべて Knowledge Catalog に自動的に反映されるため、エージェントはガバナンスが適用された共通のコンテキストを取得できます。AlloyDB から Iceberg への直接アクセスは、集計クエリにおいて、Amazon の同等の PostgreSQL 互換サービスよりも最大 7 倍高速です。</span></p>
<p><span style="vertical-align: baseline;">このボーダレス戦略の完成度をさらに高めるのが、すでに一般提供となっている </span><a href="https://cloud.google.com/products/spanner/omni"><span style="text-decoration: underline; vertical-align: baseline;">Spanner Omni</span></a><span style="vertical-align: baseline;"> です。これにより、オンプレミス、エッジノード、マルチクラウド環境にまたがるハイブリッド エージェント アプリケーションに、Google グレードの整合性、スケール、マルチモデル機能がもたらされます。</span></p>
<h4><strong style="vertical-align: baseline;">個々のエージェントを企業のコンテキストにグラウンディングして、正確かつ信頼できる回答を提供</strong></h4>
<p><span style="vertical-align: baseline;">エージェントの精度は、グラウンディングの基盤となるビジネス コンテキストの質に左右されます。</span><a href="https://cloud.google.com/products/knowledge-catalog"><span style="text-decoration: underline; vertical-align: baseline;">Knowledge Catalog</span></a><span style="vertical-align: baseline;"> は、Google Cloud のユニバーサル コンテキスト エンジンであり、元データを共有ビジネス コンテキストに変換して、エージェントがより高い精度、信頼性、トークン効率で回答、行動できるようにします。このたび、Knowledge Catalog がさらに進化し、AI を活用したコンテキスト キュレーション機能が拡張されました。具体的には、</span><strong style="vertical-align: baseline;">自己学習機能、再利用可能なコンテキスト セット、刷新されたユーザー エクスペリエンス</strong><span style="vertical-align: baseline;">によって、コンテキスト レイヤがビジネスに応じて自動的に構築されて進化し続けるほか、人間がデータ ガバナンスを完全に制御できるようになっています。Google 社内のベンチマークによると、Knowledge Catalog の使用により、AI エージェントの精度が約 4 倍向上し、レイテンシは最大 33% 短縮、トークン使用量は最大 75% 削減しています。</span></p>
<p><span style="vertical-align: baseline;">企業の組織内で培われたノウハウの多くは、データベースの中ではなく、運用ハンドブックや、ドキュメント、チケットに記されています。そのため、エージェントのコンテキストは、人々が実際に尋ねる質問に寄せながらキュレートする必要があります。Knowledge Catalog の新しい</span><a href="https://cloud.google.com/blog/ja/products/data-analytics/knowledge-catalog-self-learning-context-enrichment-for-ai-agents"><strong style="text-decoration: underline; vertical-align: baseline;">自己学習型エンリッチメント</strong></a><span style="vertical-align: baseline;">（プレビュー版）では、コンテキスト キュレーションという重労働をエージェントが担います。具体的には、Knowledge Catalog が、Google Workspace、GitHub、Jira、Confluence、SharePoint などの非構造化ソースを継続的にマイニングし、ユーザー インテントや人間とエージェント間のあらゆるやり取りから学習して、コンテキストを補いながら自動的に進化させます。また、ローカルな知識を </span><a href="https://cloud.google.com/blog/ja/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing"><span style="text-decoration: underline; vertical-align: baseline;">Open Knowledge Format</span></a><span style="vertical-align: baseline;">（OKF）コンテキスト セットにパッケージ化して再利用できるようにすることで、コンテキスト エンジニアやデータ スチュワードが拡充されたコンテキストを簡単に管理できるようにしています。さらに、データ スチュワードとデータチーム向けに、</span><a href="https://docs.cloud.google.com/knowledge-catalog/docs/knowledge-studio"><strong style="text-decoration: underline; vertical-align: baseline;">Knowledge Catalog の新しい Studio エクスペリエンス</strong></a><span style="vertical-align: baseline;">（プレビュー版）も導入されました。会話型ユーザー インターフェースを通じて、自然言語でコンテキストを探索したり、クラウド環境および SaaS アプリケーションにまたがるデータ資産全体を可視化したり、提案されたコンテキスト拡充点をチェック、監査、承認したりできます（バージョニングとロールバック機能も完備されています）。</span></p></div>

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">さらに、</span><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/welcome-to-gemini-at-work-2026?e=48754805#:~:text=Knowledge%20Catalog%3A,ensure%20factual%20responses."><strong style="text-decoration: underline; vertical-align: baseline;">Knowledge Catalog が Gemini でデフォルトで有効</strong></a><span style="vertical-align: baseline;">になりました（現在プレビューとして公開中）。これにより、データに関するあらゆる質問が、適切に管理されたビジネス コンテキストに自動的にグラウンディングされるようになります。Knowledge Catalog は、BigQuery、AlloyDB、Cloud SQL、Spanner との接続を経て、ビジネス用語の解決、信頼できるテーブルの特定、結合パスの判断までを行い、各ユーザーのアクセス権も考慮しながら SQL を生成します。こうした仕組みにより、エージェントは登録済みの共有コンテキスト セットに基づいて精度を一貫して確保できるほか、レイテンシの短縮やトークン費用の削減にもつながり、組織は自信をもってエンタープライズ規模でエージェントをデプロイすることが可能となります。</span></p>
<p><span style="vertical-align: baseline;">なお、重要なビジネス定義については LLM の推量に任せることはできません。そこで役立つのが、Knowledge Catalog が</span><a href="https://cloud.google.com/blog/ja/products/data-analytics/expanded-semantic-model-support-in-knowledge-catalog"><span style="text-decoration: underline; vertical-align: baseline;">信頼できるセマンティック モデルにエージェントをグラウンディング</span></a><span style="vertical-align: baseline;">する機能であり、このたび一般提供となりました。グラウンディングのソースは BigQuery、Looker（LookML）、Databricks、Snowflake、dbt、SAP に対応しており、データの移動は発生しません。これにより、財務上の純収益から、業務上の顧客離脱率の計算まで、ビジネスチームが使用している適切に管理された数式と同じものを使用できます。さらに、Knowledge Catalog では、メタデータの検出およびフェデレーションを Oracle AI Database@Google Cloud、Snowflake、Databricks Unity Catalog や、サードパーティのカタログ（Atlan、Collibra など）にも拡張できます。これにより、既存のカタログを活用しながら、データ資産全体を普遍的に理解することがあらゆるエージェントで可能となります。</span></p>
<h4><strong style="vertical-align: baseline;">実務担当者のエージェント エクスペリエンスを変革</strong></h4>
<p><span style="vertical-align: baseline;">Google は、データ専門家やビジネスチームの働き方をまったく新しいものへと変革します。具体的には、個々の従業員は、アシスタントという相棒のサポートを受けながら働く実務担当者から、自律型エージェントのオーケストレーターへと進化し、これらのエージェントが意図に基づきビジネスの成果を促進していく、という形になります。</span></p>
<p><span style="vertical-align: baseline;">先日の </span><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/welcome-to-gemini-at-work-2026"><span style="text-decoration: underline; vertical-align: baseline;">Gemini at Work</span></a><span style="vertical-align: baseline;"> イベントでは、技術チームと一般的なビジネス ユーザーのそれぞれに向けた Gemini の 2 つの新機能を紹介しました。データ エンジニアや ML エンジニア向けには、Gemini の ML スキルやツールが拡張されており、エージェント群がこれらを使ってあらゆるデータ サイエンティストやデータ エンジニアを支えます。エンジニアが求める結果を平易な言葉で説明すると、Gemini が PySpark コードの生成はもとより、それを編集してテストするためのノートブックの提供、モデルのトレーニング、パイプラインの問題のトラブルシューティングおよび修正までを行います。一方、ビジネス ユーザーは誰でも、質問するだけで信頼性の高いリアルタイムの業務レポートを生成できます。Gemini の業務レポート生成スキルが BigQuery および Knowledge Catalog と統合され、クエリを構築して保存するところまでを行います。クエリをいったん保存すれば、オンデマンドでレポートを実行し、トークン費用を生じさせることなく、毎回検証を経た一貫性のある回答を確実に得られるようになります。</span></p>
<p><span style="vertical-align: baseline;">さらに、これまでどおり独自ツールを使い続けたいデベロッパーのために、</span><a href="https://cloud.google.com/blog/ja/products/data-analytics/data-agent-kit-brings-data-skills-and-tools-to-your-ide-or-cli?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">Data Agent Kit</span></a><span style="vertical-align: baseline;"> の一般提供が近ごろ発表されました。Google データクラウド ツールを、デベロッパーが自分の好きな IDE や CLI（VS Code、Claude Code、Antigravity など）に直接統合できるため、コンソールを切り替えたり、お決まりの ETL 処理を記述したりする必要がなくなります。具体的には、ネイティブの MCP ツールが完備されており、ビジネス インテントを定義するだけで、エージェントにデータ パイプラインの生成、調整、テストを任せられます。</span></p>
<h4><strong style="vertical-align: baseline;">エージェントの規模に対応するデータ インフラストラクチャの構築</strong></h4>
<p><span style="vertical-align: baseline;">ワークフロー内で連携するエージェント数が数百万単位へと規模が拡大すると、従来のデータベース アーキテクチャでは破綻に陥ります。Google は、このようなエージェントの規模に対応できるよう、特別に設計、カスタマイズされたインフラストラクチャの導入に取り組んでいます。</span></p>
<p><span style="vertical-align: baseline;">迅速なテストとプロトタイピングを促進するため、このたび </span><a href="https://cloud.google.com/blog/ja/products/databases/introducing-alloydb-express-for-rapid-testing-and-prototyping"><strong style="text-decoration: underline; vertical-align: baseline;">AlloyDB Express</strong></a><span style="vertical-align: baseline;"> のプレビュー版をリリースいたします。これは、開発速度を極限まで高めたいビルダーやコーディング エージェント向けに設計された、AlloyDB の新しいエディションです。このエディションは、2 秒未満の即時プロビジョニングをはじめ、ゼロへのスケーリング（一時停止）と再開、安全なプライベート IP 接続、オブザーバビリティの統合、小さなフットプリント（1～2 個の vCPU と 20 GB のストレージ）という特徴があります。この AlloyDB は、主にデベロッパーに対して、エージェントの開発およびテストのための PostgreSQL 環境を提供します。</span></p>
<p><span style="vertical-align: baseline;">一方、本番環境向けに、</span><a href="https://cloud.google.com/blog/ja/products/databases/announcing-postgresql-for-agents-in-alloydb?e=48754805&amp;hl=ja"><strong style="text-decoration: underline; vertical-align: baseline;">AlloyDB のエージェント向け PostgreSQL</strong></a><strong style="vertical-align: baseline;">（プレビュー版）</strong><span style="vertical-align: baseline;">を最近発表しました。これを使えば、ワークロードを完全に分離した状態で、連携動作する数千の AI エージェントが本番環境のトランザクション データにクエリすることが可能となります。この</span><a href="https://cloud.google.com/blog/ja/products/databases/alloydbs-agentic-database-architecture"><span style="text-decoration: underline; vertical-align: baseline;">エージェント対応のデータベース アーキテクチャ</span></a><span style="vertical-align: baseline;">では、ミリ秒未満の I/O およびテラビット/秒の合計スキャン スループットが実現され、エージェントが 1 秒あたりに処理可能なクエリ数が 300 万以上に達します。コンピューティング リソースは、アクティブな推論セッションに基づいて自動的にスケールされ、アイドル状態になると本番環境システムに影響を与えることなくゼロにスケールダウンされます。</span></p>
<p><span style="vertical-align: baseline;">オープンソースのデータ インフラストラクチャ実行環境に関しては、</span><a href="https://cloud.google.com/products/managed-service-for-apache-spark"><span style="text-decoration: underline; vertical-align: baseline;">Managed Service for Apache Spark</span></a><span style="vertical-align: baseline;"> が Lightning Engine のさらなる改善により、市場の同等サービスと比較してコスト パフォーマンスが 3 倍以上になっています。</span><a href="https://spark.apache.org/releases/spark-release-4-0-0.html" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Spark 4.0</span></a><span style="vertical-align: baseline;"> に対して最近行った機能強化により、起動が高速化されており（追加費用なし）、インタラクティブなワークロードや小規模なバッチ ETL ジョブにおいて効果を発揮します。さらに、</span><a href="https://docs.cloud.google.com/managed-spark/docs/tiers"><span style="text-decoration: underline; vertical-align: baseline;">プレミアム ティア</span></a><span style="vertical-align: baseline;">では、アップグレードされたハードウェアと Lightning Engine のソフトウェア アクセラレーションの組み合わせによりパフォーマンスが向上しており、これはデフォルトで有効になっています。</span></p>
<p><span style="vertical-align: baseline;">さらに、エージェントのスケールに対応できるよう、</span><a href="https://cloud.google.com/bigquery"><span style="text-decoration: underline; vertical-align: baseline;">BigQuery</span></a><span style="vertical-align: baseline;"> の強化にも継続的に取り組んでいます。この過去 1 年間だけに限っても、流動的なスケーリングおよび組み込みのワークロード アクセラレーションなどのインテリジェントな最適化により、クエリ処理のコストを 50% 以上削減し、40% 以上高速化しました。また、</span><a href="https://docs.cloud.google.com/bigquery/docs/graph-overview"><strong style="text-decoration: underline; vertical-align: baseline;">BigQuery Graph</strong></a><span style="vertical-align: baseline;"> の一般提供が始まり、ペタバイト規模のグラフ分析をリレーショナル テーブルで直接、ETL なしで実行できるようになりました。BigQuery Graph でデータをノードおよびエッジとしてモデル化できるため、データを別のグラフ データベースに移動することなく、複雑で隠れた関係を明らかにすることが可能となります。さらにこのたび、Google Research が提供する 2 つの新しいモデルを BigQuery でネイティブに実行できるようになりました。1 つ目は、現在プレビュー版の </span><a href="https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">TimesFM 3.0</span></a><span style="vertical-align: baseline;"> であり、カスタムモデルをトレーニング、管理しなくても、SQL で直接予測を生成できます。2 つ目は、同じくプレビュー版の </span><a href="https://research.google/blog/introducing-tabfm-a-zero-shot-foundation-model-for-tabular-data/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">TabFM</span></a><span style="vertical-align: baseline;"> であり、BigQuery に予測 ML を直接組み込めます。</span></p>

<h3><strong style="vertical-align: baseline;">エージェントの時代における安全な構築</strong></h3>
<p><span style="vertical-align: baseline;">エージェント コーディング ツールはソフトウェア デリバリーを劇的に加速させましたが、マシンスピードで行われる commit や未検証の依存関係に、人間によるレビューが追いつかなくなっています。自律型エージェントがサプライ チェーンの一部となった今、無条件に信用してしまうと、攻撃者にとっての直接的なバックドアになり得ます。</span></p>
<p><span style="vertical-align: baseline;">開発ライフサイクルを保護する Google のアプローチでは、統合開発環境（IDE）にネイティブなリアルタイムのガードレールを構築し、コードと Identity and Access Management（IAM）全体でアセットグラフを一元化し、モデルを検証してコードが統合される前にロジックの欠陥を排除します。</span></p>
<h3><strong style="vertical-align: baseline;">CodeMender: エンタープライズ管理を備えた最先端のサイバーセキュリティ</strong></h3>
<p><span style="vertical-align: baseline;">ソフトウェアに起因する脅威が拡大し続けるなか、Google の自律型コード セキュリティ エージェント </span><a href="https://cloud.google.com/blog/ja/products/identity-security/find-and-fix-software-vulnerabilities-with-codemender?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">CodeMender</span></a><span style="vertical-align: baseline;"> は、組織がコードの脆弱性をマシンスピードで検出して修正できるよう支援します。手動によるトリアージのボトルネックを解消しながら、ソフトウェア開発ライフサイクルにセキュリティを深く組み込むことができます。</span></p>
<p><span style="vertical-align: baseline;">CodeMender は、</span><a href="https://cloud.google.com/blog/ja/products/ai-machine-learning/gemini-4-argon-available-on-google-cloud?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">Gemini 4 Argon</span></a><span style="vertical-align: baseline;"> を含む複数のモデルと連携して、最先端のサイバーセキュリティ機能を提供します。これらの機能には、これまで未知だった脆弱性を特定し、悪用される前にテスト済みのパッチを生成する機能が含まれます。</span></p>
<p><span style="vertical-align: baseline;">直近では、Wiz は Gemini 4 Argon と他のモデルを組み合わせて、</span><a href="https://www.wiz.io/blog/php2shell-php-rce" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">ウェブサイトの 70% に影響を及ぼした PHP コアの脆弱性</span></a><span style="vertical-align: baseline;">を特定し、修復を支援しました。Gemini 4 Argon は、脆弱性の発見、想定される攻撃パスの特定、攻撃の検出、パッチの検証において、特筆すべき貢献を果たしました。</span></p>
<p><span style="vertical-align: baseline;">現在プレビュー版の CodeMender は、安全な分離と柔軟なスキャンを実現する以下の新機能を提供します。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">安全かつ自律的な修復</strong><span style="vertical-align: baseline;">: CodeMender は、脆弱性の検証とエクスプロイトのシミュレーションを、選択したオペレーティング システムレベルのサンドボックスまたは隔離された仮想マシン内で行います。また、ローカルでの書き込みとコマンド実行に人間参加型のチェックを追加することで、悪意のあるエクスプロイトやゼロデイ テストが思わぬ事態を引き起こすリスクを軽減します。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">柔軟なスキャンモード</strong><span style="vertical-align: baseline;">: CodeMender では、特定のフォルダ、リポジトリ全体、または前回のスキャン以降に変更されたファイルのみをスキャンできるようになりました。これにより、スキャンするファイルの数を細かく制御して、スキャン速度と費用を最適化できます。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">7 月に CodeMender のプレビュー版がリリースされて以来、数百社におよぶお客様が CodeMender を活用し、マシンスピードで脆弱性の検出および修正を行っています。</span></p>
<p><span style="vertical-align: baseline;">「攻撃者がマシンスピードで攻撃を仕掛けてくる中、Google の Fairwind Program は、当社のアプリケーション セキュリティで遅れをとらない対応を維持するのに役立っています。CodeMender の初期評価では、専門家による検証と修復で人の目による管理を維持しながら、脆弱性発見までの時間を 95% 以上短縮できる可能性が示されています」と、Thales Group のサイバーセキュリティ サービス担当 CTO である Ivan Fontarensky 氏は述べています。</span></p>
<p><span style="vertical-align: baseline;">「IDC の調査によると、企業の 40% 近くで、脆弱性の修復が新たな脆弱性の発生ペースに追いついていません。修復を伴わない検出は、開発者の作業負担を増やすだけにすぎません」と、IDC のクラウド セキュリティ担当リサーチ ディレクターである Katie Norton 氏は述べています。「CodeMender は、悪用可能性の検証とデプロイ可能なコード修正を組み合わせることでこれを解決します。悪用されるまでの時間が短縮するなかで不可欠となる、検証済みパッチの継続的な適用を促進するからです。」</span></p>
<h3><strong style="vertical-align: baseline;">あらゆる場所でワークロードを保護</strong></h3>
<p><span style="vertical-align: baseline;">自律型ワークロードが本番環境に移行すると、脅威の状況は一変します。攻撃者は、認証情報、データ境界、エージェントと企業を接続する統合環境といった、システムの接続基盤を標的とするからです。侵入した攻撃者は、過剰な権限を持つ認証情報とセグメント化されていない環境を悪用して、企業のデータ境界を越えて横展開します。</span></p>
<p><span style="vertical-align: baseline;">このようなフラット トラスト アーキテクチャを排除するために、Google Cloud は、エージェントが実行されるあらゆる場所で、基本的なセキュリティとガバナンス制御の統合フレームワークを提供します。エージェントが Gemini プラットフォーム、Google Kubernetes Engine（GKE）、Cloud Run、新しい </span><a href="https://cloud.google.com/blog/ja/topics/ai-infrastructure/introducing-agent-compute-engine-and-expanded-agent-governance?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">Agent Compute Engine</span></a><span style="vertical-align: baseline;"> で動作しているか、マルチクラウド環境間で連携しているかにかかわらず、同じ厳格なエンタープライズ統制が適用されます。</span></p>
<p><span style="vertical-align: baseline;">トランザクション レベルで「あらゆる場所でのエージェント」フレームワークを適用するために、以下の重要な ID、ネットワーク、コンテンツの制御機能を導入します。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Auth Manager（Agent Identity）</strong><span style="vertical-align: baseline;">: IAM のガバナンスのもと、Google マネージド Vault 内で認証情報を一元管理します。一般提供が開始された</span><a href="https://docs.cloud.google.com/iam/docs/auth-manager-overview"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Auth Manager</span></a><span style="vertical-align: baseline;"> は、OAuth 2.0 / PKCE フローを自動化し、ユーザー委任トークンを更新することで、同意疲れを最小限に抑え、認証情報の盗難リスクを低減します。Auth Manager とともに、</span><a href="https://docs.cloud.google.com/iam/docs/agent-identity-overview"><span style="text-decoration: underline; vertical-align: baseline;">Agent Identity</span></a><a href="https://docs.cloud.google.com/iam/docs/auth-agent-own-identity-external"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">JWT サポート</span></a><span style="vertical-align: baseline;">（プレビュー版）が標準の OIDC トークンを発行します。これにより、エージェントは有効期間の長い静的な API キーを使用せずに、AWS、Azure、オンプレミスのバックエンド、MCP サーバー間で安全に認証できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">ID ベースの VPC Service Controls</strong><span style="vertical-align: baseline;">: データの引き出しに対する境界防御を強化するため、</span><a href="https://cloud.google.com/blog/ja/products/identity-security/introducing-new-scalable-perimeter-options-with-vpc-service-controls?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">VPC-SC の上り（内向き）と下り（外向き）のルール</span></a><span style="vertical-align: baseline;">で IAM ロールがサポートされるようになりました（一般提供）。また、Workload Identity Federation for GKE（プレビュー版）により、セキュリティ チームは、複雑な手動の例外処理を行うことなく、エンタープライズ GKE クラスタ全体にきめ細かい ID ベースの境界を適用できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Model Armor のカスタム トピック検出機能</strong><span style="vertical-align: baseline;">: 現在プレビュー版で提供されているこの機能強化により、エージェントに指定のトピックを遵守させることができます。プロンプトベースのカスタムルールを定義して、トピックに沿ったインタラクションとトピックから外れたインタラクションを識別できます。この機能は医療、保険、小売業界のユースケースに合わせてカスタマイズされているため、エージェントの会話が脱線するのを防ぎ、コンプライアンスを確保した安全なコミュニケーションを維持します。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">高度なネットワーク脅威からの保護: </strong><a href="https://docs.cloud.google.com/firewall/docs/about-intrusion-prevention"><span style="text-decoration: underline; vertical-align: baseline;">Cloud NGFW Enterprise の IPS</span></a><span style="text-decoration: underline; vertical-align: baseline;"> </span><span style="vertical-align: baseline;">機能に基づいて、Palo Alto Networks WildFire を利用した新しい</span><a href="https://docs.cloud.google.com/chronicle/docs/soar/marketplace-integrations/wildfire"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Cloud NGFW の高度なマルウェア サンドボックス</span></a><span style="vertical-align: baseline;">（一般提供）でワークロードを保護できるようになりました。また、Cloud NGFW の</span><a href="https://docs.cloud.google.com/firewall/docs/about-firewall-endpoints#:~:text=the%20folder%20level.-,Project-level%20firewall%20endpoints,-:%20project%20administrators%20create"><span style="text-decoration: underline; vertical-align: baseline;">プロジェクト レベルのリソース</span></a><span style="vertical-align: baseline;">（一般提供）を使用してファイアウォールの運用を効率化し、</span><a href="https://docs.cloud.google.com/armor/docs/managed-rules-overview"><span style="text-decoration: underline; vertical-align: baseline;">Cloud Armor のマネージド ルール</span></a><span style="vertical-align: baseline;">（プレビュー版）で脆弱性攻撃からの保護を自動化できます。このルールは、毎月 1.5 兆件のウェブ リクエストをスキャンする Thales Imperva のグローバル脅威インテリジェンスを基盤としています。</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">マシンスピードでの防御</strong></h3>
<p><span style="vertical-align: baseline;">攻撃者は、運用ライフサイクル全体に高度な機能を統合し、これまでにない規模と速度で攻撃を仕掛けています。自律型マルチエージェントによる脅威に対抗するには、エージェント型かつインテリジェンス主導の運用によって防御側を強化し、数日ではなく数分で攻撃者を無力化できるようにする必要があります。</span></p>
<p><span style="vertical-align: baseline;">最新の SOC（セキュリティ オペレーション センター）には、地球規模のインフラストラクチャを基盤とした、以下のような自律的な調査、検出、対応機能が必要です。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">継続的な監視により、ワークロード レイヤにおいてリアルタイムで発生している侵害を検出し、テレメトリーを Wiz Security Graph に直接フィードする。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">防御モデルのランタイム ロジックに直接組み込まれた Google Threat Intelligence のテレメトリーにより、プロセスツリーを再構築して脅威をリアルタイムで隔離する自動エージェント型脅威ハンティングをトリガーする。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">自律型エージェントが、複雑なアラートを分析し、マルチベンダーのテレメトリー全体にわたる相関クエリを 1 秒未満で実行して、人間が戦略的な最終承認を行えるよう明確な対応策を提示する。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">もちろん、自律型テクノロジーを導入するだけでは不十分です。チームがそれを効果的に活用するには、適切な運用フレームワークも必要です。サイバー防御運用を発展させるため、</span><a href="https://cloud.google.com/resources/report/content/the-defenders-advantage-applying-agentic-systems"><strong style="text-decoration: underline; vertical-align: baseline;">Mandiant Transformation Services</strong></a><span style="vertical-align: baseline;"> のエキスパートが運用モデルをモダナイズし、これらの高度なテクノロジーのメリットを最大限に引き出します。Mandiant は、最前線のベスト プラクティスを活用してプロセスを改善し、人材のスキルを高めることで、組織が先手を打って脅威を低減し、侵害発生時でもビジネスの継続性を確保できるよう支援します。</span></p>
<h3><strong style="vertical-align: baseline;">連携による相乗効果: Wiz と Google</strong></h3>
<p><span style="vertical-align: baseline;">エンドツーエンドの防御を実現するには、これらのネイティブ プラットフォーム制御を、組織が多様なツールを運用しているマルチクラウド環境に拡張する必要があります。</span></p>
<p><span style="vertical-align: baseline;">Wiz と Google Cloud は、自律型アプリケーションに対する深い理解、連携されたセキュリティ コンテキスト、そして脅威インテリジェンスを組み合わせることで、組織が安全にイノベーションを推進し、新たな脅威に先手を打てるよう支援します。最近のハイライトは次のとおりです。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Wiz を使用して、構築と実行場所を問わず自律型ワークロードを保護: </strong><span style="vertical-align: baseline;">組織が Google Cloud と Gemini プラットフォームを使用して構築とスケーリングを行う際、Wiz はコードからランタイムまで、ライフサイクル全体にわたって自律型アプリケーションを保護します。Wiz は、自律型アプリケーション、エージェント、インフラストラクチャを検出してマッピングし、目的、機能、権限を含めてアプリケーション自体を詳細に分析することで、隠れたリスクを明らかにします。Wiz Security Graph のコンテキストと組み合わせることで、複雑な攻撃パスやランタイムの脅威を明らかにし、チームがリスクの優先順位付けを行い、自信を持ってイノベーションを推進できるように支援します。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Wiz AI SAST でマシンスピードのコード セキュリティを実現</strong><span style="vertical-align: baseline;">: プレビュー版として提供されている Wiz AI 静的アプリケーション セキュリティ テスト（SAST）は、エージェント推論を使用してアプリケーションの動作を理解し、複雑なビジネス ロジックの欠陥をあぶり出します。Wiz Research に基づき、独自の Atlas ハーネスによって強化された </span><a href="https://www.wiz.io/blog/introducing-wiz-ai-sast" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Wiz AI SAST</span></a><span style="vertical-align: baseline;"> は、コードの脆弱性を Wiz Security Graph のインフラストラクチャ コンテキストと関連付けることで、チームが最も重要なリスクに優先して対処できるようにします。これにより、悪用可能な攻撃パスは、Green Agent と CodeMender を使用して、マシンスピードで修復できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Wiz と Google Security Operations とともに強化する脅威防御</strong><span style="vertical-align: baseline;">:</span><a href="https://www.wiz.io/blog/wiz-defend-and-google-security-operations" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Wiz Defend と Google Security Operations</span></a><span style="vertical-align: baseline;"> が共有データモデルで連携するようになり、セキュリティ運用チームはどちらのプラットフォームでも柔軟に脅威を調査できるようになりました。改善点としては、Google Security Operations における専用 Wiz コンテンツ パックや Wiz Blue Agent 調査分析の導入、プラットフォーム間の双方向同期によるアナリスト エクスペリエンスの効率化などが挙げられます。さらに、Wiz Defend は Google Threat Intelligence と統合され、最新の分析情報と最前線のインテリジェンスを Wiz に直接取り込めるようになりました。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Scan for Good でリソース不足の組織を保護</strong><span style="vertical-align: baseline;">: Google DeepMind と Wiz が共同で立ち上げたイニシアチブである </span><a href="https://www.wiz.io/blog/scan-for-good-critical-ai-exposures" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Scan for Good</span></a><span style="vertical-align: baseline;"> は、自律型テクノロジーとセキュリティ研究者の知見を組み合わせた力を、公共サービス、重要インフラ、非営利団体などのリソース不足の組織に提供します。この取り組みの最初の 1 か月で、Argon を活用することで、50 を超える公共サービス組織と重要インフラ プロバイダが重大な脆弱性を発見し、修復できるよう支援しました。</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">構築側と防御者に優位性を取り戻す</strong></h3>
<p><span style="vertical-align: baseline;">自律型エージェントの時代にセキュリティを確保するには、運用モデルを進化させ、安全性を重視した設計のパイプラインを適用し、悪意のあるインフラストラクチャに対して直接的な対策を講じる必要があります。Google の責任は、以下のように、攻撃者の発生源でその活動を阻止することにまで及びます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">Google Cloud 環境を標的とする悪意のある攻撃者の追跡と、そのインフラストラクチャの恒久的な無効化。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">Google DeepMind との連携による、重大なリスクが伴うサイバーセキュリティや自動コード分析に特化したモデルを含む、専門的な防御アーキテクチャの構築。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">最前線の脅威インテリジェンスをモデルのアライメントと分類器のトレーニングにフィードバックし、新たな攻撃ベクトルが顕在化する前に無効化。</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">ネイティブなパイプライン防御を確立し、フラット トラスト アーキテクチャを解体し、マシンスピードの運用を展開することで、企業は AI の優位性を防御者に取り戻すことができます。</span></p>
