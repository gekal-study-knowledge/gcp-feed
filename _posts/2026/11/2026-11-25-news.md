<h2 class="release-note-product-title">BigQuery</h2>
<h3>Feature</h3>
<p>You can use <a href="https://docs.cloud.google.com/bigquery/docs/cross-cloud-connections">cross-cloud connections</a> to
query data in AWS, Azure, and Salesforce Data 360 from all BigQuery regions with
more feature availability than standard connections that use BigQuery Omni. This
feature is
<a href="https://cloud.google.com/products#product-launch-stages">generally available</a>
(GA).</p>
<h3>Deprecated</h3>
<p>The BigQuery Storage API v1beta1 is deprecated and will be shut down on August 31, 2027.</p>
<p>Key milestone dates:</p>
<ul>
<li><strong>Nov 20, 2026:</strong> Access to the BigQuery Storage API v1beta1 is restricted to projects that recorded active usage between March 1, 2026, and August 31, 2026.</li>
<li><strong>August 31, 2027:</strong> The BigQuery Storage API v1beta1 will be fully shut down. After this date, calls to the v1beta1 endpoint will fail with a <code>NOT_FOUND</code> error.</li>
</ul>
<p><strong>What you need to do:</strong></p>
<p>To prevent service disruption, migrate your workloads from <code>v1beta1</code> to the generally available <a href="https://docs.cloud.google.com/bigquery/docs/reference/storage/rpc/google.cloud.bigquery.storage.v1">BigQuery Storage API v1</a>. The <code>v1</code> API is backward-compatible with <code>v1beta1</code>.</p>
<ul>
<li><strong>SDKs and connectors:</strong> If you use connectors or client libraries, update them to the latest versions to ensure they default to the <code>v1</code> API:
<ul>
<li><a href="https://docs.cloud.google.com/bigquery/docs/reference/odbc-jdbc-drivers">Simba ODBC/JDBC for BigQuery</a></li>
<li><a href="https://docs.cloud.google.com/bigquery/docs/odbc-for-bigquery">Google BigQuery ODBC</a> / <a href="https://docs.cloud.google.com/bigquery/docs/jdbc-for-bigquery">JDBC driver</a></li>
<li><a href="https://trino.io/docs/current/connector/bigquery.html">Trino BigQuery plugin</a></li>
<li><a href="https://beam.apache.org/documentation/io/built-in/google-bigquery/">Apache Beam BigQuery connector</a></li>
<li><a href="https://github.com/GoogleCloudDataproc/spark-bigquery-connector">Spark BigQuery connector</a></li>
<li><a href="https://spotify.github.io/scio/io/BigQuery.html">Scio BigQuery plugin</a></li>
</ul></li>
<li><strong>Custom code:</strong> If your applications call the <code>v1beta1</code> API directly (for example, using gRPC), update your code to target the <code>v1</code> API endpoint (<code>google.cloud.bigquery.storage.v1</code>).</li>
</ul>
<p>For more information, see the <a href="https://docs.cloud.google.com/bigquery/docs/reference/storage">BigQuery Storage API reference</a>.</p>
<p>If you are using <code>v1beta1</code> and have concerns with this deprecation schedule, please contact us via a support case.</p>
</details>

<div class="block-paragraph"><p>With a workforce that lives in the browser across a SaaS and multi-cloud estate, securing our digital environment is paramount. Our 5,000+ users include faculty, operations, engineering, contractors, and a large Bring Your Own Device (BYOD) population.</p><p>Operating at this scale, our top priority is protecting student personally identifiable information (PII) flowing through web applications. Under India's Digital Personal Data Protection Act (DPDPA), protecting this data is critical to regulatory compliance and maintaining brand trust. We needed security within the browser.</p><p><b>The challenge of a fragmented browser estate</b></p><p>We previously operated a mixed-browser environment, but managing multiple browsers made consistent policy enforcement and visibility challenging. We explored several options to standardize; however, our team didn’t want users to have to learn a new tool, and many of the options had high overhead costs.</p><p><b>Testing and rolling out Chrome Enterprise Premium</b></p><p>We implemented a phased <a href="https://chromeenterprise.google/products/chrome-enterprise-premium/" target="_blank">Chrome Enterprise Premium</a> pilot over a few weeks. Our team first validated the management capabilities in the <a href="https://www.youtube.com/watch?v=NG4R__k1HN8&amp;t=3s" target="_blank">Google Admin console</a> by testing policy, deployment, extension controls, and reporting. Once we felt confident that Chrome Enterprise Premium provided our desired level of visibility, we rolled it out to several hundred users across various environments, including BYOD, Windows, and macOS. We deployed Safe Browsing and URL filtering for immediate threat protection, DLP rules to restrict copy/paste, downloads, and uploads on sensitive SaaS apps, and context-aware access to restrict application entry based on device posture.</p><p>The proof of concept succeeded across all criteria including consistent policy enforcement, measurable reduction in risky-site and risky-download events, minimal user friction, and a centralized dashboard to give our teams visibility into managed user activity.</p><p>The real decision moment came when we realized we could achieve a true Zero Trust posture. With Chrome Enterprise Premium as our backbone, access decisions now happen dynamically based on identity, device posture, and context. A teacher on a school-managed laptop enjoys seamless, full access. It delivers airtight data protection without disrupting daily instruction.</p><p><b>A simpler, stronger foundation</b></p><p>With Chrome Enterprise Premium, we replaced virtual desktops (VDIs) and fragmented security tools with built-in browser protection. Securing the browser itself means we no longer need to install heavy security software on every computer. This makes it easy to apply security policies to personal devices used by contractors and employees. Whether our team uses Windows, macOS, ChromeOS, iOS, or Android, we manage updates, policies, and audit reports from a single Google Admin console.</p><p><b>Smart access controls</b></p><p>Chrome Enterprise Premium ensures we only grant access when it is safe. Every time someone tries to log in, we verify three things:</p><ul><li>Identity: Is the user signed into their corporate account?</li><li>Device: Is the laptop or phone managed and secure?</li><li>Context: Where are they logging in from, and on what network?</li></ul><p><b>Stronger data protection</b></p><p>We use Chrome Enterprise’s built-in features, such as Safe Browsing sandboxing and site isolation, and auto-updates to keep end users secure while they work on the web. These benefits plus Chrome Enterprise Premium prove that security does not have to slow down business. Employees work without security interruptions, and our IT team gets a single, clear audit trail across all devices. This helps us maintain high efficiency and supports our regulatory compliance efforts.</p><p><i>Read more customer stories including how Mercari drove a 50% plus cost reduction with Chrome Enterprise Premium.</i></p></div>

### Built for trust and control: Powering the next wave of AI agents across Google Workspace and Google Cloud

- **Link**: [https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise/](https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise/)
- **Published**: 2026-11-25 02:00:00
- **Fetched**: 2026-11-25 09:21:57

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">For over 20 years, we have protected 4 billion users and 13 million organizations in Workspace, and critical enterprise and government systems on Google Cloud. From personal and financial records to board materials, regulated workloads, applications, and AI models, those safeguards protect what matters most. Blocking &gt;99.9% of spam, phishing, and malware, alongside encryption and data residency, follows one principle: your data is yours, and you should always know and decide who can access it.</span></p>
<p><span style="vertical-align: baseline;">That trust has powered one of the world’s largest developer ecosystems. Workspace APIs now handle more than 2.8 trillion calls a month, and public Google Drive API traffic alone is more than two-and-a-half times the volume of 2022. More than 18 billion reads from Drive each day come from API callers. Traditional REST APIs were built for human-paced apps where a valid OAuth token implied user intent. As AI agents shift from reading information to acting autonomously at machine speed across email, documents, datasets, and cloud infrastructure, a valid token is no longer enough. Policy checks, data boundaries, and human confirmation have to live in the request path. </span></p>
<p><span style="vertical-align: baseline;">Today, Workspace MCP servers and the Workspace CLI are generally available alongside Google Cloud Agent Gateway and unified protections across Workspace and Google Cloud. Builders get modern, agent-ready interfaces, and organizations get the visibility and control to adopt AI agents with confidence.</span></p>
<h3><strong style="vertical-align: baseline;">Purpose-built interfaces: Workspace MCP servers, Workspace CLI, and Cloud Agent Gateway</strong></h3>
<p><span style="vertical-align: baseline;">To help developers build reliable agents faster without forcing security teams to compromise, we are bringing agent-native interfaces to Workspace and Google Cloud:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://developers.google.com/workspace/guides/configure-mcp-servers#support-products" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">Workspace MCP servers</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> Now generally available, dedicated remote servers for Gmail, Google Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks. Builders get one standard interface with built-in permission and DLP checks, and native human-in-the-loop (HITL) confirmations for sensitive actions. They also reject non-agent OAuth clients and work with Model Armor, Google Cloud’s prompt-injection screening service.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://developers.google.com/workspace/guides/workspace-cli" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">Workspace CLI</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> Now generally available for local agents, terminal workflows, and automation, providing structured JSON outputs and scoped OAuth sign-in across Workspace services.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview"><strong style="text-decoration: underline; vertical-align: baseline;">Google Cloud Agent Gateway</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> A protocol-native gateway for LLM, MCP, and Agent2Agent (A2A) traffic on Google Cloud. It verifies Agent Identities against Agent Registry, enforces IAM policies and default-deny outbound rules, and screens requests with Model Armor.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Together, these interfaces give AI agents open, protocol-native paths built on standards like MCP and A2A. Permissions, confirmations, prompt screening, and audit logging happen automatically, while traditional apps continue to run on existing REST APIs.</span></p>
<h3><strong style="vertical-align: baseline;">Consistent controls across every agent workflow</strong></h3>
<p><span style="vertical-align: baseline;">Those interfaces sit on a unified security model across Workspace and Google Cloud, with core controls shipping today:</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Policy checks on every request:</strong><span style="vertical-align: baseline;"> Under our new </span><a href="https://workspace.google.com/terms/ai-tools" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace AI Tools Addendum</span></a><span style="vertical-align: baseline;">, AI agents must use Workspace MCP servers or the Workspace CLI rather than existing REST APIs. Technical enforcement begins on February 1, 2027, giving builders time to transition. Every call is checked against your organization’s Workspace permissions, DLP rules, and classification labels. On Google Cloud, Agent Gateway enforces IAM and default-deny outbound rules at the protocol layer and routes custom checks through Service Extensions to Identity-Aware Proxy, your own policy engine, or third-party security tools.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Separate agent identities and limits:</strong><span style="vertical-align: baseline;"> Admins and users need to tell an AI agent apart from a traditional app or a person, and cap what it can do. Agents connecting to Workspace must use dedicated </span><a href="https://support.google.com/cloud/answer/15549257#agentic-client" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">OAuth client IDs</span></a><span style="vertical-align: baseline;">, paired with least-privilege scopes, time-limited approvals (coming soon), and </span><a href="https://developers.google.com/workspace/guides/quota-usage-tiers" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">usage quotas</span></a><span style="vertical-align: baseline;"> (billing begins on April 1, 2027). On Google Cloud, agents receive their own Agent Identity in Agent Registry with no shared or long-lived keys, bounded by IAM policies and organization, folder, and project quotas. Those identities can also carry user-delegated authorization into Workspace when accessing mail or files.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">People stay in charge of high-impact actions:</strong><span style="vertical-align: baseline;"> Routine work like creating drafts or summarizing documents runs autonomously, while critical changes require a person to sign off. In Workspace, MCP servers and the CLI enforce explicit user confirmation before agents send email, change Drive sharing permissions, or make bulk edits. On Google Cloud, policy can require multi-factor authentication or human approval before reading sensitive Cloud Storage buckets, changing IAM permissions, or modifying production infrastructure.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Clear visibility and revocation:</strong><span style="vertical-align: baseline;"> A one-time consent screen is not enough when agents run continuously. Workspace administrators can view, audit, and revoke AI agents in the </span><a href="https://support.google.com/a/answer/7281227" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">admin console</span></a><span style="vertical-align: baseline;">, and users will soon be able to view agent activity and revoke access to their emails and files. On Google Cloud, Security Command Center, Agent Observability, Cloud Audit Logs, and Wiz surface unusual behavior. Revoking a Cloud Agent Identity or OAuth grant stops access immediately.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Boundaries for your most sensitive data:</strong><span style="vertical-align: baseline;"> Coming soon in Workspace, AI access restrictions extend Workspace DLP and client-side encryption protections to agents. This will allow admins and users to block agents from accessing messages in Gmail and specific files and folders in Drive. On Google Cloud, VPC Service Controls, Principal Access Boundaries, and Context-Aware Access keep sensitive data inside designated perimeters and verified devices.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Strict rules on your data afterward:</strong><span style="vertical-align: baseline;"> Our new </span><a href="https://workspace.google.com/terms/ai-tools" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace AI Tools Addendum</span></a><span style="vertical-align: baseline;"> sets clear boundaries for AI tools using Workspace APIs. It does not allow permanent raw storage, model training, extended retention of derived data, or API scraping. Derived and user data are removed within a defined window and when a user disconnects. On Google Cloud, Sensitive Data Protection masks sensitive fields before data leaves, and customer-managed or external encryption keys let you cut off access to Cloud agent memory stores immediately.</span></p>
</li>
</ol>
<h3><strong style="vertical-align: baseline;">Getting started</strong></h3>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Workspace developers:</strong><span style="vertical-align: baseline;"> Start building with the </span><a href="https://developers.google.com/workspace/guides/configure-mcp-servers" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace MCP and CLI configuration guide</span></a><span style="vertical-align: baseline;">, implement </span><a href="https://developers.google.com/workspace/guides/mcp-elicitation" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">user confirmations via MCP</span></a><span style="vertical-align: baseline;"> and prompt-injection protection such as Model Armor, and review the </span><a href="https://workspace.google.com/terms/ai-tools" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace AI Tools Addendum</span></a><span style="vertical-align: baseline;">.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Workspace administrators:</strong><span style="vertical-align: baseline;"> Review connected apps and agents, configure DLP policies for your users, and monitor OAuth activity logs in the </span><a href="https://support.google.com/a/answer/7281227" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">admin console</span></a><span style="vertical-align: baseline;">.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Google Cloud customers:</strong><span style="vertical-align: baseline;"> Register Agent Identities in Agent Registry, place Agent Gateway and Model Armor in front of agents and MCP servers, configure MFA or human approval for sensitive actions, and review IAM, VPC Service Controls, and quota limits.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">With Workspace MCP servers and the Workspace CLI generally available alongside Google Cloud’s agent protections, developers have an open, modern platform to build on. Organizations get the visibility and control to scale AI agents with confidence.</span></p></div>
</details>

### ヨーロッパで、ヨーロッパとともに創るソブリン AI: 新しいスタートアップ アクセラレータ

- **Link**: [https://cloud.google.com/blog/ja/topics/startups/sovereign-ai-on-your-terms-our-new-startup-accelerator-is-open/](https://cloud.google.com/blog/ja/topics/startups/sovereign-ai-on-your-terms-our-new-startup-accelerator-is-open/)
- **Published**: 2026-11-25 10:00:00
- **Fetched**: 2026-11-25 18:33:59

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 11 月 18 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/topics/startups/sovereign-ai-on-your-terms-our-new-startup-accelerator-is-open?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">このたび、</span><a href="http://startup.google.com/programs/accelerator/sovereign-ai/europe-israel/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Google for Startups Accelerator: ソブリン AI</span></a><span style="vertical-align: baseline;"> の参加者募集を開始する運びとなりました。ヨーロッパとイスラエルで展開されるこのイニシアチブは、ヨーロッパの規制環境に対応する最先端 AI ソリューションを構築中のスタートアップを支援するものです。</span></p>
<p><span style="vertical-align: baseline;">AI は、</span><a href="https://cms.implementconsultinggroup.com/media/uploads/articles/2024/The-economic-opportunity-of-generative-AI-in-the-EU/The-economic-opportunity-of-AI-in-the-EU.pdf" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">ヨーロッパに推定 1 兆 2,000 億ユーロの経済的機会</span></a><span style="vertical-align: baseline;">をもたらすと試算されています。この可能性を実現するには、ヨーロッパの企業や公共機関は高度な AI を導入するだけでなく、重要なデータ ガバナンス要件も満たす必要があります。これには、</span><a href="https://artificialintelligenceact.eu/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">EU AI 規則</span></a><span style="vertical-align: baseline;">、</span><a href="https://www.nis-2-directive.com/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">NIS2</span></a><span style="vertical-align: baseline;">、</span><a href="https://www.eiopa.europa.eu/digital-operational-resilience-act-dora_en" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">DORA</span></a><span style="vertical-align: baseline;">、さらには </span><a href="https://www.lsti-certification.fr/en/Company-offers/Cybersecurity/SecNumCloud" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">SecNumCloud</span></a><span style="vertical-align: baseline;"> や </span><a href="https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/kriterienkatalog-c5_node.html" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">BSI のクラウド セキュリティおよび主権原則</span></a><span style="vertical-align: baseline;">といった各国のフレームワークも含まれます。</span></p>
<p><span style="vertical-align: baseline;">Google が目指すのは、志のある創業者がヨーロッパで、そしてヨーロッパ主導のソリューションを使用して事業を展開することです。スタートアップにとってのデジタル主権とは、質の劣るツールで妥協することでも、単一の硬直したスタックに縛り付けられることでもありません。それは、ヨーロッパのテクノロジー エコシステムと共同開発を行うことで、創業者が初日から自分たちの主導権で事業をスケールできるようにすることを意味します。たとえば、最先端の Gemini モデル、Gemma や Mistral などのオープンウェイト モデル、さらにはヨーロッパ現地のソブリン パートナーが提供する検証可能なデータ所在地や暗号化管理を自由に組み合わせることが可能です。</span></p>
<h4><strong style="vertical-align: baseline;">仕組み</strong></h4>
<p><span style="vertical-align: baseline;">エクイティフリーのこのプログラムは、15 週間にわたるハイブリッド形式で実施され、オンラインおよび対面セッションを通じて、創業者と Google エンジニア、規制の専門家、地域のパートナーを結び付けます。選定されたスタートアップは、アーキテクチャに関する実践的なメンターシップ、Google Cloud エンジニアとの 1 対 1 の個別サポート、EU AI 規則の規制サンドボックスに備えるためのアドバイザリー サポートを受けることができます。</span></p>
<p><span style="vertical-align: baseline;">参加者は、Google Cloud の階層型ソブリン ポートフォリオ全体へのデプロイに向け、直接的な支援を受けられます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">ソブリン クラウド インフラストラクチャ</strong><span style="vertical-align: baseline;">: リージョン単位のデータ管理や外部鍵管理（データ境界）から、パートナー運営のクラウド（フランスの S3NS やドイツの Thales など）、さらには完全にエアギャップのある Google Distributed Cloud 環境まで幅広く対応。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">監査可能なプライベート AI</strong><span style="vertical-align: baseline;">: Gemma ファミリー（MedGemma を含む）などのオープン ウェイト モデルをソブリン環境でファインチューニングしてデプロイし、データと運用を検証可能な形で制御できます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">エコシステムと投資家へのアクセス</strong><span style="vertical-align: baseline;">: ヨーロッパのソブリン クラウド事業者、システム インテグレーター、機関投資家と直接連携し、エンタープライズ向けセールスサイクルを短縮します。</span></p>
</li>
</ul>
<h4><strong style="vertical-align: baseline;">対象者</strong></h4>
<p><span style="vertical-align: baseline;">ヨーロッパまたはイスラエルに本社を置き、シード後期からシリーズ A 以降のステージにある、高い成長実績を備えたスタートアップから、少人数制の手厚いコホートを選定します。機密性の高い規制対象ワークロードの処理に AI を活用している企業が対象です。</span></p>
<p><span style="vertical-align: baseline;">特に、以下の分野に注力しているスタートアップを募集しています。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">政府および公共サービス テクノロジー:</strong><span style="vertical-align: baseline;"> ソブリン ドキュメント処理、市民サービス ポータル、自治体運営、スマート ユーティリティ、市民緊急グリッドなど（防衛用途は除く）。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">ヘルスケアとライフ サイエンス:</strong><span style="vertical-align: baseline;"> 臨床試験分析、電子医療記録（EHR / EHDS）、診断コパイロット、病院運営など、GDPR と</span><a href="https://health.ec.europa.eu/ehealth-digital-health-and-care/european-health-data-space-regulation-ehds_en" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">欧州健康データ空間</span></a><span style="vertical-align: baseline;">のコンプライアンス要件を満たすもの。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">規制対象の金融サービス:</strong><span style="vertical-align: baseline;"> 信用リスク モデリング、マネー ロンダリング防止パイプライン、不正行為検出、与信審査パイプライン、請求処理など。</span></p>
</li>
<li style="vertical-align: baseline;">

### ヨーロッパにおけるソブリン AI: AI スタックを制御する新しい方法

- **Link**: [https://cloud.google.com/blog/ja/products/identity-security/sovereign-ai-on-your-terms-made-with-europe/](https://cloud.google.com/blog/ja/products/identity-security/sovereign-ai-on-your-terms-made-with-europe/)
- **Published**: 2026-11-25 10:30:00
- **Fetched**: 2026-11-25 18:33:59

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 11 月 18 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/products/identity-security/sovereign-ai-on-your-terms-made-with-europe?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">今回ブリュッセルで開催された Sovereign AI Summit では、公共部門のリーダー、政策立案者、パートナー各社が集まり、ヨーロッパによる管理のもとで AI を活用して今後 10 年間のヨーロッパの公共サービス、ヘルスケア、金融をどのように構築していくかを議論しています。Google は、ヨーロッパのパートナーとともに、その実現を支援します。</span></p>
<p><span style="vertical-align: baseline;">この目標を達成するには、データの保存場所を決めるだけでは不十分です。ヨーロッパの組織との対話では、次のような 4 つの共通する疑問をよく耳にします。</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">制御を強化すると、AI の性能や機能面で妥協することを意味するのか？</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">誰がデータにアクセスできるのか、また制御が機能していることを規制当局に証明できるのか？</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">組織が AI で生み出す価値はヨーロッパにとどまるか？</span></p>
</li>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">AI を安定して稼働させ続けるにはどうすればよいか？</span></p>
</li>
</ol>
<p><span style="vertical-align: baseline;">2025 年 5 月 Google は、ワークロードごとに必要な制御レベルに合わせて選択できるソブリン クラウド サービスの</span><a href="https://cloud.google.com/blog/ja/products/identity-security/google-advances-sovereignty-choice-and-security-in-the-cloud"><span style="text-decoration: underline; vertical-align: baseline;">ポートフォリオを発表</span></a><span style="vertical-align: baseline;">しました。さらに 2 月には、このポートフォリオを支える</span><a href="https://cloud.google.com/blog/ja/products/identity-security/delivering-a-secure-open-sovereign-digital-world?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">コミットメントを策定し</span></a><span style="vertical-align: baseline;">、地域への投資、運用の継続性、お客様によるデータの管理、オープン テクノロジーを対象としました。</span></p>
<p><span style="vertical-align: baseline;">今回、Google はこれらの取り組みをさらに強化します。パートナーが運用するクラウドである Google Cloud Dedicated に Gemini モデルが導入されます。これにより、Model Garden ですでに提供されているオープンモデルにとどまらず、モデルの選択肢が広がることになります。また、暗号鍵の管理とコンプライアンス対応に向けた新機能や、ヨーロッパのソフトウェア企業やスタートアップとの新たな取り組みについても発表しました。</span></p>
<h4><strong style="vertical-align: baseline;">Google AI をソブリン ポートフォリオ全体に導入</strong></h4>
<p><span style="vertical-align: baseline;">ソブリン（主権、管理性）のあり方は一律ではないため、</span><a href="https://cloud.google.com/sovereign-cloud"><span style="text-decoration: underline; vertical-align: baseline;">Google の Sovereign Cloud</span></a><span style="vertical-align: baseline;"> では、ワークロードを実行する 3 つの方法を提供しています。1 つ目は Google Cloud Data Boundary であり、Google のパブリック クラウドにデータ所在地、アクセス、暗号化の制御を適用します。2 つ目のオプションは Google Cloud Dedicated です。これは、独立した現地パートナーが隔離されたインフラストラクチャ上で運用します。そして 3 つ目が Google Distributed Cloud であり、接続型または完全エアギャップ型のお客様独自のデータセンターで実行されます。</span></p>
<p><span style="vertical-align: baseline;">一部の Gemini モデルはすでに Google Cloud で利用可能であり、EU 域内を含む対象リージョンにおいて顧客データの ML 処理を実行することを</span><a href="https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency"><span style="text-decoration: underline; vertical-align: baseline;">確約</span></a><span style="vertical-align: baseline;">しています。また、Google Distributed Cloud でも</span><a href="https://cloud.google.com/blog/ja/topics/hybrid-cloud/gemini-is-now-available-anywhere?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">利用できます</span></a><span style="vertical-align: baseline;">。そして、今回発表された Google Cloud Dedicated への Gemini の導入により、ローカル運用のクラウドを必要とする組織でも Gemini を利用できるようになります。</span></p>
<p><span style="vertical-align: baseline;">多くのチームは、オープンモデルや、独自にチューニングしたモデルの利用も求めています。フランスでは、S3NS が Google Cloud Dedicated を基盤とするクラウド PREMI3NS において、マネージドのモデル提供と推論を</span><a href="https://www.s3ns.io/en/news/ai-PREMI3NS-model" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">一般提供</span></a><span style="vertical-align: baseline;">として開始しました。各チームは、Mistral や Google などのプロバイダが提供するオープンモデルを Model Garden からデプロイしたり、独自のモデルを導入したりできます。S3NS が環境を運用し、デプロイされたモデルとプロンプトが S3NS の管理下にある PREMI3NS 環境内に留まるように設計されています。</span></p>
<h4><strong style="vertical-align: baseline;">お客様がアクセスと鍵を管理</strong></h4>
<p><span style="vertical-align: baseline;">多くのヨーロッパの組織にとって、データアクセス、暗号鍵へのアクセス、サービスへのアクセスが主権体制の基準となります。Google のパブリック クラウドでは、</span><a href="https://cloud.google.com/assured-workloads/access-transparency/docs/overview"><span style="text-decoration: underline; vertical-align: baseline;">アクセスの透明性</span></a><span style="vertical-align: baseline;">、</span><a href="https://cloud.google.com/assured-workloads/access-approval/docs/overview"><span style="text-decoration: underline; vertical-align: baseline;">アクセス承認</span></a><span style="vertical-align: baseline;">、</span><a href="https://cloud.google.com/assured-workloads/key-access-justifications/docs/overview"><span style="text-decoration: underline; vertical-align: baseline;">Key Access Justifications</span></a><span style="vertical-align: baseline;"> を使用して Google の担当者がいつ、なぜデータにアクセスしたかを確認し、そのアクセスを承認または拒否できます。より詳細な制御が必要な場合は、</span><a href="https://cloud.google.com/kms/docs/ekm"><span style="text-decoration: underline; vertical-align: baseline;">Google Cloud の外部</span></a><span style="vertical-align: baseline;">で暗号鍵を保持することで、理由を問わずデータへのアクセスを拒否できます。こうした制御を組み合わせることで、お客様自身があらゆるデータへのアクセスを制御できるようになります。</span></p>
<p><span style="vertical-align: baseline;">Google Cloud の外部で鍵を保持する場合、鍵のリクエストごとに外部システムへの通信が発生するため、レイテンシと可用性のリスクが増大する可能性があります。現在プレビュー版として提供されている Confidential External Key Management（cEKM）は、このトレードオフを解消するように設計されています。お客様またはお客様が選択した現地パートナーが、Google Cloud の外部でルートキーを保持し、アクセスを制御します。一方、鍵の操作は、ハードウェアで証明された </span><a href="https://cloud.google.com/confidential-computing"><span style="text-decoration: underline; vertical-align: baseline;">Confidential Computing</span></a><span style="vertical-align: baseline;"> 環境内で実行されます。この環境は、AI をはじめとするデータ集約型のワークロードで求められる低レイテンシと信頼性を両立できるように設計されています。</span></p>
<p><span style="vertical-align: baseline;">信頼できる現地パートナーに、Google インフラストラクチャの外部で鍵を保持するよう依頼することもできます。スペインの Telefónica との新たなパートナーシップ（現在はプレビュー版）により、フランス、ドイツ、イタリア、スペインにおける既存のヨーロッパのパートナーシップに加えて、お客様の選択肢が広がります。</span></p>
<h4><strong style="vertical-align: baseline;">お客様が規制当局にコンプライアンスを実証できるよう支援</strong></h4>
<p><span style="vertical-align: baseline;">主権管理と要件の監査は困難なだけでなく、多くの場合、エンジニアリング面の負担も大きくなります。監査を円滑に進めるために、Google は</span><a href="https://cloud.google.com/blog/products/identity-security/inside-the-new-data-boundary-experience"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Data Boundary</span></a><span style="vertical-align: baseline;"> フレームワークを導入しています。このフレームワークは、地域や国ごとの規制要件を、強制適用される監査可能な管理策にマッピングします。</span><a href="https://docs.cloud.google.com/assured-workloads/docs/control-packages/switzerland-data-boundary"><span style="text-decoration: underline; vertical-align: baseline;">スイス</span></a><span style="vertical-align: baseline;">向けのフレームワークは提供開始されました。EU のデジタル オペレーショナル レジリエンス法（DORA）に対応したフレームワークも金融サービス組織向けに計画されています。</span></p>
<p><a href="https://cloud.google.com/products/audit-manager/"><span style="text-decoration: underline; vertical-align: baseline;">Audit Manager</span></a><span style="vertical-align: baseline;"> を使用すると、お客様は既製のフレームワークをベースに、それを自社のポリシーに適合させ、継続的かつ機械で読み取り可能な証拠を監査者に提供できます。これは、顧客データを指定された境界内に保持するように設計されています。</span></p>
<h4><strong style="vertical-align: baseline;">ヨーロッパの通信事業者、ソフトウェア ベンダー、スタートアップとの連携</strong></h4>
<p><span style="vertical-align: baseline;">主権は、テクノロジーを運用する主体や、生み出された価値が地域に留まるかどうかにも左右されます。そのため Google は、クラウドを運用する企業、クラウド用のソフトウェアを構築する企業、そして次世代を担うスタートアップなど、あらゆる立場のヨーロッパ企業と連携しています。</span></p>
<p><span style="vertical-align: baseline;">Google Cloud Dedicated は、現地パートナーが環境を制御し、例外的な状況においてはソフトウェア アップデートをブロックできるように設計されています。また、Dedicated インスタンスと Google の接続が切断されるという万が一の事態が発生した場合でも、最大 12 か月間運用を継続できます。こうした設計上の選択は、2 月に発表した</span><a href="https://cloud.google.com/blog/ja/products/identity-security/delivering-a-secure-open-sovereign-digital-world?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">コミットメント</span></a><span style="vertical-align: baseline;">に沿ったものです。このコミットメントには、Google がいずれかの国から提供される Google Cloud の運用の提供を停止または終了するよう政府から命令を受けた場合、利用可能なあらゆる法的手段を講じて、そのような命令を制限、修正、または異議を申し立てるよう努めるという内容も含まれます。</span></p>
<p><span style="vertical-align: baseline;">フランスでは、S3NS 社の PREMI3NS が、フランスの国家サイバーセキュリティ機関である ANSSI から SecNumCloud 3.2 認証を取得しています。また、Thales 社とともに Google Cloud Dedicated をドイツに拡張し（現在はプレビュー版）、EU 全域で主権ハイパースケール機能を実現します。</span></p>
<p><span style="vertical-align: baseline;">規制対象のワークロードは、チームが利用しているセキュリティ、ID、モニタリング ツールが主権環境で利用できないために導入が滞ることが少なくありません。現在は Memority や Tsuga などのヨーロッパのプロバイダをはじめ、</span><a href="https://cloud.google.com/blog/products/identity-security/how-isvs-are-unlocking-european-workloads-on-google-cloud-dedicated"><span style="text-decoration: underline; vertical-align: baseline;">10 社以上のソフトウェア ベンダーが、Google Cloud Dedicated 上で自社製品の検証を完了</span></a><span style="vertical-align: baseline;">しています。</span></p>
<p><span style="vertical-align: baseline;">また、AI が生み出す新しい企業やスキルがヨーロッパに根付くよう支援したいと考えています。新設の </span><a href="https://startup.google.com/programs/accelerator/sovereign-ai/europe-israel/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Google for Startups Accelerator: Sovereign AI</span></a><span style="vertical-align: baseline;"> は、規制対象セクターのスタートアップに対して Google エンジニアによるサポート、メンターシップ、地域のクラウド プロバイダへのアクセスを提供する、エクイティフリーのプログラムです。</span></p>
<h4><strong style="vertical-align: baseline;">今後の展開</strong></h4>
<p><span style="vertical-align: baseline;">Google は、2025 年に設定した戦略を継続的に強化しています。その戦略とは、お客様が検証できる制御、クラウドでの運用方法や環境を運用する主体の選択、デプロイの形態にかかわらず高度な AI へのアクセスを提供することです。Google は、パートナーが運用する環境やオンプレミス環境に AI プラットフォームをさらに導入し、より多くのサービスにアクセス制御や鍵管理を拡張し、より多くの規制に対応したフレームワークを追加していきます。これは、これらのサービスを運用するヨーロッパのパートナーと協力して取り組んでいきます。</span></p>

### Built for trust and control: Powering the next wave of AI agents across Google Workspace and Google Cloud

- **Link**: [https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise/](https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise/)
- **Published**: 2026-11-25 02:00:00
- **Fetched**: 2026-11-25 09:22:02

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">For over 20 years, we have protected 4 billion users and 13 million organizations in Workspace, and critical enterprise and government systems on Google Cloud. From personal and financial records to board materials, regulated workloads, applications, and AI models, those safeguards protect what matters most. Blocking &gt;99.9% of spam, phishing, and malware, alongside encryption and data residency, follows one principle: your data is yours, and you should always know and decide who can access it.</span></p>
<p><span style="vertical-align: baseline;">That trust has powered one of the world’s largest developer ecosystems. Workspace APIs now handle more than 2.8 trillion calls a month, and public Google Drive API traffic alone is more than two-and-a-half times the volume of 2022. More than 18 billion reads from Drive each day come from API callers. Traditional REST APIs were built for human-paced apps where a valid OAuth token implied user intent. As AI agents shift from reading information to acting autonomously at machine speed across email, documents, datasets, and cloud infrastructure, a valid token is no longer enough. Policy checks, data boundaries, and human confirmation have to live in the request path. </span></p>
<p><span style="vertical-align: baseline;">Today, Workspace MCP servers and the Workspace CLI are generally available alongside Google Cloud Agent Gateway and unified protections across Workspace and Google Cloud. Builders get modern, agent-ready interfaces, and organizations get the visibility and control to adopt AI agents with confidence.</span></p>
<h3><strong style="vertical-align: baseline;">Purpose-built interfaces: Workspace MCP servers, Workspace CLI, and Cloud Agent Gateway</strong></h3>
<p><span style="vertical-align: baseline;">To help developers build reliable agents faster without forcing security teams to compromise, we are bringing agent-native interfaces to Workspace and Google Cloud:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://developers.google.com/workspace/guides/configure-mcp-servers#support-products" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">Workspace MCP servers</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> Now generally available, dedicated remote servers for Gmail, Google Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks. Builders get one standard interface with built-in permission and DLP checks, and native human-in-the-loop (HITL) confirmations for sensitive actions. They also reject non-agent OAuth clients and work with Model Armor, Google Cloud’s prompt-injection screening service.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://developers.google.com/workspace/guides/workspace-cli" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">Workspace CLI</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> Now generally available for local agents, terminal workflows, and automation, providing structured JSON outputs and scoped OAuth sign-in across Workspace services.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview"><strong style="text-decoration: underline; vertical-align: baseline;">Google Cloud Agent Gateway</strong></a><strong style="vertical-align: baseline;">:</strong><span style="vertical-align: baseline;"> A protocol-native gateway for LLM, MCP, and Agent2Agent (A2A) traffic on Google Cloud. It verifies Agent Identities against Agent Registry, enforces IAM policies and default-deny outbound rules, and screens requests with Model Armor.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Together, these interfaces give AI agents open, protocol-native paths built on standards like MCP and A2A. Permissions, confirmations, prompt screening, and audit logging happen automatically, while traditional apps continue to run on existing REST APIs.</span></p>
<h3><strong style="vertical-align: baseline;">Consistent controls across every agent workflow</strong></h3>
<p><span style="vertical-align: baseline;">Those interfaces sit on a unified security model across Workspace and Google Cloud, with core controls shipping today:</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Policy checks on every request:</strong><span style="vertical-align: baseline;"> Under our new </span><a href="https://workspace.google.com/terms/ai-tools" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace AI Tools Addendum</span></a><span style="vertical-align: baseline;">, AI agents must use Workspace MCP servers or the Workspace CLI rather than existing REST APIs. Technical enforcement begins on February 1, 2027, giving builders time to transition. Every call is checked against your organization’s Workspace permissions, DLP rules, and classification labels. On Google Cloud, Agent Gateway enforces IAM and default-deny outbound rules at the protocol layer and routes custom checks through Service Extensions to Identity-Aware Proxy, your own policy engine, or third-party security tools.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Separate agent identities and limits:</strong><span style="vertical-align: baseline;"> Admins and users need to tell an AI agent apart from a traditional app or a person, and cap what it can do. Agents connecting to Workspace must use dedicated </span><a href="https://support.google.com/cloud/answer/15549257#agentic-client" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">OAuth client IDs</span></a><span style="vertical-align: baseline;">, paired with least-privilege scopes, time-limited approvals (coming soon), and </span><a href="https://developers.google.com/workspace/guides/quota-usage-tiers" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">usage quotas</span></a><span style="vertical-align: baseline;"> (billing begins on April 1, 2027). On Google Cloud, agents receive their own Agent Identity in Agent Registry with no shared or long-lived keys, bounded by IAM policies and organization, folder, and project quotas. Those identities can also carry user-delegated authorization into Workspace when accessing mail or files.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">People stay in charge of high-impact actions:</strong><span style="vertical-align: baseline;"> Routine work like creating drafts or summarizing documents runs autonomously, while critical changes require a person to sign off. In Workspace, MCP servers and the CLI enforce explicit user confirmation before agents send email, change Drive sharing permissions, or make bulk edits. On Google Cloud, policy can require multi-factor authentication or human approval before reading sensitive Cloud Storage buckets, changing IAM permissions, or modifying production infrastructure.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Clear visibility and revocation:</strong><span style="vertical-align: baseline;"> A one-time consent screen is not enough when agents run continuously. Workspace administrators can view, audit, and revoke AI agents in the </span><a href="https://support.google.com/a/answer/7281227" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">admin console</span></a><span style="vertical-align: baseline;">, and users will soon be able to view agent activity and revoke access to their emails and files. On Google Cloud, Security Command Center, Agent Observability, Cloud Audit Logs, and Wiz surface unusual behavior. Revoking a Cloud Agent Identity or OAuth grant stops access immediately.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Boundaries for your most sensitive data:</strong><span style="vertical-align: baseline;"> Coming soon in Workspace, AI access restrictions extend Workspace DLP and client-side encryption protections to agents. This will allow admins and users to block agents from accessing messages in Gmail and specific files and folders in Drive. On Google Cloud, VPC Service Controls, Principal Access Boundaries, and Context-Aware Access keep sensitive data inside designated perimeters and verified devices.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Strict rules on your data afterward:</strong><span style="vertical-align: baseline;"> Our new </span><a href="https://workspace.google.com/terms/ai-tools" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Workspace AI Tools Addendum</span></a><span style="vertical-align: baseline;"> sets clear boundaries for AI tools using Workspace APIs. It does not allow permanent raw storage, model training, extended retention of derived data, or API scraping. Derived and user data are removed within a defined window and when a user disconnects. On Google Cloud, Sensitive Data Protection masks sensitive fields before data leaves, and customer-managed or external encryption keys let you cut off access to Cloud agent memory stores immediately.</span></p>
</li>
</ol>
