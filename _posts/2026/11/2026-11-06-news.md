### Building an agent skill optimizer with AlphaEvolve, Harbor and Gemini 4 Argon

- **Link**: [https://cloud.google.com/blog/topics/developers-practitioners/how-to-build-an-agent-skill-optimizer-with-alphaevolve-and-harbor/](https://cloud.google.com/blog/topics/developers-practitioners/how-to-build-an-agent-skill-optimizer-with-alphaevolve-and-harbor/)
- **Published**: 2026-11-06 02:00:00
- **Fetched**: 2026-11-06 04:31:04

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">Every day, more and more people are using coding agents like </span><a href="https://antigravity.google/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Google Antigravity</span></a><span style="vertical-align: baseline;"> and </span><a href="https://opencode.ai/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">OpenCode</span></a><span style="vertical-align: baseline;"> to complete software engineering tasks. But those tools need instructions to operate and their output is only as good as the inputs they get. By utilizing </span><a href="https://agentskills.io" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">agent skills</span></a><span style="vertical-align: baseline;"> that direct the agents through building, testing, and deploying code, developers have a powerful way to automate their workflows. </span></p>
<p><span style="vertical-align: baseline;">But most skills are written manually, so it’s hard to know which instructions are effective without assessing their output.</span></p>
<p><span style="vertical-align: baseline;">To measure the effectiveness of our skills, we ran OpenCode with </span><a href="https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Gemini 3.8 Flash</span></a><span style="vertical-align: baseline;"> on tasks from </span><a href="https://github.com/harbor-framework/terminal-bench-2" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Terminal-Bench 2.0</span></a><span style="vertical-align: baseline;">, a public benchmark. The results were inconclusive: with our baseline skill, the agent passed about two-thirds of its attempts, but the outcome was about the same even without the skill. We needed better results.</span></p>
<p><span style="vertical-align: baseline;">To achieve them, we turned to </span><a href="https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-is-available-for-everyone"><span style="text-decoration: underline; vertical-align: baseline;">AlphaEvolve</span></a><span style="vertical-align: baseline;">, which optimizes skills the way it optimizes code: Gemini proposes a new version, an evaluator scores it, and the search retains the higher-scoring version. And with </span><a href="https://harborframework.com" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Harbor</span></a><span style="vertical-align: baseline;">, that evaluator can be a real coding agent working on real tasks. We saw improvements of 5% with just a few iterations with alphaevolve</span></p>
<p><span style="vertical-align: baseline;">This is how you can build the same loop:</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Treat the skill as the program:</strong><span style="vertical-align: baseline;"> AlphaEvolve can rewrite your skill's text.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Let the agent judge:</strong><span style="vertical-align: baseline;"> Harbor runs the agent with the skill on real tasks.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Make the score trustworthy:</strong><span style="vertical-align: baseline;"> Compare each version to the baseline skill and run them both at the same time.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Check the winner on unseen tasks:</strong><span style="vertical-align: baseline;"> Save some tasks the search never sees for your final check.</span></p>
</li>
</ol>

<div class="block-paragraph_advanced"><h3><span style="vertical-align: baseline;">Let the agent judge</span></h3>
<p><span style="vertical-align: baseline;">Harbor runs agents on benchmark tasks, with each trial in its own container. We ran it on </span><a href="https://cloud.google.com/kubernetes-engine"><span style="text-decoration: underline; vertical-align: baseline;">Google Kubernetes Engine</span></a><span style="vertical-align: baseline;"> (GKE) with one pod per trial, and a single search ran thousands of agent trials.</span></p>
<p><span style="vertical-align: baseline;">For each candidate, the evaluator returns a score for passes and failures, as well as  short notes on tasks that failed or timed-out. AlphaEvolve then sends those notes to Gemini for the next version.</span></p>
<h3><span style="vertical-align: baseline;">Make the score trustworthy</span></h3>
<p><span style="vertical-align: baseline;">Agent scores can be noisy. In one of our early runs on the same benchmark, our model’s latency explained much of the variance in candidate scores. With each candidate running next to the baseline skill on the same tasks at the same time,  their scores are the difference.</span></p>
<h3><span style="vertical-align: baseline;">Check the winner on unseen tasks</span></h3>
<p><span style="vertical-align: baseline;">The best skills read differently than the baseline, which is a careful checklist: read first, reproduce the failure, and work in small verified steps. AlphaEvolve's version is a protocol built around the time limit:</span></p></div>

<div class="block-paragraph_advanced"><h3><span style="vertical-align: baseline;">What we learned</span></h3>
<p><span style="vertical-align: baseline;">AlphaEvolve focused on the most common failure: running out of time. About a third of the search's trials hit their time limit, as reported in the evaluator's notes, and AlphaEvolve's best skill is built around that limit.</span></p>
<p><span style="vertical-align: baseline;">We also found that running the search is harder than building the loop. After about 10 hours, the search scored no new candidate; our latency check held back every evaluation while model responses were slow, and full agent logs filled the controller's disk. It’s important to plan for slow model windows and for log storage before a long search.</span></p>
<p><span style="vertical-align: baseline;">In addition, skills paid off when they added what the agent lacks, as advised by the </span><a href="https://agentskills.io/skill-creation/best-practices" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Agent Skills best practices</span></a><span style="vertical-align: baseline;">. Our baseline skill made no measurable difference, while the skill holding the answers added 33 points on the dev tasks.</span></p>
<p><span style="vertical-align: baseline;">Our hypothesis: today's models and coding agents are already tuned for coding work, so general advice has little left to add. If so, the room is in specifics, which a search can find: AlphaEvolve's best skill is built around the agent's most common failure, running out of time.</span></p>
<h3><span style="vertical-align: baseline;">What's next</span></h3>
<p><span style="vertical-align: baseline;">We’re testing AlphaEvolve on enterprise agent harnesses — system prompt, policy instructions, and tools —  where the agent lacks business rules that a search can add. In one small study on customer service test cases for a fictional bank, AlphaEvolve found and fixed a wrong policy rule we had planted, and carried the fix over to cases it never saw.</span></p>
<p><span style="vertical-align: baseline;">Other small studies were mixed, and we’ll share our final results when we’ve completed the full study. </span></p>

### Semantic aggregation over millions of rows in BigQuery with AI.AGG

- **Link**: [https://cloud.google.com/blog/products/data-analytics/semantic-data-aggregation-with-bigquery-and-ai-agg/](https://cloud.google.com/blog/products/data-analytics/semantic-data-aggregation-with-bigquery-and-ai-agg/)
- **Published**: 2026-11-06 02:00:00
- **Fetched**: 2026-11-06 04:31:04

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p style="text-align: justify;"><span style="vertical-align: baseline;">For more than a decade, BigQuery has helped set standards for structured data aggregation, calculating financial sums, counting active users, and computing historical averages at a petabyte scale in seconds. But as modern enterprises become inundated with unstructured data — application logs, customer service transcripts, product imagery, and diagnostic reports — a critical gap has emerged.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Historically, relational SQL engines have lacked the native ability to aggregate, synthesize, and extract overarching semantic themes from millions of rows of text and multimodal data. While BigQuery recently introduced powerful row-level AI functions (like AI.GENERATE and AI.CLASSIFY), analyzing massive datasets holistically presents a unique architectural challenge: the large language model (LLM) context window.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Even with advanced foundation models like Gemini, you cannot pass millions of rows into a single prompt without triggering severe truncation or hard execution failures. Traditionally, solving this required data engineering teams to construct complex external map-reduce pipelines, manage rate-limiting backoffs, and recursively stitch chunked summaries together.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Today, we are thrilled to deep-dive into AI.AGG — currently in preview — a fully managed, multi-level semantic aggregation function natively embedded within BigQuery GoogleSQL. By conceptualizing semantic aggregation as a distributed map-reduce problem, AI.AGG enables data teams to run natural-language instructions over millions of rows of data using a single SQL query.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Here is a look under the hood at how it works, transformative enterprise use cases, and best practices for deploying it in production.</span></p></div>

<div class="block-paragraph_advanced"><h3><strong style="vertical-align: baseline;">Multi-level batching architecture</strong></h3>
<p style="text-align: justify;"><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> abstracts the immense engineering complexity of chunking and parallel execution. When you execute an </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> query, the BigQuery engine automatically orchestrates a sequence natively within the database:</span></p>
<ol>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><strong style="vertical-align: baseline;">Row-level validation: </strong><span style="vertical-align: baseline;">The engine helps verify no single row exceeds the maximum context window (dropping or returning an error on payloads &gt;10 MiB).</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><strong style="vertical-align: baseline;">Context-safe batching:</strong><span style="vertical-align: baseline;"> The engine dynamically groups input rows into smaller batches that safely fit within the token limits of your chosen Gemini endpoint.</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><strong style="vertical-align: baseline;">Parallel inference: </strong><span style="vertical-align: baseline;">Your natural-language SQL prompt is applied to each batch in parallel, generating intermediate semantic summaries via Vertex AI.</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><strong style="vertical-align: baseline;">Recursive synthesis:</strong><span style="vertical-align: baseline;"> Finally, the system batches these intermediate outputs together and passes them back to the LLM with the exact same instruction. This reduction repeats recursively until a single, final aggregated string is produced per SQL </span><code style="vertical-align: baseline;">GROUP BY</code><span style="vertical-align: baseline;"> clause.</span></p>
</li>
</ol>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Because </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> requires deep reasoning to synthesize concepts across disparate batches, it relies entirely on full-weight LLMs for every stage of its pipeline — differentiating it from row-level functions like </span><code style="vertical-align: baseline;">AI.CLASSIFY</code><span style="vertical-align: baseline;">, which can leverage distilled CPU proxy models.</span></p>
<h3><strong style="vertical-align: baseline;">Built for the multimodal enterprise</strong></h3>
<p style="text-align: justify;"><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> natively supports both text and multimodal inputs. By leveraging BigQuery Object Tables and the </span><code style="vertical-align: baseline;">OBJ.GET_ACCESS_URL</code><span style="vertical-align: baseline;"> function, analytics teams can aggregate visual insights across thousands of images stored directly in Cloud Storage with no data movement or transcoding required.</span></p>
<p style="text-align: justify;"><span style="font-style: italic; vertical-align: baseline;"> </span><span style="font-style: italic; vertical-align: baseline;">Data engineering pro-tip: The NULL exclusivity rule</span></p>
<p style="text-align: justify;"><span style="font-style: italic; vertical-align: baseline;">When evaluating multiple columns, users often pass a STRUCT into the function. However, if even a single field within that composite structure evaluates to NULL, the entire row is treated as NULL and silently discarded. Always explicitly wrap nullable fields with IFNULL() (e.g., IFNULL(description, 'No data provided')) to help verify your data safely enters the pipeline.</span></p>
<h3><strong style="vertical-align: baseline;">Transformative enterprise use cases</strong></h3>
<p style="text-align: justify;"><span style="vertical-align: baseline;">The true analytical power of </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> emerges when combined with standard SQL </span><code style="vertical-align: baseline;">GROUP BY</code><span style="vertical-align: baseline;"> operations.</span></p>
<h4><strong style="vertical-align: baseline;">1. Diagnostic analysis of high-volume system logs</strong></h4>
<p style="text-align: justify;"><span style="vertical-align: baseline;">System logs generated by globally distributed microservices often hide subtle degradations (like memory thrashing or systemic clock drift) that never throw explicit fatal errors. Using </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;">, DevOps teams can group millions of logs by system component and generate targeted, human-readable diagnostic summaries.</span></p>
<ul>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Prompting Tip: Instruct the model to explicitly describe the "normal operation" of the component before hunting for anomalies. This helps suppress the LLM's tendency to hallucinate errors on completely healthy logs.</span></p>
</li>
</ul>
<h4><strong style="vertical-align: baseline;">2. Building the "agentic data cloud"</strong></h4>
<p style="text-align: justify;"><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> isn't just an analytical reporting tool; it’s a dynamic orchestration engine. Imagine acquiring a massive repository of legacy support tickets with no clear categorization. You can deploy </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> to read the raw text, synthesize a definitive list of categories, and output them as a strict JSON array.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">By unpacking this array via </span><code style="vertical-align: baseline;">JSON_VALUE_ARRAY</code><span style="vertical-align: baseline;"> and feeding those dynamic labels directly into row-level classifiers like </span><code style="vertical-align: baseline;">AI.CLASSIFY</code><span style="vertical-align: baseline;">, you can orchestrate an end-to-end, autonomous data labeling pipeline natively in SQL — reducing the need for external Python scripts.</span></p>
<h3><strong style="vertical-align: baseline;">Prompt engineering is data engineering</strong></h3>
<p style="text-align: justify;"><span style="vertical-align: baseline;">When integrating generative models into highly deterministic SQL pipelines, standard conversational prompts will often fail. Prompting for programmatic SQL outputs is a strict engineering discipline:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Explicit output contracts: Treat the prompt as an API contract. Append commands like: "Return exactly one valid JSON array of strings. Do not include markdown code blocks or conversational text."</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Contextual delimiters: Use string concatenation with explicit labels (e.g., </span><code style="vertical-align: baseline;">'- Description: '</code><span style="vertical-align: baseline;">) to anchor the LLM and prevent it from conflating fields across dense batches.</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Failure state design: Explicitly instruct the model to return strict null values for missing information rather than guessing, preventing schema hallucinations downstream.</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Few-shot anchoring: Provide a literal example of your expected structure within the prompt to heavily ground the model's attention mechanism.</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">Governance, cost management, and guardrails</strong></h3>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Transitioning semantic workloads to production requires operational oversight. Because of the recursive batching architecture, the total tokens sent to Gemini will be greater than the token count of your source data. To mitigate costs, mandate strict </span><code style="vertical-align: baseline;">WHERE</code><span style="vertical-align: baseline;"> and </span><code style="vertical-align: baseline;">LIMIT</code><span style="vertical-align: baseline;"> pre-filtering.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Furthermore, for workflows cross-referencing massive, static datasets, BigQuery supports Gemini Context Caching, which can reduce input token costs and execution latency. Use the </span><code style="vertical-align: baseline;">AI.COUNT_TOKENS</code><span style="vertical-align: baseline;"> utility to estimate query costs prior to execution.</span></p>
<p style="text-align: justify;"><span style="vertical-align: baseline;">Administrators can operate knowing </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> works strictly within BigQuery's governance framework, supporting VPC Service Controls (VPC-SC) to prevent data exfiltration. Furthermore, if a transient error occurs during a batch process, the function degrades gracefully — skipping the rejected rows rather than crashing the entire query.</span></p>
<p><strong style="vertical-align: baseline;">Preview guardrails to keep in mind:</strong></p>
<ul>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">The final output string per SQL group is strictly capped at 10,000 tokens per group. Ask the model for concise output</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">Individual payload rows must not exceed 10 MiB.</span></p>
</li>
<li style="vertical-align: baseline;">
<p style="text-align: justify;"><span style="vertical-align: baseline;">When processing multimodal arrays, limit image assets to fewer than 10 images per row to avoid silent skipping.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">For optimal stability, we recommend processing a maximum of 20 million rows and outputting a maximum of 1,000 distinct SQL groups per query.</span></p>
<h3><strong style="vertical-align: baseline;">Putting AI.AGG into practice</strong></h3>
<p style="text-align: justify;"><span style="vertical-align: baseline;">To help you get started, here are examples of how </span><code style="vertical-align: baseline;">AI.AGG</code><span style="vertical-align: baseline;"> is used to synthesize insights alongside traditional SQL metrics.</span></p>

### 独自のビジネス条件の範囲内でイノベーションを実現: Google Cloud の利用額上限の一般提供を開始

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 10 月 31 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/topics/cost-management/google-cloud-spend-caps-now-generally-available?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">このたび、Google Cloud の予算での利用額上限の一般提供が開始されました。</span></p>
<p><span style="vertical-align: baseline;">今回のリリースにより、リソース削除というリスクを冒すことなく、ワークロードにかかる費用の急増を回避できるようになります。</span><strong style="vertical-align: baseline;">さらに重要な点は、最初のプレビュー以降にお客様から寄せられたフィードバックを直接反映した 3 つの大きなアップデートを導入することです。</strong><span style="vertical-align: baseline;">これにより、お客様の費用管理ハンドブックに、プログラマビリティ、リアルタイムの可視性、自動化されたガードレールを組み込むことができます。</span></p>
<h4><strong style="vertical-align: baseline;">新しい利用額上限がビジネスにもたらすメリット</strong></h4>
<p><span style="vertical-align: baseline;">Google は、次の 3 つの点で、利用額上限の使いやすさと機能を大幅に向上させました。</span></p>
<p><span style="vertical-align: baseline;">1. </span><strong style="vertical-align: baseline;">利用額上限 API による自動化</strong><span style="vertical-align: baseline;">: 何百ものプロジェクトのガードレールを手動で管理することは、運用上の大きな課題となっています。これに対処するため、既存の Cloud Billing の予算 API からアクセスできる利用額上限 API をリリースしました。これにより、各プロジェクト内の対象サービスに対して、追加のオーバーヘッドなしで、プログラムによって予算の制限を適用できるようになりました。デベロッパーが新しいサンドボックス プロジェクトをスピンアップするたびに、お客様は上限の引き上げ、更新、削除をその場で自動的に行い、利用額上限を即座に適用できます。</span></p>
<p><span style="vertical-align: baseline;">2. </span><strong style="vertical-align: baseline;">ライブ費用レポートによるリアルタイムの可視化: </strong><span style="vertical-align: baseline;">AI サービスの利用額上限は、推定ライブ費用に基づいて、使用から数分以内にトリガーされます。上限がトリガーされた場合、上限を超えた理由とタイミングを正確に把握する必要があります。この推定費用を、費用レポート内で直接、より迅速に確認できるようになりました。標準的な課金パイプラインによる純費用の確定を何時間も待つ必要はありません。違反措置のトリガーとなった正確な財務スナップショットを取得できるため、正確な根本原因分析の実行に必要なコンテキストをすぐに把握できます。</span></p></div>

<h4><strong style="vertical-align: baseline;">利用額上限を導入する際のベスト プラクティス</strong></h4>
<p><span style="vertical-align: baseline;">全社規模で利用額上限を導入する際は、次の運用上のヒントを念頭に置いてください。</span></p>
<ol>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">まず非本番環境を対象にする</strong><span style="vertical-align: baseline;">: まずは、デベロッパー サンドボックス、テストクラスタ、試験運用版 AI エージェントのプレイグラウンドに、厳格な低額の利用額上限を適用しましょう。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">アラートを適切に構成する</strong><span style="vertical-align: baseline;">: デフォルトのアラートは、上限の 50%、80%、100% に達した時点で、課金管理者とプロジェクト オーナーに自動的に送信されます。これらのロールに適切な担当者が設定されていることを確認してください。これにより、いざ予算が枯渇しそうになったときにチームが慌てずに済みます。必要に応じて、カスタムロールに利用額上限に関する権限を追加することもできます。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">固定費用とオンデマンド費用の違いを理解する</strong><span style="vertical-align: baseline;">: 予算のしきい値に達すると、利用額上限により、従量課金制と CUD の対象となるリクエストが停止されます。ただし、プロビジョンド スループットが停止されることはありません。予約済み容量を使用するリクエストは引き続き実行され、通常どおりトラフィックを処理します。</span></p>
</li>
</ol>

### Oracle AI Database@Google Cloud の最新イノベーションでエージェント型エンタープライズを強化

<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 10 月 28 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/products/databases/oracle-ai-databasegoogle-cloud-whats-new-at-oracle-ai-world?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">数十年にわたり、グローバル サプライ チェーンや会計台帳から請求エンジンに至るまで、企業のコア オペレーションは Oracle データベースのパフォーマンスとトランザクションの整合性に依存してきました。今回、ラスベガスで開催された</span><a href="https://www.oracle.com/ai-world/" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Oracle AI World</span></a><span style="vertical-align: baseline;"> において、Google Cloud と Oracle は、Oracle AI Database@Google Cloud、</span><a href="https://cloud.google.com/data-cloud"><span style="text-decoration: underline; vertical-align: baseline;">Google の Agentic Data Cloud</span></a><span style="vertical-align: baseline;">、Gemini Enterprise のインテグレーションを深化させることで、AI コンピューティングとインフラストラクチャ（Oracle Cloud Infrastructure を介して Google TPU を利用可能にすることを含む）、エンタープライズ データ、エージェント型 AI にわたる AI スタック全体でパートナーシップを拡大することを発表しました。</span></p>
<p><span style="vertical-align: baseline;">Oracle のミッション クリティカルな運用データとアプリケーションを Google Cloud のデータおよび AI エコシステム（BigQuery、Gemini Enterprise、Gemini モデルなど）と統合することで、企業は静的な分析を超えて、自律的なエージェント ワークフローを構築できます。このアーキテクチャは、従来のデータサイロを解消し、エージェントが実世界のアクションを推進するために必要となる基礎的なエンタープライズ データに、直接的、安全、かつリアルタイムにアクセスできるようにします。</span></p>
<h3><strong style="vertical-align: baseline;">エージェント型 AI の基盤となる構成要素</strong></h3>
<p><span style="vertical-align: baseline;">本番環境グレードのエージェント型 AI を実現するには、モデルの基本的な能力だけでは不十分です。強力なデータベース接続、統合されたデータ ガバナンス、豊富なセマンティック コンテキストが、まとまりのある基盤として連携していることが必要です。Google Cloud Next '26 で初めて発表された以下のコア機能は、Oracle AI Database@Google Cloud で会話型インテリジェンス、エンドツーエンドのガバナンス、自律型エージェント環境を構築するための構成要素として機能します。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/oracle/database/docs/use-oracledatabase-mcp"><strong style="text-decoration: underline; vertical-align: baseline;">Data API を使用したリモート MCP サーバー</strong></a><span style="vertical-align: baseline;">: IAM によって管理される ExecuteSQL Data API を活用した、Oracle ワークロード向けのリモート Model Context Protocol（MCP）サーバーが一般提供されました。これらを組み合わせることで、AI エージェント、Google Cloud サービス、エンタープライズ アプリケーションが SQL を安全に実行し、Oracle データベースと直接やり取りすることを可能にする、統合され、標準化されたインターフェースが提供されます。この機能は、Secret Manager を介してデータベース認証情報を自動的に解決し、Google Cloud IAM ポリシーを適用することで、カスタムの natural-language-to-SQL（自然言語から SQL への変換）ミドルウェア、踏み台 VM、平文パスワードを不要にします。</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/knowledge-catalog/docs/introduction"><strong style="text-decoration: underline; vertical-align: baseline;">Knowledge Catalog のインテグレーション</strong></a><span style="vertical-align: baseline;">: Google Cloud の Knowledge Catalog のインテグレーション（現在プレビュー版）により、Oracle データベースとより広範な Google Agentic Data Cloud にわたり、エンタープライズ メタデータの検出とガバナンスが統合されます。スキーマとビジネス メタデータを自動的にカタログ化することで、組織は一貫したアクセス制御を適用し、データの来歴を追跡し、エージェントが複雑な運用データに対して正確な推論を行うために必要となる豊富なセマンティック コンテキストを提供できるようになります。この機能に登録するには、</span><a href="https://docs.google.com/forms/d/e/1FAIpQLSf3gSDItjmOSsusMr-3opC8Yzfq8cc1mo8onkNTnyuDVAiIJA/viewform" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">こちらをクリック</span></a><span style="vertical-align: baseline;">してください。</span></p>
</li>
</ul>
<h3><strong style="vertical-align: baseline;">Oracle AI Database@Google Cloud 向け Gemini コネクタ</strong></h3>
<p><span style="vertical-align: baseline;">前述の基本機能をそのまま基盤として、</span><strong style="vertical-align: baseline;">Oracle AI Database@Google Cloud 向け Gemini コネクタ</strong><span style="vertical-align: baseline;">のプレビュー版もリリースします。このネイティブなインテグレーションにより、ビジネス ユーザーとデベロッパーは、Gemini アプリ内で自然言語クエリを使用して、Oracle AI Database@Google Cloud 上の Oracle データベースを直接操作できるようになります。バックグラウンドでは、Gemini が Knowledge Catalog を自動的に活用して、各ユーザーがアクセスを許可されている統制された Oracle データのみを対象に、検出、検索、回答のグラウンディングを行います。これにより、企業のセキュリティを損なうことなく、複雑な運用データベースを直感的で会話形式のエクスペリエンスに変えることができます。この機能に登録するには、</span><a href="https://docs.google.com/forms/d/e/1FAIpQLSf3gSDItjmOSsusMr-3opC8Yzfq8cc1mo8onkNTnyuDVAiIJA/viewform" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">こちらをクリック</span></a><span style="vertical-align: baseline;">してください。</span></p>
<h3><strong style="vertical-align: baseline;">Oracle in Gemini と Gemini in Oracle</strong></h3>
<p><span style="vertical-align: baseline;">Google Cloud と Oracle は、直接のデータベース クエリにとどまらず、より広範なアプリケーション レイヤにわたってエージェント ワークフローを連携させています。これにより、Oracle データを Gemini Enterprise に取り込み、Gemini モデルを Oracle アプリケーション内にネイティブに組み込んでいます。</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Oracle in Gemini Enterprise:</strong><span style="vertical-align: baseline;"> このたび提供が開始された Oracle in Gemini Enterprise では、会話型分析、クロスクラウド データベース コネクタ、ドメイン認識エージェントが導入されています（新しい Oracle AI Database Agent in Gemini Enterprise も含まれます）。135 を超える事前構築済みの運用スキルとデベロッパー スキル、そして平文の認証情報を一切使用しない標準化された MCP 接続を基盤として、企業はカスタム SQL や脆弱なミドルウェアを使用することなく、JD Edwards、E-Business Suite、NetSuite、Oracle Fusion にわたってマルチエージェント ワークフローをオーケストレートできます。</span></p>

<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Oracle アプリケーションにおける Gemini モデル</strong><span style="vertical-align: baseline;">: 同時に、Gemini のフロンティア推論が </span><a href="https://www.oracle.com/news/announcement/oracle-to-make-gemini-models-available-2026-07-30/" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Oracle Fusion AI Agent Studio</span></a><span style="vertical-align: baseline;">、</span><a href="https://www.oracle.com/news/announcement/oracle-extends-fusion-agentic-applications-with-introduction-of-fusion-claw-2026-09-29/" rel="noopener" target="_blank"><span style="vertical-align: baseline;"> </span><span style="text-decoration: underline; vertical-align: baseline;">Fusion Claw</span></a><span style="vertical-align: baseline;">、Oracle Fusion Applications、NetSuite に直接組み込まれます。これにより、Oracle データベース インテリジェンスと Gemini のエージェント機能が組み合わされ、トランザクション記録システム全体で実行が自動化されます。</span></p>

<h3><strong style="vertical-align: baseline;">レイクハウス、ストリーミング、連携による選択肢の拡充</strong></h3>
<p><span style="vertical-align: baseline;">運用する Oracle データを BigQuery や AI ワークロードに接続する際、アーキテクチャの優先事項、レイテンシのしきい値、ガバナンス要件は企業ごとに異なります。Google Cloud と Oracle は、画一的な統合パターンを規定するのではなく、お客様がワークロードとユースケースに最適なアプローチを選択または組み合わせることができるよう、データ統合の選択肢を幅広く提供しています。</span></p>
<p><strong style="vertical-align: baseline;">Google Cloud ボーダーレス Lakehouse と Oracle AI Lakehouse の双方向性</strong></p>
<p><span style="vertical-align: baseline;">最新のエンタープライズ データ アーキテクチャは、マルチクラウド化が進んでおり、オープン スタンダードをその基盤としています。Google Cloud と Oracle は、戦略的パートナーシップを基盤として、オープンな Apache Iceberg 標準を活用したクロスクラウドのデータ相互運用をサポートする重要なイノベーションを今年発表しました。それは、</span><strong style="vertical-align: baseline;">Google のボーダーレス Lakehouse と</strong><a href="https://www.oracle.com/autonomous-database/autonomous-ai-lakehouse/" rel="noopener" target="_blank"><strong style="vertical-align: baseline;"> </strong><strong style="text-decoration: underline; vertical-align: baseline;">Oracle AI Lakehouse</strong></a><span style="vertical-align: baseline;"> のインテグレーションです。</span></p>
<p><span style="vertical-align: baseline;">この取り組みにより、ボーダーレス Lakehouse は、双方のプラットフォームでサポートされているカタログとストレージを活用して、任意のパブリック クラウドやオンプレミス環境にある、Oracle AI Lakehouse によって作成された Apache Iceberg テーブルを読み取ることができるようになりました。</span></p>
<p><span style="vertical-align: baseline;">このたび、</span><strong style="vertical-align: baseline;">Google Cloud ボーダーレス Lakehouse への Oracle のアクセス（プレビュー版）</strong><span style="vertical-align: baseline;">により、このインテグレーションをさらに進化させ、完全な双方向性を実現しました。Oracle Autonomous AI Database と Google のボーダーレス Lakehouse（BigQuery と Managed Spark を活用）は、Google Cloud Storage 内の共有 Apache Iceberg テーブルに対して直接クエリを実行し、書き込み / DML オペレーションを実行できるようになりました。これにより、ETL やデータ レプリケーションの必要性はまったくなくなります。</span></p>
<p><span style="vertical-align: baseline;">DBMS_CATALOG を介して Oracle に統合された Lakehouse ランタイム REST カタログを利用することで、この双方向のインテグレーションは、オープン スタンダードのストレージ フレームワークを提供すると同時に、分析チーム（BigQuery と Gemini を使用）と運用チーム（Oracle SQL を使用）が、統合された信頼できる唯一の情報源に基づいて連携することを可能にします。この機能に登録するには、</span><a href="https://docs.google.com/forms/d/e/1FAIpQLSf3gSDItjmOSsusMr-3opC8Yzfq8cc1mo8onkNTnyuDVAiIJA/viewform" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">こちらをクリック</span></a><span style="vertical-align: baseline;">してください。</span></p>
<p><strong style="vertical-align: baseline;">OCI GoldenGate による 1 秒未満の CDC ストリーミング</strong></p>
<p><span style="vertical-align: baseline;">大規模な分析や AI のために、ミッション クリティカルな運用データを BigQuery 内に継続的に反映させたい組織にとって、リアルタイムの変更データ キャプチャ（CDC）は、即座に競争上の優位性をもたらします。</span><a href="https://docs.cloud.google.com/oracle/database/docs/deploy-and-connect"><span style="text-decoration: underline; vertical-align: baseline;">ネイティブな OCI GoldenGate のインテグレーション</span></a><span style="vertical-align: baseline;">により、テーブル ブロックへのアクセスやトランザクション ワークロードへの負荷を抑えながら、CDC イベントを Oracle REDO ログから直接抽出できます。トランザクションは、Google Cloud のプライベート ネットワークを介して BigQuery マネージド テーブルに直接、安全にストリーミングされます。これにより、1 秒未満の分析鮮度がもたらされ、Gemini、Feature Store、ライブ ビジネス インテリジェンス ダッシュボードが強化されるとともに、オンプレミス環境から Oracle AI Database@Google Cloud への移行も効率化されます。</span></p>
<p><strong style="vertical-align: baseline;">BigQuery と Oracle のクエリ連携</strong></p>
<p><span style="vertical-align: baseline;">ワークロードで、オンデマンドの運用可視性や、データを移動しない低頻度の資産間の結合が必要な場合、BigQuery と Oracle のクエリ連携（プレビュー版）により、ライブの Oracle データベースに対して直接、リアルタイムのインプレース分析が可能になります。EXTERNAL_QUERY 関数を使用すると、データチームは BigQuery クエリ、ダッシュボード、パイプラインからネイティブの Oracle SQL を直接実行して、ライブ トランザクション レコードを取得し、ペタバイト規模の BigQuery データセットと簡単に結合できます。このゼロコピー アプローチにより、アドホックなルックアップ、イントラデイ リスク報告、リアルタイムの不正検出における重複ストレージと ETL メンテナンスを排除することで、運用が簡素化され、総所有コスト（TCO）が削減されます。この機能への登録をご希望の場合は、Google Cloud のアカウント担当者にお問い合わせください。</span></p>

### Google Cloud と NASA: 深宇宙ミッション用のロボット システムをテスト

- **Link**: [https://cloud.google.com/blog/ja/topics/public-sector/google-cloud-and-nasa-testing-robotic-systems-for-deep-space-missions/](https://cloud.google.com/blog/ja/topics/public-sector/google-cloud-and-nasa-testing-robotic-systems-for-deep-space-missions/)
- **Published**: 2026-11-06 11:00:00
- **Fetched**: 2026-11-06 16:40:16

<details class="entry-summary">
<summary>詳細を表示</summary>
<div class="block-paragraph_advanced"><p><span style="vertical-align: baseline;">※この投稿は米国時間 2026 年 10 月 27 日に、Google Cloud blog に</span><a href="https://cloud.google.com/blog/topics/public-sector/google-cloud-and-nasa-testing-robotic-systems-for-deep-space-missions?e=48754805&amp;hl=en"><span style="text-decoration: underline; vertical-align: baseline;">投稿</span></a><span style="vertical-align: baseline;">されたものの抄訳です。</span></p>
<p><span style="vertical-align: baseline;">NASA は、月探査の拡大、月面基地による人類の持続的な滞在の確立、そして初の有人火星ミッションに向けた基盤構築を目指し、より高度なミッションへ宇宙飛行士を送り出す</span><a href="https://www.nasa.gov/humans-in-space/artemis/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">アルテミス計画</span></a><span style="vertical-align: baseline;">を進めています。こうしたなか、乗組員の安全確保と、地球に依存しない自律性の確立が最重要課題となっています。将来の火星への深宇宙ミッションにおいて、宇宙飛行士は深刻な運用上の課題に直面する可能性があります。たとえば通信の往復遅延は最大 44 分に及び、乗組員に対するリアルタイムの医療支援はほぼ不可能です。</span></p>
<p><span style="vertical-align: baseline;">昨年、Google Public Sector は、</span><a href="https://cloud.google.com/blog/ja/topics/public-sector/how-google-and-nasa-are-testing-ai-for-medical-care-in-space?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">Crew Medical Officer Digital Assistant（CMO-DA）</span></a><span style="vertical-align: baseline;">の開発状況を発表しました。CMO-DA は、遠隔・孤立環境にいる宇宙飛行士へリアルタイムで医療ガイダンスを提供するために設計された、自動臨床意思決定支援システム（CDSS）としてのデジタル アシスタントです。現在、Google はこのイノベーションを基盤として、深宇宙ミッションのサポートや NASA のミッションにおける宇宙飛行士の支援を目的とした、実体のあるロボット システムの概念実証モデルの開発に取り組んでいます。</span></p>
<h4><strong style="vertical-align: baseline;">乗組員の作業時間と安全性の最適化</strong></h4>
<p><span style="vertical-align: baseline;">月の南極エリアに計画されている月面基地は、人類の持続的な滞在を支えることを目的としています。宇宙における時間は極めて限られた貴重なリソースです。そのため、宇宙飛行士の身体的負担を軽減し、科学研究や発見に充てる時間を最大化することが最優先事項となっています。この課題に対処するため、NASA の</span><a href="https://www.nasa.gov/hrp/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">ヒューマン リサーチ プログラム</span></a><span style="vertical-align: baseline;">、ジョンソン宇宙センターのロボティクス チーム、ジェット推進研究所（JPL）は、Google Public Sector と協力してロボット システムの開発に取り組むことになりました。このシステムが日常的な準備や管理業務を引き受けることで、宇宙飛行士は人間ならではの強みである複雑な科学研究や発見に専念できるようになります。</span></p>
<p><span style="vertical-align: baseline;">少人数の乗組員でも最大限の成果を上げられるよう、このロボット システムは貨物や資材の管理、機器の操作などをこなす多用途な「ペイロード」ハンドラとして設計されています。工具の整理やコンパートメントの安全確保などの日常メンテナンスを行っていない時間帯は、医療支援へと柔軟に対応を変更できます。たとえば、宇宙飛行士が腎臓結石の兆候である可能性のある激しい腰痛を訴えた場合、ロボットが超音波診断装置を取ってきて準備します。これにより、人間の医療担当者はエコー画像の分析と患者の治療に集中できるようになります。</span></p>
<h4><strong style="vertical-align: baseline;">ロボット システムに向けた空間認識と視覚言語行動モデルの適応</strong></h4>
<p><span style="vertical-align: baseline;">限られた空間の宇宙船内で、人間と並んで安全に稼働することは非常に複雑な課題です。人が立ち入らない固定された環境で稼働する産業用ロボットとは異なり、超知能（SI）を活用する宇宙システムが狭い船内環境に安全に適応するには、人間の指示に従って柔軟に動くツールが不可欠です。また、カメラをはじめとする限られたセンサー情報に頼る必要があるため、JPL は、もともと軌道上の物体を追跡するために開発された衛星状況認識インテリジェンス ツールを応用しています。これにより、ロボット システムが自らの置かれた 3D 環境を認識し、安全に移動できるよう支援しています。</span></p>
<p><span style="vertical-align: baseline;">これをジョンソン宇宙センターの iMETRO 施設で安全にテストするため、Google DeepMind の </span><a href="https://mujoco.org/" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">MuJoCo シミュレータ</span></a><span style="vertical-align: baseline;">が活用されました。これは、SI が実機を稼働させる前に、高精度な仮想空間内で複雑な動作をシミュレーションできる高度な物理エンジンです。最近行われた概念実証の技術デモでは、医療用バッグの位置を特定して指定の場所へ移動させるという、複雑な「ピック＆プレース」動作の実証実験がロボット システムに課されました。空間認識能力を高める「アイツーハンド」カメラ構成を採用したことで、</span><a href="https://cloud.google.com/blog/ja/topics/startups/why-global-startups-are-gathering-at-google-cloud-next25?e=48754805&amp;hl=ja"><span style="text-decoration: underline; vertical-align: baseline;">Google Cloud インフラストラクチャ上で Physical Intelligence 社</span></a><span style="vertical-align: baseline;">が開発したオープンソースの </span><a href="https://huggingface.co/gimarchetti/clr-experiment-pi0" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Pi0 モデル</span></a><span style="vertical-align: baseline;">は、こうした初期のラボ環境において 85% のベースライン成功率を達成しました。これにより、今後の厳格なトレーニングと安全性の向上に向けた強固な基盤が確立されました。視覚言語行動（VLA）モデルは言語を物理的な動作に直接結び付けるため、宇宙飛行士は通常の英語テキストプロンプトを通じて、ロボット システムへ柔軟に指示を出すことができます。</span></p>
<h4><strong style="vertical-align: baseline;">宇宙: 究極のエッジ コンピューティング環境</strong></h4>
<p><span style="vertical-align: baseline;">こうした複雑なタスクの処理には莫大なコンピューティング能力が必要となりますが、そこに「宇宙は究極のエッジ コンピューティング環境である」という新たなハードルが立ちはだかります。宇宙船は、地球上にあるデータセンターとの継続的な接続に頼ることができません。この課題を解決するため、Google のチームは Google Cloud の </span><a href="https://docs.cloud.google.com/compute/docs/accelerator-optimized-machines#g4-series"><span style="text-decoration: underline; vertical-align: baseline;">G4 インスタンス</span></a><span style="vertical-align: baseline;">を活用してベースモデルの高速なトレーニングを行い、40 億パラメータの Pi0 モデルをわずか 2.5 時間でファインチューニングすることに成功しました。特筆すべきは、ファインチューニングされたモデルが、エネルギー効率に優れたコンパクトなエッジデバイス上でローカル動作可能であることを実証した点です。過去 2 年間にわたり、チームは約 15 種類のエッジ コンピューティング デバイスを検証し、将来の火星ミッションで求められる軽量かつ低消費電力なハードウェア上で、効率的に動作するデバイスを選定しました。</span></p>
<h4><strong style="vertical-align: baseline;">乗組員の安全確保と宇宙探査の未来を切り開く</strong></h4>
<p><span style="vertical-align: baseline;">将来的には、宇宙飛行士の直接的な監督と指揮のもと、簡単な音声指示でさまざまなタスクを実行できるロボット システムを構築することが最終目標です。たとえば、人間の医療責任者による厳格な指導のもと、基本的なバイタルサインの測定や簡単な超音波検査といった日常的な健康モニタリングを補佐するよう、ロボットに指示を出すことができます。これにより、人間の判断や意思決定を代替することなく、宇宙飛行士が自力では行うのが難しい物理的なサポートをロボットから受けることが可能になります。</span></p>
<p><span style="vertical-align: baseline;">Google Public Sector と NASA によるこの共同取り組みは、科学的発見の限界を押し広げるような、より高度なミッションへの道を切り開くことに貢献します。</span></p>
