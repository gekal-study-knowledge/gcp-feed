<td>
<p>Container breakout vulnerabilities CVE-2026-43284 and CVE-2026-43500 have been found in the Linux kernel, known as DirtyFrag. They allow an unprivileged local attacker to escalate to root on the host.</p>
<p>There are two exploit paths.</p>
<p>rxrpc exploit path (CVE-2026-43500): Container-Optimized OS is not vulnerable because the vulnerable module is not compiled in. Ubuntu nodes are vulnerable.</p>
<p>esp4 exploit path (CVE-2026-43284): Both Container-Optimized OS and Ubuntu are vulnerable, but the GKE default seccomp profile provides a mitigation that protects all Autopilot clusters and Standard clusters with <a href="https://docs.cloud.google.com/kubernetes-engine/docs/concepts/node-pools#autopilot-node-pools">Autopilot-managed node pools</a>. The esp4 exploit path requires the user to have the ability to make the unshare syscall to obtain CAP_NET_ADMIN. Containers that use the <code dir="ltr">RuntimeDefault</code> SeccompProfile can’t call unshare and are unaffected. Containers that grant CAP_NET_ADMIN explicitly are affected.</p>
<p>Containers using GKE Sandbox are not impacted.</p>
<h4 id="what-should-i-do_6" tabindex="-1">What should I do?</h4>
<p><strong>2026-06-24 Update:</strong> The following versions of GKE are updated with code to fix this vulnerability on Container-Optimized OS. Upgrade your Container-Optimized OS node pools to the following versions or later:</p>
<ul>
<li>1.30.14-gke.2558000</li>
<li>1.31.14-gke.1967000</li>
<li>1.32.13-gke.1829000</li>
<li>1.33.12-gke.1059000</li>
<li>1.34.8-gke.1218000</li>
<li>1.35.5-gke.1057000</li>
<li>1.36.0-gke.2459000</li>
</ul>
<hr />
<p>Upstream kernel patches have only recently been released. Those patches are being built into GKE releases and this bulletin will be updated when they are available. In the interim, partial mitigations are available below. We do not recommend relying on containers as a security boundary, container breakout vulnerabilities are very common. <a href="https://docs.cloud.google.com/kubernetes-engine/docs/how-to/hardening-your-cluster#gke_sandbox">Use GKE Sandbox instead</a>.</p>
<p>If possible, migrate your workloads to run as non-root. If your container needs to be root, consider setting the <code dir="ltr">pod.spec.securityContext.seccompProfile.type</code> to <code dir="ltr">RuntimeDefault</code> for all workloads in your cluster. As an added security measure we also recommend setting the <code dir="ltr">pod.spec.containers[*].securityContext.allowPrivilegeEscalation</code> to <code dir="ltr">false</code>.</p>
<div></div><pre dir="ltr"><code dir="ltr">apiVersion: v1
kind: Pod
metadata:
  name: default-pod
spec:
  securityContext:
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: mycontainer
    image: ubuntu
    securityContext:
      allowPrivilegeEscalation: false</code></pre>
